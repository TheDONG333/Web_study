# 05.3 自动文档：Swagger UI 与 ReDoc（重点）

> **学习目标**
> - 会用 `/docs` 调试接口（FastAPI 最大效率优势）
> - 知道 `/redoc` 和 `/openapi.json` 是什么
> - 会给接口写描述、给参数写说明
> - 知道文档里的参数类型、必填、默认值从哪里来

---

## 1. 白话理解：文档是"自动生成的接口说明书"

Spring 项目里想看接口文档，通常要额外集成 springdoc/Swagger。  
FastAPI **内置**了文档，启动服务就能用：

```
http://127.0.0.1:8000/docs      ← Swagger UI，可交互调试
http://127.0.0.1:8000/redoc     ← ReDoc，正式文档
http://127.0.0.1:8000/openapi.json  ← OpenAPI 规范（前两者都基于它）
```

> 文档不是手写的，是 FastAPI 根据你的**函数签名、类型注解、装饰器参数**自动生成的。

---

## 2. Swagger UI：/docs

打开 `http://127.0.0.1:8000/docs`，你会看到：

- 每个接口一行，按 HTTP 方法分组
- 点开接口 → **Try it out** → 填参数 → **Execute**
- 下方显示请求 URL、响应状态码、响应 JSON
- 还能看到自动生成的 curl 命令

### 调试流程

```
打开 /docs
  → 找到 GET /chat
  → Try it out
  → message 输入 "你好"
  → Execute
  → 查看 Response body
```

> **Agent 项目的日常**：写完接口先在 `/docs` 里调通，再去接前端或别的服务，效率非常高。

---

## 3. ReDoc：/redoc

打开 `http://127.0.0.1:8000/redoc`：

- 更正式、更适合阅读的文档样式
- 按标签分组，左侧导航
- **不能交互调试**，适合给前端/同事看

| | Swagger UI `/docs` | ReDoc `/redoc` |
|---|-------------------|----------------|
| 交互调试 | ✅ Try it out | ❌ |
| 阅读体验 | 一般 | ✅ 更正式 |
| 用途 | 开发调试 | 接口说明 |

## 4. 给接口写描述

### 4.1 应用级信息

```python
app = FastAPI(
    title="Agent API",
    description="用于学习 FastAPI 的示例接口",
    version="0.1.0"
)
```

这些会显示在 `/docs` 顶部。

### 4.2 路由级信息

```python
@app.get(
    "/chat",
    summary="模拟对话",
    description="接收用户消息，返回固定的模拟回复",
    tags=["chat"]
)
def chat(message: str):
    return {"reply": f"收到：{message}"}
```

| 参数 | 作用 |
|------|------|
| `summary` | 接口列表里的简短标题 |
| `description` | 展开后的详细说明 |
| `tags` | 分组标签（如 chat、user、tool） |

### 4.3 用文档字符串（docstring）写说明

```python
@app.get("/chat", summary="模拟对话")
def chat(message: str):
    """
    最简对话模拟接口。

    - 输入用户消息
    - 返回固定格式的模拟回复
    """
    return {"reply": f"收到：{message}"}
```

> 不写 `description` 时，FastAPI 会把 docstring 当作接口描述。**推荐用 docstring**，代码和文档放在一起。

## 5. 给参数写说明

### 5.1 查询参数：Query

```python
from fastapi import FastAPI, Query

@app.get("/chat")
def chat(
    message: str = Query(
        ...,
        description="用户输入的消息",
        min_length=1,
        max_length=200
    )
):
    return {"reply": f"收到：{message}"}
```

| 参数 | 作用 |
|------|------|
| `...` | 必填（不传返回 422） |
| `description` | 显示在文档里的参数说明 |
| `min_length` / `max_length` | 长度校验 |
| `ge` / `le` | 数值范围（大于等于/小于等于） |

文档里会显示：参数名、类型、是否必填、说明、校验规则。

### 5.2 路径参数：Path

```python
from fastapi import Path

@app.get("/users/{user_id}")
def get_user(
    user_id: int = Path(..., description="用户 ID", ge=1)
):
    return {"user_id": user_id}
```

- `ge=1`：必须 ≥ 1
- `/users/0` → 422
- 文档里会标注"必须大于等于 1"

### 5.3 可选参数的文档

```python
@app.get("/items")
def list_items(
    page: int = Query(1, description="页码，从 1 开始", ge=1),
    size: int = Query(10, description="每页条数", ge=1, le=100),
    keyword: str | None = Query(None, description="搜索关键词")
):
    return {"page": page, "size": size, "keyword": keyword}
```

文档中：

- `page`、`size` 有默认值 → 显示为可选
- `keyword` 默认 None → 可选
- `ge` / `le` → 显示范围

## 6. 文档里的 422 长什么样

参数校验失败时，`/docs` 的响应里会直接展示：

```json
{
  "detail": [
    {
      "type": "string_too_short",
      "loc": ["query", "message"],
      "msg": "String should have at least 1 character",
      "input": ""
    }
  ]
}
```

- `loc`：出错位置（query / path）
- `msg`：错误原因
- `input`：你传的值

> 调试时先看 `loc` 和 `msg`，基本能直接定位问题。

---

## 7. 文档是"代码的镜子"

| 文档里显示的 | 来自哪里 |
|-------------|---------|
| 接口路径 | `@app.get("/chat")` |
| 请求方法 | `get` |
| 参数名 | 函数参数名 |
| 参数类型 | 类型注解 `str` / `int` |
| 是否必填 | 有没有默认值 / `...` |
| 参数说明 | `Query(description=...)` |
| 接口说明 | `summary` / `description` / docstring |
| 分组 | `tags` |

> **结论**：把类型和说明写清楚，文档自动就好；不用维护两份。

---

## 8. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ `/docs` | Swagger UI，可交互调试，开发必用 |
| ✅ `/redoc` | 正式文档，适合阅读和分享 |
| ✅ `/openapi.json` | 文档的原始规范 |
| ✅ summary/tags | 接口标题和分组 |
| ✅ docstring | 接口详细说明 |
| ✅ Query/Path | 参数说明和校验规则 |
| ✅ 文档自动生成 | 来自函数签名和类型注解 |
