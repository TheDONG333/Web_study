# 06.4 response_model 与统一返回：对标 Result<T>

> **学习目标**
> - 会用 response_model 定义响应结构
> - 知道 response_model 能过滤内部字段
> - 会写统一的 `ApiResponse[T]` 泛型封装
> - 理解 Pydantic 响应模型和 Java `Result<T>` 的对应关系

---

## 1. 白话理解：response_model 是"出参模板"

请求有模板（Pydantic 模型），响应也应该有模板：

- 告诉调用方"返回结构长什么样"
- 自动过滤不该暴露的内部字段
- `/docs` 里显示准确的响应示例
- 返回值不符合结构时，直接报错（开发期就能发现）

> **Java 对照**：相当于给 Controller 方法声明返回类型 `Result<UserVO>`，但 Python 的 response_model 还会**实际执行过滤和校验**。

---

## 2. 定义响应模型

```python
from pydantic import BaseModel

class ChatResponse(BaseModel):
    reply: str
    elapsed_ms: int
```

接口：

```python
@app.post("/chat", response_model=ChatResponse)
def chat(req: ChatRequest):
    return {
        "reply": f"收到：{req.message}",
        "elapsed_ms": 35
    }
```

`/docs` 里会自动显示：

```json
{
  "reply": "string",
  "elapsed_ms": 0
}
```

---

## 3. 过滤内部字段（重点）

假设内部返回多了一个调试字段：

```python
@app.post("/chat", response_model=ChatResponse)
def chat(req: ChatRequest):
    return {
        "reply": "你好",
        "elapsed_ms": 35,
        "internal_trace": "prompt=...; model=..."   # 内部调试信息
    }
```

实际响应：

```json
{
  "reply": "你好",
  "elapsed_ms": 35
}
```

**`internal_trace` 被自动过滤掉了**——因为 `ChatResponse` 里没有定义这个字段。

> **用途**：内部日志、模型原始响应、数据库字段、密钥等，都可以放在返回值里给内部用，但不暴露给调用方。

---

## 4. 统一返回：ApiResponse[T]

### 4.1 定义泛型模型

```python
from typing import Generic, TypeVar
from pydantic import BaseModel

T = TypeVar("T")

class ApiResponse(BaseModel, Generic[T]):
    code: int = 200
    message: str = "ok"
    data: T | None = None
```

- `T` 是"占位类型"
- `ApiResponse[ChatResponse]` 表示 data 必须是 ChatResponse
- 默认 `code=200`、`message="ok"`

### 4.2 使用

```python
@app.post("/chat", response_model=ApiResponse[ChatResponse])
def chat(req: ChatRequest):
    return {
        "code": 200,
        "message": "ok",
        "data": {
            "reply": f"收到：{req.message}",
            "elapsed_ms": 35
        }
    }
```

响应：

```json
{
  "code": 200,
  "message": "ok",
  "data": {
    "reply": "收到：你好",
    "elapsed_ms": 35
  }
}
```

也可以返回模型对象：

```python
return ApiResponse(
    data=ChatResponse(reply="你好", elapsed_ms=35)
)
```

> 两者都可以，FastAPI 会用 response_model 做最终校验和序列化。

### 4.3 和 Java 对照

| Java | Python |
|------|--------|
| `class Result<T> { int code; String message; T data; }` | `class ApiResponse(BaseModel, Generic[T])` |
| `Result.ok(user)` | `ApiResponse(data=user)` |
| `Result.fail(400, "参数错误")` | `ApiResponse(code=400, message="参数错误", data=None)` |
| `Result<UserVO>` | `ApiResponse[ChatResponse]` |

> 结构完全一致，只是 Python 用泛型模型 + response_model 表达。

## 5. 响应模型也可以嵌套

```python
class TokenUsage(BaseModel):
    prompt_tokens: int
    completion_tokens: int
    total_tokens: int

class ChatResponse(BaseModel):
    reply: str
    usage: TokenUsage
    elapsed_ms: int

@app.post("/chat", response_model=ApiResponse[ChatResponse])
def chat(req: ChatRequest):
    ...
```

`/docs` 里会展开显示 `data.usage.prompt_tokens` 等字段，调用方一目了然。

---

## 6. response_model 的三种写法

### 6.1 装饰器参数（推荐，最清晰）

```python
@app.post("/chat", response_model=ApiResponse[ChatResponse])
def chat(req: ChatRequest):
    ...
```

### 6.2 函数返回类型注解

```python
@app.post("/chat")
def chat(req: ChatRequest) -> ApiResponse[ChatResponse]:
    ...
```

FastAPI 会自动把返回类型当作 response_model。

### 6.3 不声明（不推荐）

```python
@app.post("/chat")
def chat(req: ChatRequest):
    return {...}
```

- 能跑，但文档里响应结构不明确
- 内部字段不会被过滤
- 返回结构容易失控

> **规范**：正式接口都写 `response_model`，和请求模型一样重要。

---

## 7. 校验错误仍然走 422

注意：**请求模型校验失败**返回的是 FastAPI 默认的 422 结构，不是你的 `ApiResponse`：

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "message"],
      "msg": "Field required"
    }
  ]
}
```

如果你想连错误响应也统一成 `ApiResponse`，需要自定义异常处理器（后续再学）。本阶段先接受默认 422，够用。

---

## 8. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ response_model | 定义响应结构，自动校验和序列化 |
| ✅ 过滤字段 | 响应模型里没定义的字段不会返回 |
| ✅ ApiResponse[T] | 泛型统一返回，对标 Result<T> |
| ✅ 嵌套响应 | data 里可以继续嵌套模型 |
| ✅ 两种返回 | dict 或模型对象都可以 |
| ✅ 请求错误 | 仍然返回 FastAPI 默认 422 |
