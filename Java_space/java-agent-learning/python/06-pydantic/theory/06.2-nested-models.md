# 06.2 嵌套模型：对话历史与工具调用

> **学习目标**
> - 会在模型里嵌套另一个模型
> - 会定义模型列表（如多轮对话历史）
> - 会定义工具调用参数结构
> - 能看懂嵌套校验错误的位置

---

## 1. 白话理解：嵌套模型是"结构里还有结构"

Agent 的请求通常不是几个简单字段，而是这样：

```json
{
  "messages": [
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好，有什么可以帮你？"}
  ],
  "model": "gpt-4o-mini",
  "temperature": 0.7
}
```

- 外层是一个请求对象
- 里面有一个**消息列表**
- 每条消息又是一个对象

用 Pydantic 就是把"小结构"定义成模型，再嵌进"大结构"。

---

## 2. 消息模型 + 请求模型

```python
from enum import Enum
from pydantic import BaseModel, Field

class Role(str, Enum):
    SYSTEM = "system"
    USER = "user"
    ASSISTANT = "assistant"

class Message(BaseModel):
    role: Role
    content: str = Field(..., min_length=1)

class ChatRequest(BaseModel):
    messages: list[Message]
    model: str = "gpt-4o-mini"
    temperature: float = Field(0.7, ge=0.0, le=2.0)
```

使用：

```python
req = ChatRequest(messages=[
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "你好，有什么可以帮你？"}
])

print(req.messages[0].role)       # Role.USER
print(req.messages[0].content)    # 你好
print(req.model_dump())
```

> FastAPI 会自动把 JSON 里的每个对象转成 `Message`，列表转成 `list[Message]`。

---

## 3. 嵌套校验：错误定位到具体位置

```python
ChatRequest(messages=[
    {"role": "boss", "content": "你好"}
])
```

错误信息大致是：

```
messages.0.role
  Input should be 'system', 'user' or 'assistant'
```

在 FastAPI 返回的 422 里，`loc` 会是这样：

```json
["body", "messages", 0, "role"]
```

| 位置 | 含义 |
|------|------|
| `body` | 请求体 |
| `messages` | 字段名 |
| `0` | 列表第 0 个元素 |
| `role` | 该元素里的字段 |

> **调试技巧**：422 的 `loc` 是从外到内的路径，按路径一层层找就能定位。

## 4. 工具调用模型

大模型 function calling 的参数，通常长这样：

```json
{
  "name": "search",
  "arguments": {
    "query": "Python 装饰器",
    "top_k": 3
  }
}
```

对应模型：

```python
from typing import Any
from pydantic import BaseModel, Field

class ToolCall(BaseModel):
    name: str = Field(..., min_length=1, description="工具名称")
    arguments: dict[str, Any] = Field(
        default_factory=dict,
        description="工具参数，键值对形式"
    )
```

`arguments` 用 `dict[str, Any]`，因为不同工具的参数完全不同。

### 带工具列表的 Agent 请求

```python
class AgentRequest(BaseModel):
    query: str = Field(..., min_length=1, description="用户问题")
    tools: list[ToolCall] = Field(default_factory=list)
    history: list[Message] = Field(default_factory=list)
```

```python
req = AgentRequest(
    query="帮我搜一下 Python 装饰器",
    tools=[{"name": "search", "arguments": {"top_k": 3}}]
)
print(req.tools[0].name)               # search
print(req.tools[0].arguments["top_k"]) # 3
```

> 这就是后面写 Agent 接口时最常见的请求结构：**问题 + 可用工具 + 历史**。

## 5. 嵌套响应模型

响应也可以是嵌套的，比如 token 用量：

```python
class TokenUsage(BaseModel):
    prompt_tokens: int = Field(..., ge=0)
    completion_tokens: int = Field(..., ge=0)
    total_tokens: int = Field(..., ge=0)

class ChatResponse(BaseModel):
    reply: str
    usage: TokenUsage
    elapsed_ms: int = Field(..., ge=0)
```

返回：

```python
resp = ChatResponse(
    reply="你好",
    usage={"prompt_tokens": 10, "completion_tokens": 5, "total_tokens": 15},
    elapsed_ms=35
)
print(resp.usage.total_tokens)     # 15
print(resp.model_dump())
```

> 嵌套响应让前端/调用方拿到稳定结构，不用猜字段。

---

## 6. 可选嵌套模型

有些字段不是每次都有，可以设为可选：

```python
class ChatResponse(BaseModel):
    reply: str
    usage: TokenUsage | None = None
    elapsed_ms: int = 0
```

不传 usage 时就是 None：

```python
resp = ChatResponse(reply="你好")
print(resp.usage)      # None
```

> 区分"必填的嵌套对象"和"可选的嵌套对象"，文档里会自动标出来。

---

## 7. 模型转 dict / JSON

```python
req.model_dump()
# {'messages': [{'role': 'user', 'content': '你好'}], ...}

req.model_dump_json()
# '{"messages":[{"role":"user","content":"你好"}],...}'

req.messages[0].model_dump()
# {'role': 'user', 'content': '你好'}
```

> 嵌套模型会**递归转换**，不用手动处理每一层。

---

## 8. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 嵌套模型 | 一个模型里引用另一个模型 |
| ✅ 模型列表 | `list[Message]`，适合对话历史 |
| ✅ 工具参数 | `dict[str, Any]`，不同工具参数不同 |
| ✅ 嵌套校验 | 422 的 `loc` 会定位到具体元素和字段 |
| ✅ 嵌套响应 | token 用量等结构化数据 |
| ✅ 可选嵌套 | `Model \| None = None` |
| ✅ 序列化 | `model_dump()` 递归转 dict |
