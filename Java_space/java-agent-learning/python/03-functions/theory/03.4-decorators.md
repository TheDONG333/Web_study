# 03.4 装饰器：无侵入地增强函数（Agent 工程化高频）

> **学习目标**
> - 理解装饰器的本质：函数作为参数，返回新函数
> - 会写基础装饰器，并保留原函数名（functools.wraps）
> - 会写带参数的装饰器（三层结构）
> - 能给 Agent 工具加日志、计时、重试、权限校验

---

## 1. 白话理解：装饰器是"给函数套一个包装盒"

你有一个工具函数，想在不改它代码的前提下：

- 每次调用打印日志
- 统计耗时
- 失败自动重试
- 调用前检查权限

**装饰器**就是套在函数外面的包装盒：进去之前做点事，出来之后做点事，**原函数一行都不用改**。

```
调用者 → 包装盒（日志/计时/重试/权限）→ 原函数
```

> **Java 对照**：类似 Spring AOP 的思想——把日志、事务、权限这些横切逻辑抽出来，业务代码保持干净。

---

## 2. 前提：函数是"一等公民"

Python 里函数可以像普通变量一样传递：

```python
def greet(name):
    return f"你好，{name}"

f = greet               # 函数赋给变量
print(f("Tom"))         # 你好，Tom

def call_func(func, arg):   # 函数作为参数
    return func(arg)

print(call_func(greet, "Jerry"))   # 你好，Jerry
```

装饰器就是利用这一点：**接收一个函数，返回一个新函数**。

---

## 3. 基础装饰器

```python
from functools import wraps

def log_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"[LOG] 调用 {func.__name__}，参数: {args} {kwargs}")
        result = func(*args, **kwargs)
        print(f"[LOG] 返回: {result}")
        return result
    return wrapper

@log_decorator
def add(a, b):
    return a + b

print(add(1, 2))
```

输出：

```
[LOG] 调用 add，参数: (1, 2) {}
[LOG] 返回: 3
3
```

### 3.1 `@` 到底是什么

```python
@log_decorator
def add(a, b):
    ...
```

等价于：

```python
def add(a, b):
    ...

add = log_decorator(add)
```

- `log_decorator(add)` 返回 `wrapper`
- 之后调用 `add(1, 2)`，实际调用的是 `wrapper(1, 2)`
- `wrapper` 内部再调用原来的 `add`

### 3.2 为什么 wrapper 要写 `*args, **kwargs`

因为你不知道被装饰的函数有几个参数、是位置还是关键字。用 `*args, **kwargs` 原样接住、原样传回去，才能装饰**任意函数**。

### 3.3 为什么加 `@wraps(func)`

不加的话，`add.__name__` 会变成 `"wrapper"`，文档字符串也丢了。

```python
print(add.__name__)     # 加了 @wraps 才是 'add'
```

> **规范**：写装饰器**一律加 `@wraps(func)`**，否则排查问题、看日志时函数名全变成 wrapper。

## 4. 带参数的装饰器（三层结构）

### 4.1 需求

`@retry` 不够，想要 `@retry(times=3, delay=1)` 自定义重试次数和间隔。

### 4.2 写法

```python
import time
from functools import wraps

def retry(times=3, delay=1):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            last_error = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    last_error = e
                    print(f"[retry] 第 {attempt} 次失败: {e}")
                    if attempt < times:
                        time.sleep(delay)
            raise last_error
        return wrapper
    return decorator
```

使用：

```python
@retry(times=3, delay=0.5)
def call_llm(prompt):
    print("调用模型...")
    raise TimeoutError("超时")
```

### 4.3 三层分别管什么

```
retry(times=3, delay=0.5)   ← 第一层：接收装饰器参数
        │ 返回
        ▼
decorator(func)             ← 第二层：接收被装饰的函数
        │ 返回
        ▼
wrapper(*args, **kwargs)    ← 第三层：接收函数调用时的参数
```

> **记忆**：**带参数的装饰器 = 普通装饰器外面再套一层**。看到三层嵌套不要慌，从里往外读。

## 5. Agent 四大场景

### 5.1 日志：记录每次工具调用

```python
@log_decorator
def search(query, top_k=5):
    return f"搜索 {query}，返回 {top_k} 条"
```

> 模型调了哪个工具、传了什么参数、返回了什么，一目了然。

### 5.2 计时：看工具/模型调用耗时

```python
import time
from functools import wraps

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"[timer] {func.__name__} 耗时 {time.time() - start:.3f}s")
        return result
    return wrapper
```

> 排查"为什么这次响应这么慢"时非常有用。

### 5.3 重试：模型/网络失败自动重试

```python
@retry(times=3, delay=0.5)
def call_llm(prompt):
    ...
```

> 大模型 API 超时、限流很常见，重试是最基本的兜底（配合指数退避更佳，后续再学）。

### 5.4 权限：调用敏感工具前校验

```python
CURRENT_USER = {"name": "Tom", "role": "user"}

def require_role(role):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            if CURRENT_USER["role"] != role:
                raise PermissionError(f"需要 {role} 权限")
            return func(*args, **kwargs)
        return wrapper
    return decorator

@require_role("admin")
def delete_user(user_id):
    return f"删除用户 {user_id}"
```

> Agent 调用"删除数据""执行 SQL"这类工具前，必须做权限校验。

## 6. 多个装饰器叠加

```python
@timer
@log_decorator
def work():
    print("执行任务")

work()
```

- **应用顺序**：从下往上，等价于 `timer(log_decorator(work))`
- **执行顺序**：外层先进后出，`timer` 开始 → `log` 打印 → 原函数 → `log` 返回 → `timer` 结束

> 初学阶段知道"叠加有顺序"即可，实际写的时候保持装饰器职责单一。

## 7. 常见坑

| 坑 | 现象 | 解决 |
|----|------|------|
| 忘记 `return wrapper` | `TypeError: 'NoneType' object is not callable` | decorator 里返回 wrapper |
| wrapper 忘记 `return result` | 原函数有返回值，装饰后变 None | 把结果 return 出去 |
| 忘记 `@wraps(func)` | `__name__` 变成 wrapper | 加上 `@wraps(func)` |
| 带参装饰器少写一层 | `@retry` 写成 `@retry()` 或反之 | 三层结构对照检查 |
| 参数没接住 | 调用报缺少参数 | wrapper 用 `*args, **kwargs` |
| 权限装饰器顺序错 | 先执行了敏感逻辑再校验 | 校验放 wrapper 最前面 |

## 8. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 本质 | 接收函数、返回新函数 |
| ✅ `@` 语法 | `add = log_decorator(add)` |
| ✅ wrapper | 用 `*args, **kwargs` 适配任意参数 |
| ✅ `@wraps` | 保留原函数名和文档 |
| ✅ 带参装饰器 | 三层：参数 → 函数 → 调用参数 |
| ✅ Agent 用途 | 日志、计时、重试、权限 |
| ✅ 无侵入 | 原业务函数一行都不用改 |
