# 01.1 环境与工程基础：Python 安装、pip、venv、调试、导入

> **学习目标**
> - 在 Windows 上装好 Python 3.11/3.12 并验证
> - 掌握 pip 和 venv（重点：每个项目独立环境）
> - 会用编辑器打断点调试

## 1. 白话理解：为什么 Agent 开发用 Python

大模型相关的 SDK、框架（OpenAI SDK、LangChain、LangGraph、向量库客户端等）**几乎都优先支持 Python**，示例代码和社区资料也最多。Java 也能做，但 Python 在这个领域是"母语"。

这个模块不写 Agent，先把"工具台"搭好：装 Python、隔离依赖、会调试、会导入模块。

---

## 2. 安装 Python（Windows）

### 2.1 下载安装

1. 打开 [python.org/downloads](https://www.python.org/downloads/)，下载 **Python 3.12.x**（或 3.11.x）
2. 安装时**务必勾选**：

```
☑ Add python.exe to PATH
```

> 不勾这一项，命令行里会提示"找不到 python"，后面每一步都别扭。

### 2.2 验证

打开 PowerShell / Git Bash：

```bash
python --version        # Python 3.12.x
pip --version           # pip 24.x
```

Windows 上如果 `python` 不是预期版本，可以用 `py -3.12 --version` 指定版本。

---

## 3. pip：安装第三方库

### 白话理解

pip 是 Python 的"**应用商店**"：想用别人写好的库，一条命令装上。

```bash
pip install requests          # 装 HTTP 请求库
pip show requests             # 看装了什么版本
pip uninstall requests        # 卸载
```

### 国内加速（建议配置一次）

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

> 之后 `pip install` 会走清华镜像，速度快很多。

## 4. venv：每个项目一个独立环境（重点）

### 白话理解

Python 默认把包装在**全局环境**里：项目 A 和项目 B 共用一个仓库。A 要 `openai==1.0`，B 要 `openai==2.0`，就会打架。

**venv（虚拟环境）** = 给每个项目发一个**独立的工具箱**：项目里装的包只影响自己，互不干扰。

> **Java 对照**：Maven 的依赖是写在 `pom.xml` 里、按项目隔离的；Python 默认不是——所以必须手动用 venv 隔离。

### 4.1 创建

进入项目目录，执行：

```bash
python -m venv .venv
```

执行完会多一个 `.venv` 文件夹，里面就是这个项目专属的 Python 和 pip。

### 4.2 激活（每次打开终端都要做）

| 终端 | 命令 |
|------|------|
| PowerShell | `.venv\Scripts\Activate.ps1` |
| CMD | `.venv\Scripts\activate.bat` |
| Git Bash | `source .venv/Scripts/activate` |

激活成功后，命令行前面会出现 `(.venv)`：

```
(.venv) PS E:\python-demo>
```

### 4.3 在虚拟环境里装包

```bash
pip install requests
pip freeze > requirements.txt     # 把当前依赖导出成清单
```

别人拿到项目后：

```bash
python -m venv .venv
source .venv/Scripts/activate     # 激活
pip install -r requirements.txt   # 一键还原依赖
```

### 4.4 退出

```bash
deactivate
```

> **规范**：`.venv/` 不要提交到 Git（体积大且与机器相关），只提交 `requirements.txt`。

## 5. 编辑器与断点调试

### VS Code（推荐）

1. 安装 **Python 扩展**（Microsoft 官方）
2. `Ctrl+Shift+P` → **Python: Select Interpreter** → 选择 `.venv` 里的 Python
3. 打开 `.py` 文件，点行号左边打**红点断点**
4. 按 **F5** 启动调试：程序停在断点处，左侧能看到所有变量的值，可以单步执行

### PyCharm

- 新建项目时选择 **Virtualenv**，自动创建 `.venv`
- 点行号打红点，点绿色小虫子（Debug）启动
- 底部 Debug 面板看变量、调用栈

> 调试是排查 Agent 问题的核心技能：**能看变量，比 print 高效得多**。

## 6. 模块导入：三种写法

```python
# ① 导入整个模块
import math
print(math.sqrt(16))          # 4.0

# ② 从模块里导入指定内容
from datetime import datetime
print(datetime.now())

# ③ 别名导入（名字太长时常用）
import numpy as np            # 第三方库，需先 pip install numpy
from datetime import datetime as dt
print(dt.now())
```

| 写法 | 使用方式 | 适用 |
|------|---------|------|
| `import math` | `math.sqrt()` | 模块名短、想看清来源 |
| `from datetime import datetime` | 直接 `datetime.now()` | 只用一个类/函数 |
| `import numpy as np` | `np.array()` | 名字长、社区有约定俗成的别名 |

### 第三方库

```bash
pip install requests
```

```python
import requests

resp = requests.get("https://httpbin.org/get", timeout=5)
print(resp.status_code)
```

> 导入失败 `ModuleNotFoundError`，先检查：**虚拟环境激活了吗？包装了吗？**

## 7. 一个最小的项目结构

```
python-demo/
├── .venv/                 ← 虚拟环境（不提交 Git）
├── requirements.txt       ← 依赖清单
└── main.py                ← 入口脚本
```

```python
# main.py
import json

data = {"name": "tom", "age": 18}
print(json.dumps(data, ensure_ascii=False))
```

运行：

```bash
python main.py
```

## 8. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 装 Python 勾选 Add to PATH | 否则命令行找不到 python |
| ✅ pip 装第三方库 | 国内配清华镜像加速 |
| ✅ venv 隔离项目依赖 | 每个项目一个 `.venv`，互不干扰 |
| ✅ 激活后再装包 | 命令行出现 `(.venv)` 才对 |
| ✅ requirements.txt | `pip freeze` 导出，`pip install -r` 还原 |
| ✅ 断点调试 | VS Code F5，看变量比 print 高效 |
| ✅ 三种导入 | import / from...import / as 别名 |
