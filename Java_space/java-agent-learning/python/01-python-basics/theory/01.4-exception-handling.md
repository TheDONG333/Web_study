# 01.4 异常处理：Agent 工程化的底线

> **学习目标**
> - 掌握 try / except / else / finally 完整结构
> - 认识常见异常类型，知道什么场景会触发
> - 会用 raise 主动抛异常
> - 能把异常处理用到 Agent 场景：API 调用失败、工具出错、参数校验

---

## 1. 白话理解：异常是"程序遇到意外"

程序运行中会遇到各种意外：用户输入的不是数字、字典里没有这个 key、网络请求超时、文件不存在……

**不处理**：程序直接崩溃，后面的代码不执行，用户看到一堆红色报错。

**处理**：提前想好"出错了怎么办"，给用户一个友好提示，或者换一种方式继续。

> **Agent 场景**：调用大模型 API 一定会失败（超时、限流、余额不足、返回格式不对）。**不会异常处理，Agent 就是玩具**。

---

## 2. 完整结构：try / except / else / finally

```python
try:
    number = int("abc")        # 可能出错的代码
except ValueError:
    print("转换失败：不是合法数字")
else:
    print("成功，数字是", number)
finally:
    print("无论成败都会执行")
```

### 四个部分各管什么

| 部分 | 什么时候执行 | 用途 |
|------|-------------|------|
| `try` | 总是先执行 | 放可能出错的代码 |
| `except` | try 里抛异常且类型匹配时 | 捕获并处理 |
| `else` | try 里**没有**抛异常时 | 成功后的逻辑（可选） |
| `finally` | **无论如何都执行** | 收尾：关文件、关连接、记日志 |

### 执行流程（背这张表）

| 情况 | 执行顺序 |
|------|---------|
| 没有异常 | try → else → finally |
| 有异常且被捕获 | try → except → finally |
| 有异常但没捕获 | try → finally → 异常继续向上抛（程序可能崩） |

---

## 3. 常见异常类型（必记）

```python
int("abc")          # ValueError：值不合法
{"a": 1}["b"]       # KeyError：字典没有这个键
[1, 2][10]          # IndexError：列表下标越界
"a" + 1             # TypeError：类型不匹配
1 / 0               # ZeroDivisionError：除以零
open("不存在.txt")   # FileNotFoundError：文件不存在
```

| 异常 | 触发场景 | Agent 里的常见来源 |
|------|---------|-------------------|
| `ValueError` | 类型对但值不对 | JSON 解析、参数校验 |
| `KeyError` | 字典键不存在 | 模型返回缺字段 |
| `IndexError` | 列表越界 | 取对话历史第 N 条 |
| `TypeError` | 类型不匹配 | 参数传错类型 |
| `ZeroDivisionError` | 除以 0 | 计算指标 |
| `FileNotFoundError` | 文件不存在 | 读配置文件 |
| `Exception` | 所有异常的父类 | 最外层兜底 |

> **注意**：`Exception` 是大多数异常的基类，**不能**用它替代具体异常做精细处理；它适合放在最后一层兜底。

---

## 4. 捕获多个异常

### 4.1 分开处理

```python
try:
    data = {"age": "abc"}
    age = int(data["age"])
except KeyError:
    print("缺少 age 字段")
except ValueError:
    print("age 不是数字")
```

### 4.2 一次捕获多个

```python
try:
    value = int("abc")
except (ValueError, TypeError) as e:
    print("转换失败:", e)
```

### 4.3 捕获所有异常（兜底）

```python
try:
    do_something()
except Exception as e:
    print(f"发生未知错误: {e}")
```

> **顺序规则**：具体的异常写前面，`Exception` 放最后。如果把 `Exception` 放最前，后面的 `except` 永远不会执行。
>
> **不要写裸 `except:`**：它会连 `Ctrl+C`、程序退出信号都吞掉，排查问题很痛苦。用 `except Exception`。

## 5. raise：主动抛异常

有时候不是程序出错，而是**业务规则不允许**——这时主动抛：

```python
def validate_age(age):
    if age < 0:
        raise ValueError("年龄不能为负数")
    if age > 150:
        raise ValueError("年龄不合理")
    return age

try:
    validate_age(-1)
except ValueError as e:
    print("参数校验失败:", e)      # 参数校验失败: 年龄不能为负数
```

> **Agent 场景**：工具调用前校验参数，不合法就直接抛异常，让上层统一处理，而不是返回一个模棱两可的结果。

## 6. Agent 场景实战：API 调用兜底

```python
def call_llm(prompt):
    # 模拟大模型调用：真实项目里是 requests / SDK 调用
    raise TimeoutError("模型响应超时")

prompt = "你好"

try:
    answer = call_llm(prompt)
except TimeoutError:
    answer = "模型响应超时，请稍后重试"          # 降级兜底
except Exception as e:
    print(f"调用失败，原因: {e}")
    answer = "服务暂时不可用，请稍后再试"        # 最终兜底
finally:
    print("本次请求结束")                       # 记日志 / 释放资源

print("给用户的回复:", answer)
```

### 这段代码体现的三个工程习惯

| 习惯 | 说明 |
|------|------|
| 捕获具体异常 | 超时单独处理，给出更准确的提示 |
| 有兜底 | 未知异常也不能让程序崩 |
| finally 收尾 | 不管成败都记录日志、释放资源 |

### 工具执行出错也要兜住

```python
def run_tool(tool_name, **kwargs):
    try:
        # 真实场景：调用搜索、计算器、数据库等工具
        result = {"status": "ok", "data": "工具结果"}
        return result
    except Exception as e:
        return {"status": "error", "message": str(e)}
```

> **原则**：Agent 的每个外部依赖（模型、工具、网络、文件）都要有失败预案。**能降级就降级，不能降级就给友好提示，绝不让整个程序崩掉。**

---

## 7. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 完整结构 | try → except / else → finally |
| ✅ else | try 没异常时执行 |
| ✅ finally | 无论成败都执行，用于收尾 |
| ✅ 常见异常 | ValueError / KeyError / IndexError / TypeError |
| ✅ 捕获顺序 | 具体在前，Exception 兜底 |
| ✅ 不用裸 except | 用 `except Exception` |
| ✅ raise | 业务规则不满足时主动抛 |
| ✅ Agent 底线 | API、工具、参数都要有失败兜底 |
