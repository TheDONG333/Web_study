# 04.2 封装：保护 Agent 的内部状态

> **学习目标**
> - 理解封装的意义：只暴露必要接口
> - 掌握 `_` 单下划线和 `__` 双下划线的约定
> - 会用 @property 控制属性的读取和修改
> - 能给 Agent 封装对话历史、模型配置等内部状态

---

## 1. 白话理解：封装是"黑盒 + 按钮"

一个 Agent 内部有很多东西：对话历史、模型配置、API Key、内部方法……

封装就是：**把这些东西藏起来，只留几个按钮给外面用**。

```
外部调用者
   │  只允许：chat()、history
   ▼
┌─────────────────────────┐
│ Agent                    │
│  _history  （内部）      │
│  __api_key （内部）      │
│  _build_prompt（内部）   │
└─────────────────────────┘
```

好处：

- 外部不会乱改内部状态（历史被清空、模型被换成不存在的）
- 内部实现可以随便改，只要按钮不变
- 代码边界清晰，排查问题更容易

> **Agent 场景**：对话历史、模型配置、工具列表都是内部状态，**只应该通过方法修改**，不能让人随便 `agent.history = []` 清空。

---

## 2. Python 的"私有"只是约定

### 2.1 公有：随便访问

```python
class Agent:
    def __init__(self, name):
        self.name = name

agent = Agent("小助手")
print(agent.name)      # 小助手
agent.name = "新名字"   # 可以改
```

### 2.2 单下划线 `_`：约定"内部使用"

```python
class Agent:
    def __init__(self):
        self._history = []

agent = Agent()
print(agent._history)      # 能访问，但约定你不要碰
```

- `_xxx` 只是一个**约定**：告诉其他开发者"这是内部属性"
- Python **不会阻止**你访问
- 子类可以访问，适合"想给子类用"的内部成员

### 2.3 双下划线 `__`：会改名

```python
class Agent:
    def __init__(self):
        self.__api_key = "sk-123"

agent = Agent()
# print(agent.__api_key)        # ❌ AttributeError
print(agent._Agent__api_key)    # sk-123（改名后仍能访问）
```

- `__xxx` 会被 Python 改名成 `_类名__xxx`（name mangling）
- 目的是**避免子类意外覆盖**，不是安全防护
- 仍然能通过改名后的名字访问，所以**别把它当密码保险箱**

| 写法 | 含义 | 外部能否访问 | 建议 |
|------|------|-------------|------|
| `name` | 公有 | ✅ | 对外接口 |
| `_history` | 约定内部 | ⚠️ 能，但不该 | 内部状态、给子类用 |
| `__api_key` | 改名私有 | ⚠️ 改名后能 | 不想被子类碰的成员 |

## 3. @property：像属性一样用，实际走方法

### 3.1 只读属性

```python
class Agent:
    def __init__(self):
        self._history = []

    @property
    def history(self):
        return list(self._history)     # 返回副本，保护内部列表
```

使用：

```python
agent = Agent()
agent._history.append({"role": "user", "content": "你好"})

print(agent.history)        # [{'role': 'user', 'content': '你好'}]
agent.history.append("x")   # 改的是副本，内部不受影响
print(len(agent.history))   # 1
```

> **为什么要返回 `list(...)` 副本**：如果直接返回 `self._history`，外部一个 `agent.history.clear()` 就把内部状态清了。返回副本 = 只能看，不能改。

### 3.2 可读可写 + 校验

```python
class Agent:
    def __init__(self, model="gpt-4o-mini"):
        self._model = model

    @property
    def model(self):
        return self._model

    @model.setter
    def model(self, value):
        if not value:
            raise ValueError("模型名不能为空")
        self._model = value
```

使用：

```python
agent = Agent()
print(agent.model)          # gpt-4o-mini（不用写括号）
agent.model = "gpt-4o"      # 走 setter
print(agent.model)          # gpt-4o

# agent.model = ""          # ❌ ValueError: 模型名不能为空
```

> **和 Java 对比**：Java 要写 `getModel()` / `setModel()`，调用时带括号；Python 用 @property 后，**调用方像访问普通属性一样**，但内部仍然执行校验逻辑。

### 3.3 什么时候用 @property

| 场景 | 用不用 |
|------|--------|
| 需要校验（模型名不能空） | ✅ |
| 只读（history 只能看） | ✅ |
| 计算属性（消息数量） | ✅ |
| 简单的公开字段（name） | ❌ 直接 `self.name` 就行 |

> Python 不流行给每个字段都写 getter/setter。**只在需要控制时用 @property**。

## 4. 完整示例：封装后的 Agent

```python
class Agent:
    def __init__(self, name, model="gpt-4o-mini"):
        self.name = name                  # 公有
        self._model = model               # 内部
        self._history = []                # 内部
        self.__api_key = "sk-demo"        # 私有（改名）

    @property
    def history(self):                    # 只读
        return list(self._history)

    @property
    def model(self):                      # 可读
        return self._model

    @model.setter
    def model(self, value):               # 可写 + 校验
        if not value:
            raise ValueError("模型名不能为空")
        self._model = value

    def add_message(self, role, content):
        self._history.append({"role": role, "content": content})

    def chat(self, user_input):
        self.add_message("user", user_input)
        reply = f"[{self._model}] 收到：{user_input}"
        self.add_message("assistant", reply)
        return reply
```

外部只能：

```python
agent = Agent("小助手")
agent.chat("你好")
print(agent.history)      # 只读查看
agent.model = "gpt-4o"    # 走校验
```

外部不能：

```python
# agent.history = []              # 没有 setter，报错
# agent._history.clear()          # 能跑，但违反约定
# agent.__api_key                 # 改名，访问不到
```

## 5. 封装在 Agent 项目里的意义

| 内部状态 | 暴露方式 |
|---------|---------|
| 对话历史 `_history` | `@property history` 返回副本 |
| 模型配置 `_model` | getter + setter 校验 |
| API Key `__api_key` | 完全不暴露 |
| Prompt 拼接 `_build_prompt()` | 私有方法，只给 `chat()` 内部用 |
| 对外入口 | `chat()` / `__call__` |

> **原则**：**内部状态用单下划线，敏感信息用双下划线，对外只留少量方法**。这样以后重构内部实现，外部代码不用改。

---

## 6. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 封装目的 | 隐藏内部状态，只暴露必要接口 |
| ✅ `_name` | 约定内部使用，Python 不强制 |
| ✅ `__name` | 改名 `_类名__name`，不是真私有 |
| ✅ @property | 像属性一样访问，实际走方法 |
| ✅ setter | `@x.setter`，可做校验 |
| ✅ 返回副本 | 列表类属性返回 `list(...)` 防外部修改 |
| ✅ Agent 场景 | 历史、配置、Key、内部方法都要藏好 |
