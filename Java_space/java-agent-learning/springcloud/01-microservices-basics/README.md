# 模块 1：微服务基础认知（1 天）

> **学习目标**：搞懂为什么用微服务、核心要解决什么问题，不盲目堆组件。

---

## 学习顺序

| 顺序 | 文档 | 预计时间 | 核心问题 |
|------|------|---------|---------|
| 1 | [01.1 微服务 vs 单体架构](theory/01.1-microservices-vs-monolith.md) | 2 小时 | 为什么要拆？拆了有什么代价？ |
| 2 | [01.2 微服务七大核心问题](theory/01.2-seven-core-problems.md) | 2 小时 | 拆完之后要解决哪些新问题？ |
| 3 | [01.3 Spring Cloud 与 Boot 版本对应](theory/01.3-version-compatibility.md) | 1.5 小时 | 版本怎么选才不会报错？ |
| 4 | [01.4 Spring Cloud Alibaba 的定位](theory/01.4-spring-cloud-alibaba.md) | 1.5 小时 | 官方 Cloud 和 Alibaba 是什么关系？ |

> 本模块是**认知模块**，不写代码。目标是建立整体地图，后面学组件时才知道它站在哪。

---

## 一天怎么安排

```
上午：01.1 + 01.2
  - 理解单体与微服务的取舍
  - 把七大问题对应到你写过的 SSM 项目上

下午：01.3 + 01.4
  - 记住版本对应规则
  - 搞清 Spring Cloud、Spring Boot、Alibaba 三者的关系
  - 完成下面的自检题
```

---

## 自检清单（全部答上来才算过关）

- [ ] 能说出单体架构的 3 个优点和 3 个缺点
- [ ] 能说出微服务带来的 3 个新成本（不是只有好处）
- [ ] 能判断什么团队/什么阶段适合微服务，什么阶段应该先用单体
- [ ] 能背出微服务七大核心问题（不用背组件名，先背问题）
- [ ] 能解释每个问题"不解决会发生什么"
- [ ] 能说出 Spring Cloud 版本号和 Spring Boot 版本号怎么对应
- [ ] 知道为什么不能给每个 starter 手写版本号
- [ ] 能说出 Spring Cloud 和 Spring Cloud Alibaba 的关系
- [ ] 知道国内为什么常用 Spring Cloud Alibaba
- [ ] 知道哪些组件已淘汰、不要学

---

## 思考题（写在纸上或文档里）

1. 你现在写过的 SSM 用户管理系统，如果拆成"用户服务 + 订单服务 + 通知服务"，会多出哪些原来不存在的问题？
2. 一个 5 人团队、业务还在快速试错的创业项目，应该上微服务吗？为什么？
3. 七大问题里，哪几个是"必须解决才能上线"，哪几个是"规模大了才需要"？
4. 如果 Spring Cloud 2025.0.x 对应的 Boot 是 3.5.x，你硬配 Boot 4.0 会发生什么？
