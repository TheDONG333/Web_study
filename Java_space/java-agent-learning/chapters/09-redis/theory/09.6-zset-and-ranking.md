# 09.6 ZSet：排行榜、热搜、延时任务 ⭐

> **学习目标**（本章最高频、面试最爱问）
> - 掌握 zadd / zrange / zrangebyscore / zrem（+ 排行榜必需的延伸命令）
> - 独立理解"排行榜"从添加分数到查排名的完整闭环
> - 知道延时任务的基本思路（后续项目会用到）

## 1. 白话理解：ZSet 是"带成绩单的 Set"

Set 去重但无序，想排序得自己写逻辑。ZSet（Sorted Set）在 Set 的基础上给每个成员**配了一个分数（score）**，Redis **自动按分数排序**：

```
rank:sale:2026-09-24        （一张自动排好的榜）
├── 机械键盘   : 980      ← 分数最高，排第一
├── 显示器     : 750
└── 鼠标       : 320
```

- 成员**不重复**（和 Set 一样），但**必须带分数**，且按分数**从小到大自动排**
- 分数相同？Redis 再按成员名字典序排（了解即可）

> **一句话**：要"排序 + 排名"，就用 ZSet——**这就是排行榜的原生数据结构**，别的类型做排行榜都得自己写排序代码。

## 2. 核心命令（redis-cli）

```bash
# ① 添加成员 + 分数（成员已存在则更新分数）
zadd rank:sale 980 "机械键盘"
zadd rank:sale 750 "显示器" 320 "鼠标"      # 可一次加多个

# ② 按排名范围查（默认从小到大；加 rev 反转 = 从高到低）
zrange rank:sale 0 -1                       # 低 → 高
zrevrange rank:sale 0 2                     # 高 → 低 取前 3 名（排行榜用这个！）

# ③ 按分数范围查（如"800 分以上的商品"）
zrangebyscore rank:sale 800 1000            # 分数在 800~1000 的成员
zrangebyscore rank:sale 500 +inf            # +inf = 正无穷（500 分以上所有）

# ④ 查某个成员的分数 / 排名 / 删成员
zscore rank:sale "机械键盘"                  # "980"
zrevrank rank:sale "显示器"                  # 1（从高到低排第 2 名 → 下标从 0 开始）
zrem rank:sale "鼠标"                        # 删除成员

# ⑤ 给成员加/减分（销量榜每次下单 +1）
zincrby rank:sale 1 "机械键盘"               # 980 → 981
```

| 命令 | 白话 | 排行榜里的角色 |
|------|------|---------------|
| zadd | 添加/更新分数 | 商品上架、初始化分数 |
| zrevrange | 取前 N 名（高到低） | **查榜单** |
| zrangebyscore | 按分数区间查 | 分数门槛筛选 |
| zscore / zrevrank | 查分数 / 查排名 | **查"我排第几"** |
| zincrby | 分数加减 | **下单/点赞加分** |
| zrem | 删成员 | 商品下架 |

## 3. 三个高频场景

### 场景一：商品销量排行榜（本阶段实操案例）

**白话闭环**：商品每卖出一件 → `zincrby` 加 1 分 → 榜单自动重排；用户看榜 → `zrevrange` 取前 10；商品详情页问"排第几" → `zrevrank` + 1。

```bash
zadd rank:sale 0 "键盘" "鼠标" "显示器"      # 初始分数 0
zincrby rank:sale 1 "键盘"                   # 键盘卖出一件
zincrby rank:sale 3 "鼠标"                   # 鼠标卖出三件
zrevrange rank:sale 0 9 WITHSCORES           # 销量 Top10（带分数）
zrevrank rank:sale "键盘"                     # 查键盘排第几（0 开头）
```

> 对比 MySQL 方案：`SELECT * FROM product ORDER BY sale DESC LIMIT 10`——每次全表排序，销量一高就扛不住；ZSet 是**随时维护好的有序结构**，查询零排序开销。

### 场景二：热搜榜

**白话**：一模一样，只是"分数"换成了"搜索次数"。热搜还常按时间窗口做榜（今日榜 / 周榜）——**key 里带日期**即可：

```bash
zincrby hot:search:2026-09-24 1 "AI Agent"   # 有人搜了一次
zrevrange hot:search:2026-09-24 0 9          # 今日热搜 Top10
expire hot:search:2026-09-24 86400           # 一天后自动消失（窗口过期）
```

### 场景三：延时任务基础（知道原理即可）

**白话思路**：把"任务"当成员，把**要执行的时间戳**当分数：

```bash
# 10 分钟后要关闭这个订单（score = 执行时间的时间戳）
zadd delay:close _1700000000 "order:1001"

# 轮询者：把"时间已到"（分数 ≤ 当前时间戳）的任务拉出来执行
zrangebyscore delay:close 0 _当前时间戳
```

> 排序结构天然就是"按时间先后排队"——这就是延时队列/延时任务的原理。生产中这块还有更完整的方案，你只要知道 **ZSet 能当定时器用** 即可。

## 4. Java 里怎么写（opsForZSet）

```java
@Autowired
private StringRedisTemplate redis;

String key = "rank:sale";

// 添加/加分
redis.opsForZSet().add(key, "键盘", 0);
redis.opsForZSet().incrementScore(key, "键盘", 1);        // = zincrby

// 取前 N 名（高到低）—— 排行榜核心
Set<String> top10 = redis.opsForZSet().reverseRange(key, 0, 9);

// 取前 N 名带分数（TypedTuple 里有 value 和 score）
Set<ZSetOperations.TypedTuple<String>> top =
        redis.opsForZSet().reverseRangeWithScores(key, 0, 9);

// 查分数 / 排名（reverseRank 从 0 开始，展示要 +1）
Double score  = redis.opsForZSet().score(key, "键盘");
Long   rank   = redis.opsForZSet().reverseRank(key, "键盘");

// 按分数区间查
Set<String> range = redis.opsForZSet().rangeByScore(key, 800, 1000);

// 删除成员
redis.opsForZSet().remove(key, "鼠标");
```

| 命令 | Java API |
|------|---------|
| `zadd k score v` | `opsForZSet().add(k, v, score)` |
| `zincrby k n v` | `opsForZSet().incrementScore(k, v, n)` |
| `zrevrange k 0 9` | `opsForZSet().reverseRange(k, 0, 9)` |
| `zrevrange ... WITHSCORES` | `opsForZSet().reverseRangeWithScores(k, 0, 9)` |
| `zrevrank k v` | `opsForZSet().reverseRank(k, v)` |
| `zrangebyscore k a b` | `opsForZSet().rangeByScore(k, a, b)` |

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ ZSet = 带分数的 Set | 成员不重复 + 自动按分数排序 |
| ✅ 排行榜三件套 | zadd 初始化、zincrby 加分、zrevrange 取前 N |
| ✅ 查"我排第几" | zrevrank（0 开头，展示记得 +1） |
| ✅ 分数可复用 | 销量、搜索次数、时间戳——分数是什么由业务定 |
| ✅ 延时任务原理 | 分数 = 执行时间戳，zrangebyscore 拉到期任务 |
| ✅ 为什么不用 MySQL 排序 | ZSet 结构天然有序，查询零排序开销 |
