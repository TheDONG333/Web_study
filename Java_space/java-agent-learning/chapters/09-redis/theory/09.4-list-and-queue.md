# 09.4 List：简单消息队列与最新消息列表

> **学习目标**
> - 掌握 lpush / rpush / lpop / rpop / lrange
> - 理解"两头都能进出"的结构怎么变出两个高频场景
> - 会在 Java 里用 opsForList 完成同样操作

---

## 1. 白话理解：List 是一根两头开口的管道

把它想成一根**可以两头塞、两头取的管道**（类似 Java 的 `LinkedList`）：元素**有顺序、可重复**。

```
lpush（左边塞）→  [ c  b  a ]  ← rpush（右边塞）
lpop（左边取）  ←             →  rpop（右边取）
```

- `l` 开头 = 从**左**边操作，`r` 开头 = 从**右**边操作
- 元素顺序就是"塞进去的时间顺序"——这是它和 Set 的根本区别

---

## 2. 核心命令（redis-cli）

```bash
# ① 从左塞 / 从右塞（可一次塞多个）
lpush news:latest "新闻A"        # 列表: [新闻A]
rpush news:latest "新闻B"        # 列表: [新闻A, 新闻B]

# ② 从左取 / 从右取（取出来就没了！）
lpop news:latest                 # "新闻A"，列表剩 [新闻B]
rpop news:latest                 # "新闻B"，列表空

# ③ 查看范围（只读不删；0 -1 表示从头到尾）
lpush queue:mail m1 m2 m3        # 列表: [m3, m2, m1]（注意每次插左边，顺序反了）
lrange queue:mail 0 -1           # 1) "m3"  2) "m2"  3) "m1"
lrange queue:mail 0 0            # 只看第一条
```

| 命令 | 白话 | 关键点 |
|------|------|--------|
| lpush / rpush | 左塞 / 右塞 | 方向不同，顺序相反 |
| lpop / rpop | 左取 / 右取 | **取了就没了**（这是"消费"） |
| lrange start stop | 看一个范围 | 只读，不删数据 |

---

## 3. 两个高频场景

### 场景一：最新消息列表（朋友圈 / 消息流）

**白话**：新消息永远想排在**最前面**，用户通常只看最近 10 条。

```bash
lpush msg:list:1001 "消息C"     # 新消息从左塞 → 永远在最前
lpush msg:list:1001 "消息B"
lpush msg:list:1001 "消息A"     # 列表: [消息A, 消息B, 消息C]

lrange msg:list:1001 0 9        # 取最近 10 条展示
```

> ⚠️ **列表要控长度**：没人看第 1000 条，长时间攒着白占内存。生产用 `ltrim key 0 99` 只保留最近 100 条（本阶段知道有这个命令即可）。

### 场景二：简单消息队列（生产者-消费者）

**白话**：生产者把任务塞进管道，消费者从另一头取走干活——**天然的"排队-领取"结构**。

```bash
# 生产者（发邮件后台服务）：右塞
rpush queue:mail "user1@demo.com"
rpush queue:mail "user2@demo.com"

# 消费者（发信工人）：左取，取到就处理
lpop queue:mail                 # "user1@demo.com" → 发邮件
```

```
生产者 ──rpush──▶ [ 队 列 ] ──lpop──▶ 消费者
                       │
                 谁取到归谁，不会重复
```

> **边界要清楚**：
> - **轻量任务**（发验证码短信、异步日志）：Redis List 足够，一条命令的事
> - **正式消息队列**（订单、支付等不能丢的）：要用 RabbitMQ / Kafka——它们有确认机制、重试、持久化保证
>
> 记住判断标准：**任务丢了要不要命？** 要命就别用 List。

## 4. Java 里怎么写（opsForList）

```java
@Autowired
private StringRedisTemplate redis;

String key = "queue:mail";

// 左塞 / 右塞
redis.opsForList().leftPush(key, "消息A");
redis.opsForList().rightPush(key, "消息B");

// 左取 / 右取（取不到返回 null）
String task = redis.opsForList().leftPop(key);

// 查看范围（0 到 -1 = 全部；只读）
List<String> all = redis.opsForList().range(key, 0, -1);

// 取长度
Long size = redis.opsForList().size(key);
```

| 命令 | Java API |
|------|---------|
| `lpush k v` | `opsForList().leftPush(k, v)` |
| `rpush k v` | `opsForList().rightPush(k, v)` |
| `lpop k` | `opsForList().leftPop(k)` |
| `rpop k` | `opsForList().rightPop(k)` |
| `lrange k 0 -1` | `opsForList().range(k, 0, -1)` |

---

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ List = 有顺序 + 可重复 | 两头都能进出，像一根管道 |
| ✅ l/r 分方向 | lpush 塞左、rpush 塞右，顺序相反 |
| ✅ 最新列表 | lpush + lrange 0 9，新消息永远在最前 |
| ✅ 简单队列 | 一边 rpush 生产、一边 lpop 消费 |
| ✅ 选型边界 | 丢不起的任务（订单/支付）用 RabbitMQ/Kafka |
