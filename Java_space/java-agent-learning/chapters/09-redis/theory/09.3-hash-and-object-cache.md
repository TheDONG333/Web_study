# 09.3 Hash：存对象，改字段不用整体覆盖

> **学习目标**
> - 掌握 hset / hget / hmget / hgetall / hdel
> - 理解 Hash 存对象和 String 存 JSON 的区别、各自适合什么
> - 会在 Java 里用 opsForHash 完成同样操作

---

## 1. 白话理解：Hash 是一张挂起来的"小表"

String 是"一个 key 一个值"，如果要用 String 存一个用户对象，只能把整个对象转成 JSON 字符串：

```
user:info:1001 → "{\"name\":\"tom\",\"age\":25,\"balance\":100}"
```

想改年龄？**只能取出整串 JSON、改了、再整体写回去**。并发时两个请求同时改不同字段，还会互相覆盖。

Hash 换了个思路：**一个 key 下面挂一张 field → value 的小表**，像 Java 里的 `Map<String, String>`：

```
user:info:1001  （一张小表）
├── name    : tom
├── age     : 25
└── balance : 100
```

改年龄就是改一个 field——**不动别人**。这就是"部分字段更新"。

| 对比 | String + JSON | Hash |
|------|--------------|------|
| 存对象 | 整个 JSON 字符串 | 每个字段一个 field |
| 改一个字段 | 取→改→整体写回 | 只改那个 field |
| 并发改不同字段 | 会互相覆盖 | 互不影响 |
| 取整个对象 | `get` 一步到位 | `hgetall` 一步到位 |
| 适合 | 简单缓存、整存整取 | **对象字段经常单独更新** |

> **选择口诀**：整存整取用 String 存 JSON；**字段要单独改（余额、状态、库存）用 Hash**。

---

## 2. 核心命令（redis-cli）

```bash
# ① 存一个字段 / 取一个字段
hset user:info:1001 name tom
hset user:info:1001 age 25
hget user:info:1001 name                  # "tom"

# ② 批量取多个字段（一次拿回需要的几列，比 hget 多次快）
hmget user:info:1001 name age             # 1) "tom"  2) "25"

# ③ 取整张表（所有字段）
hgetall user:info:1001
# 1) "name"  2) "tom"  3) "age"  4) "25"   ← 交替返回 field / value

# ④ 删字段（删的是字段，不是整个 key）
hdel user:info:1001 age                   # (integer) 1
```

| 命令 | 一句话 |
|------|--------|
| hset / hget | 存 / 取一个字段 |
| hmget | 一次取多个字段 |
| hgetall | 取整个对象的所有字段 |
| hdel | 删除一个字段（key 还在） |

## 3. 高频场景：存用户 / 商品对象

### 白话 + 例子

**场景一：用户信息缓存**——用户名、头像这类字段很少变，但"余额""积分"经常变。用 Hash 只更新变的那个：

```bash
hset user:info:1001 name tom age 25 balance 100
hset user:info:1001 balance 80         # 扣了 20 块，只动 balance 一个字段
hget user:info:1001 balance            # "80"
```

**场景二：商品库存**——秒杀时库存被高频扣减，用 Hash 每个商品一张小表：

```bash
hset product:stock:2001 name "机械键盘" stock 100
hset product:stock:2001 stock 99       # 卖掉一个，只改 stock
```

> ⚠️ 注意：**库存扣减这种"读-改-写"逻辑，光靠 hset 是不安全的**（两个请求同时读到 99 都写回 98）。生产要用 Redis 的原子命令（如 `hincrby`，本阶段不展开）或 Lua 脚本——有并发的地方就要想起第二章的教训。

### 和 MySQL 的分工

| 操作 | 放哪 |
|------|------|
| 商品详情页展示（读多写少、要快） | Redis Hash 缓存一份 |
| 订单、支付记录（必须准、不能丢） | MySQL |
| 库存实时扣减 | Redis（原子操作）+ 异步落库 |

## 4. Java 里怎么写（opsForHash）

```java
@Autowired
private StringRedisTemplate redis;

String key = "user:info:1001";

// 存单字段
redis.opsForHash().put(key, "name", "tom");
redis.opsForHash().put(key, "balance", "100");

// 取单字段
String name = (String) redis.opsForHash().get(key, "name");

// 批量取
List<Object> list = redis.opsForHash().multiGet(key, List.of("name", "balance"));

// 取整个对象（返回 Map<field, value>）
Map<Object, Object> user = redis.opsForHash().entries(key);

// 删字段
redis.opsForHash().delete(key, "balance");
```

| 命令 | Java API |
|------|---------|
| `hset k f v` | `opsForHash().put(k, f, v)` |
| `hget k f` | `opsForHash().get(k, f)` |
| `hmget k f1 f2` | `opsForHash().multiGet(k, List.of(f1, f2))` |
| `hgetall k` | `opsForHash().entries(k)` |
| `hdel k f` | `opsForHash().delete(k, f)` |

---

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ Hash = key 下挂一张小表 | 一个 field 一个值，改字段不动别人 |
| ✅ 和 String+JSON 的分界 | 整存整取用 String；字段单独改用 Hash |
| ✅ 典型场景 | 用户信息、商品信息、库存 |
| ✅ hgetall 取整个对象 | 返回 field/value 交替列表 |
| ✅ 读-改-写要注意并发 | 高并发扣减用原子命令，别用 hset 覆盖 |
