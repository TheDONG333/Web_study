# 09.2 String：验证码 / 限流 / 计数器 / 分布式 ID

> **学习目标**
> - 掌握 set / get / mset / mget / incr / decr / setex / setnx
> - 理解 String 的四个高频业务场景怎么落地
> - 会在 Java 里用 opsForValue 完成同样操作

---

## 1. 白话理解：String 是什么

Redis 的 String 是**最基础的类型**：一个 key 对应一个值。值的表面是字符串，但 Redis 会把它**当数字用**——这就是 `incr`（自增）能干活的原因。

```
key: article:view:100     value: "1024"     ← 它知道这是数字，能 incr
key: sms:code:138xxxx     value: "8848"     ← 它只当字符串，只能覆盖
```

> **记忆**：String 不只是"存字符串"，它是 **计数器 + 验证码 + 缓存值** 的通用载体。

---

## 2. 核心命令（redis-cli）

```bash
# ① 存 / 取
set name tom
get name                  # "tom"

# ② 批量存 / 批量取（一次网络往返，比循环 set 快）
mset k1 v1 k2 v2
mget k1 k2                # 1) "v1"  2) "v2"

# ③ 自增 / 自减（value 必须是数字；key 不存在时从 0 开始算）
set views 100
incr views                # (integer) 101
decr views                # (integer) 100

# ④ setex：存值 + 同时设置过期秒数（验证码的标准写法）
setex sms:code:13800138000 60 8848
ttl sms:code:13800138000  # (integer) 58

# ⑤ setnx：key 不存在才设置，存在就不动（防重复的基石）
setnx lock:order:100 1    # (integer) 1  ← 抢到了
setnx lock:order:100 1    # (integer) 0  ← 已存在，没抢到
```

| 命令 | 一句话 | 频率 |
|------|--------|------|
| set / get | 存取单个 | ⭐⭐⭐ |
| mset / mget | 批量存取 | ⭐⭐ |
| incr / decr | 自增 / 自减（原子操作，天然线程安全） | ⭐⭐⭐ |
| setex | 存值 + 过期一步到位 | ⭐⭐⭐ |
| setnx | 不存在才写（防重复） | ⭐⭐ |

## 3. 四大高频场景（重点）

### 场景一：短信验证码（本阶段实操案例）

**白话**：验证码的三大需求——① 60 秒自动失效 ② 能查询剩余时间 ③ 用完即删。Redis 三件套 `setex + ttl + del` 完美命中。

```bash
setex sms:code:13800138000 60 8848     # 发送：存验证码，60 秒过期
ttl  sms:code:13800138000              # 用户问"还剩多久" → 58
get  sms:code:13800138000              # 校验：取出比对
del  sms:code:13800138000              # 验证通过后立即删除（一次性）
```

> 用 MySQL 存验证码要建表、写定时任务清理过期数据——Redis 一行命令解决。**这就是它存在的意义。**

### 场景二：接口限流（同一用户 1 分钟最多 10 次）

**白话**：给每个用户一个计数器，每次请求 +1；计数器第一次创建时设置 60 秒过期——60 秒后 key 自动消失，计数重新开始。

```bash
incr rate:user:1001                    # 每次请求先 +1
# 若返回 1（说明是这一分钟第一次），紧接着设置过期
expire rate:user:1001 60
# 若 incr 结果 > 10 → 拒绝请求（返回"请求过于频繁"）
```

> **关键点**：`incr` 是**原子操作**——1 万个请求同时打进来也不会算错。这是它比"先 get 再 set"高级的地方（后者会有并发问题，回忆第二章的线程安全问题）。

### 场景三：计数器（阅读量 / 点赞数）

```bash
incr article:view:100                  # 阅读 +1
incr article:like:100                  # 点赞 +1
get  article:view:100                  # 展示阅读量
```

> 高频计数别直接 `UPDATE ... SET views = views + 1` 打 MySQL（行锁 + 磁盘 IO 扛不住）；先累加在 Redis，定时同步回 MySQL。

### 场景四：分布式 ID（全局唯一自增号）

```bash
incr order:id                          # 1, 2, 3... 全局唯一
```

**白话**：单机数据库自增主键好用，但**分库分表后两台的 ID 会撞车**。Redis 的 `incr` 全部实例共用一个计数器，天然全局唯一。真实订单号一般再拼上日期、机器号，但核心自增段就靠它。

## 4. Java 里怎么写（StringRedisTemplate）

```java
@Autowired
private StringRedisTemplate redis;

// 验证码：存 60 秒
redis.opsForValue().set("sms:code:" + phone, code, Duration.ofSeconds(60));

// 取 + 剩余时间
String saved = redis.opsForValue().get("sms:code:" + phone);
Long ttl = redis.getExpire("sms:code:" + phone);       // 秒

// 计数器自增（返回自增后的值）
Long count = redis.opsForValue().increment("article:view:100");

// 防重复：不存在才设置成功（返回 true 表示抢到了）
Boolean ok = redis.opsForValue().setIfAbsent("lock:order:100", "1", Duration.ofSeconds(30));
```

| 命令 | Java API |
|------|---------|
| `setex k 60 v` | `opsForValue().set(k, v, Duration.ofSeconds(60))` |
| `incr k` | `opsForValue().increment(k)` |
| `setnx k v` | `opsForValue().setIfAbsent(k, v)` |

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ String 是通用载体 | 能当字符串存，也能当数字自增 |
| ✅ incr / decr 原子安全 | 高并发计数不串，比 get+set 可靠 |
| ✅ setex = 存值 + 过期 | 验证码的标准写法 |
| ✅ setnx = 防重复 | "不存在才写"，抢锁/防重发的基础 |
| ✅ 四大场景 | 验证码、限流、计数器、分布式 ID——见本节 |
