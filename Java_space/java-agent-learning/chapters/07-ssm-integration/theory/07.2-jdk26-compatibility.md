# 07.2 JDK 26 版本兼容性：版本选型与排错

> **学习目标**
> - 理解为什么老版本 SSM 跑不了新 JDK
> - 掌握与 JDK 26 兼容的版本组合（直接照着用）
> - 遇到兼容性报错时知道怎么定位

---

## 1. 先说结论：你的 JDK 26 怎么选版本

### 白话理解

你的电脑装的是 **JDK 26**。网上大多数 SSM 教程用的是 **Spring 5.3 + Tomcat 9 + javax.servlet**——**这套组合在 JDK 26 上跑不起来**。

原因（理解即可）：

| 原因 | 白话 |
|------|------|
| **ASM 字节码版本** | Spring 5.3 内置的字节码解析器（ASM）太老，**读不懂 JDK 26 编译出的 class 文件**（报 `Unsupported class file major version 70`） |
| **CGLIB 代理** | Spring 5.3 的 AOP 依赖老版 CGLIB，在新 JDK 上反射访问受限，代理失败 |
| **javax vs jakarta** | Spring 6 起包名从 `javax.servlet` 换成 `jakarta.servlet`，老教程代码直接编译不过 |

### 兼容版本组合（本项目直接用这套）

| 依赖 | 版本 | 说明 |
|------|------|------|
| **JDK** | 26 | 你的环境 |
| **Spring** | **6.2.x**（取最新小版本，如 6.2.10+） | 支持 JDK 17-26，**必须 ≥6.2** |
| **Servlet API** | `jakarta.servlet-api` **6.0.0** | 注意是 jakarta 不是 javax |
| **Tomcat** | **10.1.x**（如 10.1.28+） | 支持 jakarta.servlet 6.0 |
| **MyBatis** | **3.5.19** | 较新版本，兼容新 JDK |
| **mybatis-spring** | **3.0.4** | 3.0.x 才支持 Spring 6（2.1.x 是给 Spring 5 的） |
| **MySQL 驱动** | `mysql-connector-j` **8.4.0** | 注意新版 artifactId 是 `mysql-connector-j` |
| **Jackson** | 2.18.x | JSON 序列化 |
| **JSP API** | `jakarta.servlet.jsp-api` **3.1.0** | 页面用 JSP 时 |
| **Logback** | 1.5.x | 日志（Spring 6 默认） |

> ⚠️ **包名变化**：Spring 6 起所有 `javax.servlet` 变成 `jakarta.servlet`，代码里 `import javax.servlet.http.*` 都要改成 `import jakarta.servlet.http.*`。

## 2. 常见兼容性报错对照表

| 报错信息 | 原因 | 解决 |
|---------|------|------|
| `Unsupported class file major version 70` | Spring/ASM 版本太老 | 升级 Spring 到 6.2.x 最新版 |
| `ClassNotFoundException: javax.servlet...` | 依赖还是 javax 包 | 改用 jakarta.servlet-api |
| `NoClassDefFoundError: jakarta.servlet...` | 缺 jakarta 依赖或 Tomcat 版本不对 | 用 Tomcat 10.1+ |
| `UnsupportedOperationException: ... Add --add-opens` | CGLIB/反射在新 JDK 被限制 | Spring 6.2 已解决；还报就加 JVM 参数 `--add-opens java.base/java.lang=ALL-UNNAMED` |
| `java.lang.IllegalStateException: Error processing condition` | 依赖版本互相不匹配 | 全部按上表版本对齐 |

### 快速自查清单

- [ ] Spring 版本 ≥ 6.2
- [ ] 所有 `javax.servlet` 依赖换成 `jakarta.servlet-api`
- [ ] mybatis-spring 用 3.0.x
- [ ] Tomcat 用 10.1+
- [ ] MySQL 驱动用 `com.mysql:mysql-connector-j`

---

## 3. 老教程（Spring 5.3）怎么对照着看？

网上大量 SSM 教程是 Spring 5.3 + javax 写的，**代码主体逻辑完全一样**，只有三处需要翻译：

| 老教程（Spring 5） | 新写法（Spring 6） |
|-------------------|-------------------|
| `javax.servlet.http.HttpServletRequest` | `jakarta.servlet.http.HttpServletRequest` |
| `javax.servlet.http.HttpSession` | `jakarta.servlet.http.HttpSession` |
| `javax.servlet.annotation.WebServlet` | `jakarta.servlet.annotation.WebServlet` |

> 看到老教程报错时，先检查 import 是不是 `javax` 开头——改成本章用的 `jakarta` 就对了。

## 4. 如果还是跑不起来：最后的兜底方案

> **方案 B**：在 IDEA 里给这个项目单独指定 **JDK 17**（不影响你系统里的 JDK 26）

```
IDEA → File → Project Structure → Project SDK → 选择 JDK 17
（需要先在官网下载安装 JDK 17，IDEA 里 Add SDK 添加）
```

- 切到 JDK 17 后，就可以用经典版本：Spring 5.3.31 + Tomcat 9 + javax.servlet
- 好处：和网上所有老教程完全一致，查资料方便
- 本项目文档**默认按 JDK 26 + Spring 6.2** 编写

> **建议**：优先用 JDK 26 + Spring 6.2 方案（版本新、以后写 Spring Boot 无缝衔接）；跑不通再退回 JDK 17 方案。

---

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ JDK 26 必须配 Spring 6.2 + Tomcat 10.1 | 老组合（Spring 5.3）跑不了 |
| ✅ javax → jakarta 包名变化 | 代码 import 要改 |
| ✅ mybatis-spring 3.0.x 才支持 Spring 6 | 2.1.x 是给 Spring 5 的 |
| ✅ 报 class file major version 就是版本太老 | 升 Spring 小版本 |
| ✅ 兜底方案：项目单独用 JDK 17 | 与老教程对齐 |
