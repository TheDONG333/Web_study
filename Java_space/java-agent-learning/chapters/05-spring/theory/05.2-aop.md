# 05.2 AOP 面向切面编程（重点）

> **学习目标**
> - 理解 AOP 思想：不修改业务代码，给方法"加功能"
> - 掌握四个核心概念：通知、切点、切面、连接点
> - 会用注解版 AOP（@Aspect / @Before / @Around 等）
> - 能写出日志记录、权限校验等实际场景

---

## 1. AOP 是什么？为什么需要它？

### 白话理解

假设有 10 个 Service 方法，每个都要写日志：

```java
// 方法1
public void addUser() {
    log("开始执行 addUser");       // 重复代码！
    // 业务逻辑...
    log("addUser 执行完成");       // 重复代码！
}

// 方法2、方法3、方法4...每个都要写这两行
```

**问题**：日志、权限校验、事务这些"和业务无关的公共逻辑"，每个方法都要重复写一遍。

**AOP（面向切面编程）** 的思路：把公共逻辑抽出来，放在一个"切面"里，**Spring 自动在方法执行前后帮你调用**，业务代码里一行都不用加：

```
没有 AOP：        业务方法 + 日志代码 混在一起
有 AOP：          业务方法只有业务逻辑
                  日志代码单独放一个"切面"里
                  Spring 自动在方法调用时"织入"日志
```

> **一句话**：AOP = 不改业务代码，就能给方法"贴上"公共功能（日志、权限、事务）。你专注业务，公共逻辑交给切面。

### 技术要点

- AOP 底层是**动态代理**：Spring 给目标类生成代理对象，调用方法时代理先执行通知，再调真实方法
- 事务（下节）、Spring Security 权限都是基于 AOP 实现的

## 2. 四个核心概念（面试必背）

| 概念 | 白话理解 | 类比 |
|------|---------|------|
| **连接点（JoinPoint）** | 所有**可以**被增强的方法 | 所有房间的门 |
| **切点（Pointcut）** | 实际**选定**要被增强的方法 | 装了防盗门的那几个门 |
| **通知（Advice）** | 增强的**逻辑**（在方法前后做什么） | 装门这个动作本身 |
| **切面（Aspect）** | 切点 + 通知的组合体 | 一整套防盗系统 |

```
连接点：UserService 里所有方法（都能加功能）
切点：  只选 addUser、deleteUser 两个方法
通知：  方法执行前打日志
切面：  "在 addUser/deleteUser 前打日志" 这个整体
```

### 记忆口诀

> **连接点是候选，切点是入选**；**通知是动作，切面是整体**。

## 3. 五种通知类型

```java
@Aspect                    // 标注：这是一个切面类
@Component                 // 让 Spring 管理这个切面
public class LogAspect {

    // ① 前置通知：方法执行前
    @Before("execution(* com.demo.service.*.*(..))")
    public void before() {
        System.out.println("【前置】方法开始执行");
    }

    // ② 后置通知：方法执行后（无论成功失败）
    @After("execution(* com.demo.service.*.*(..))")
    public void after() {
        System.out.println("【后置】方法执行完毕");
    }

    // ③ 返回通知：方法成功返回后（可以拿到返回值）
    @AfterReturning(value = "execution(* com.demo.service.*.*(..))", returning = "result")
    public void afterReturning(Object result) {
        System.out.println("【返回】返回结果 = " + result);
    }

    // ④ 异常通知：方法抛出异常后
    @AfterThrowing(value = "execution(* com.demo.service.*.*(..))", throwing = "e")
    public void afterThrowing(Exception e) {
        System.out.println("【异常】方法报错: " + e.getMessage());
    }

    // ⑤ 环绕通知：方法前后都能控制（最强大，可决定是否执行方法）
    @Around("execution(* com.demo.service.*.*(..))")
    public Object around(ProceedingJoinPoint pjp) throws Throwable {
        System.out.println("【环绕】方法调用前...");
        Object result = pjp.proceed();   // 调用真实方法（不放行就不执行！）
        System.out.println("【环绕】方法调用后...");
        return result;
    }
}
```

### 五种通知对比

| 通知 | 执行时机 | 特点 |
|------|---------|------|
| `@Before` | 方法执行前 | 拿不到返回值 |
| `@After` | 方法执行后（无论成败） | 类似 finally |
| `@AfterReturning` | 方法**成功**返回后 | 能拿到返回值 |
| `@AfterThrowing` | 方法**抛异常**后 | 能拿到异常对象 |
| `@Around` | 前后都能控制 | 最强大，能拦截/修改/放弃执行 |

## 4. 切点表达式怎么读

### 白话理解

`execution(修饰符 返回值 类.方法(参数))` 是一套"选择方法"的规则。

```java
// 解析：com.demo.service 包下 所有类的 所有方法（任意参数）
"execution(* com.demo.service.*.*(..))"
//          ↑返回值任意  ↑包            ↑类   ↑方法 ↑参数任意

// 限定某个方法
"execution(public void com.demo.service.UserService.addUser(..))"

// 限定返回值类型
"execution(* com.demo.service.*.add*(..))"   // add 开头的方法
```

| 片段 | 含义 |
|------|------|
| `*` | 任意返回值 / 任意类 |
| `..` | 任意参数（0 个或多个） |
| `com.demo.service.*` | 该包下的所有类 |

> 记不住表达式没关系，能读懂、会用 `*` 和 `..` 就行。实际开发中大部分切点直接写 `execution(* com.你的包..*.*(..))`。

## 5. 实际场景一：日志记录（完整示例）

```java
@Aspect
@Component
public class LogAspect {

    // 给 service 包下所有方法加日志
    @Around("execution(* com.demo.service.*.*(..))")
    public Object logAround(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();

        System.out.println("【日志】调用: " + pjp.getSignature().getName()
                + " 参数: " + Arrays.toString(pjp.getArgs()));

        Object result = pjp.proceed();   // 执行真实方法

        long cost = System.currentTimeMillis() - start;
        System.out.println("【日志】完成, 耗时: " + cost + "ms");

        return result;
    }
}
```

**效果**：Service 里每个方法运行都会自动打印日志，**业务代码零改动**。

## 6. 实际场景二：权限校验

```java
@Aspect
@Component
public class PermissionAspect {

    // 拦截 Controller 中所有方法，先检查是否登录
    @Around("execution(* com.demo.controller.*.*(..))")
    public Object checkPermission(ProceedingJoinPoint pjp) throws Throwable {
        // 模拟从 Session/Token 获取当前用户
        String currentUser = getCurrentUser();

        if (currentUser == null) {
            throw new RuntimeException("未登录，禁止访问！");
        }

        System.out.println("【权限】当前用户: " + currentUser + " 放行");
        return pjp.proceed();   // 有权限才执行
    }

    private String getCurrentUser() {
        return null;  // 演示：假装没人登录 → 会抛异常
    }
}
```

> 这就是 Spring Security 的雏形——基于 AOP 在方法调用前做校验。你想加"登录才能访问"，不用改每个方法，加一个切面就搞定。

## 7. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ AOP = 不修改业务代码，自动加公共功能 | 日志、权限、事务全靠它 |
| ✅ 四个概念：连接点 / 切点 / 通知 / 切面 | 候选 / 入选 / 动作 / 整体 |
| ✅ 五种通知：Before / After / AfterReturning / AfterThrowing / Around | Around 最强大 |
| ✅ 切点表达式：execution(返回值 包.类.方法(参数)) | 会用 * 和 .. 即可 |
| ✅ 实际场景：日志记录、权限校验 | 都是加一个切面类搞定 |
