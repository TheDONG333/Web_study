# 05.1 IOC 控制反转与 DI 依赖注入

> **学习目标**
> - 理解 IOC 是什么、解决了什么问题
> - 会用 xml 和注解两种方式注册 Bean
> - 掌握依赖注入的几种方式
> - 掌握 Bean 作用域与生命周期（面试必背）

---

## 1. IOC 是什么？为什么需要它？

### 白话理解

**没有 IOC 时**，对象之间的依赖全靠自己 new：

```java
public class UserService {
    // 自己创建依赖对象（传统写法）
    private UserDao userDao = new UserDaoImpl();
}
```

问题：如果你把 `UserDaoImpl` 换成 `UserDaoMySql`，要改代码、重新编译。类与类之间**紧紧绑在一起**（耦合度高）。

**有了 IOC 后**，对象不自己 new 了，交给 Spring 统一管理：

```
以前：UserService 自己 new UserDao    （自己管自己）
现在：Spring 容器 new 所有对象         （统一管理）
      UserService 说"我需要一个 UserDao"
      Spring 从容器里拿一个给它        （依赖注入 DI）
```

| 概念 | 白话理解 |
|------|---------|
| **IOC（控制反转）** | 创建对象的控制权从"自己 new"反转给"Spring 容器" |
| **容器** | Spring 创建的"对象仓库"，所有 Bean 都放里面 |
| **DI（依赖注入）** | 容器把依赖对象"送"给需要它的 Bean |

> **一句话**：IOC 是思想（对象不自己 new），DI 是实现手段（容器把依赖送过来）。IOC 负责注册和管理 Bean，DI 负责把 Bean 注入到需要它的地方。

### Spring 的地位

**Spring 是 SSM 的"根"**：Spring Boot 底层就是 Spring，它管理所有对象的创建和依赖关系。学好这一章，后面看 Spring Boot 就能看懂大半。

## 2. 用 XML 注册 Bean（传统方式）

### 白话理解

在配置文件中告诉 Spring："这个类归你管，创建对象后放进容器"。

```xml
<!-- applicationContext.xml -->
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans
       http://www.springframework.org/schema/beans/spring-beans.xsd">

    <!-- 把 UserDaoImpl 注册为 Bean，id 是容器里的名字 -->
    <bean id="userDao" class="com.demo.dao.impl.UserDaoImpl"/>

    <!-- 把 UserService 注册为 Bean，并注入 userDao -->
    <bean id="userService" class="com.demo.service.impl.UserServiceImpl">
        <property name="userDao" ref="userDao"/>
    </bean>

</beans>
```

**Java 中从容器取对象：**

```java
ClassPathXmlApplicationContext ctx = new ClassPathXmlApplicationContext("applicationContext.xml");

// 从容器取 Bean（按 id）
UserService service = (UserService) ctx.getBean("userService");
service.xxx();
```

### 技术要点

- `<bean>` 标签 = 注册一个对象，`class` 写全类名，`id` 是容器里的名字
- `<property name="xxx" ref="yyy">` = 注入依赖（setter 注入，下节详讲）
- 容器创建好后，所有对象都归它管，想用就从 `getBean` 取

## 3. 用注解注册 Bean（主流方式）

### 白话理解

XML 写起来太啰嗦。Spring 提供四个注解，标在类上就能注册为 Bean，Spring 启动时会自动扫描。

| 注解 | 放在哪 | 白话理解 |
|------|--------|---------|
| `@Component` | 通用类 | "这个类归 Spring 管"（通用） |
| `@Service` | Service 层 | 业务逻辑类 |
| `@Repository` | Dao 层 | 数据访问类 |
| `@Controller` | 控制层 | 接收请求的类 |

> 四个注解功能一样，只是语义不同，方便别人看懂分层。

```java
@Service        // 标注：这个类交给 Spring 管理
public class UserServiceImpl implements UserService {
    @Autowired  // 标注：帮我注入 UserDao
    private UserDao userDao;

    public void register() {
        userDao.save();  // 直接用，不需要 new！
    }
}
```

**配置组件扫描（applicationContext.xml）：**

```xml
<context:component-scan base-package="com.demo"/>
```

> 这一行告诉 Spring："去 com.demo 包下找所有标了 @Component/@Service/@Repository/@Controller 的类，全部注册进容器"。

## 4. 依赖注入 DI：三种方式

### 4.1 字段注入（@Autowired 直接标在字段上，最常用）

```java
@Service
public class UserServiceImpl implements UserService {
    @Autowired
    private UserDao userDao;   // 容器自动注入，不用 new、不用 setter
}
```

### 4.2 Setter 注入（xml 方式对应）

```java
@Service
public class UserServiceImpl implements UserService {
    private UserDao userDao;

    @Autowired
    public void setUserDao(UserDao userDao) {
        this.userDao = userDao;
    }
}
```

### 4.3 构造器注入（官方推荐）

```java
@Service
public class UserServiceImpl implements UserService {
    private final UserDao userDao;  // final：依赖不可变

    @Autowired
    public UserServiceImpl(UserDao userDao) {
        this.userDao = userDao;     // 通过构造器传入
    }
}
```

### @Autowired vs @Resource 对比（面试高频）

| 对比 | @Autowired | @Resource |
|------|-----------|-----------|
| 来源 | Spring 自己的注解 | JDK 标准注解（javax.annotation） |
| 按什么找 | **按类型**找（byType） | **按名称**找（byName） |
| 多个同类型时 | 报错，需配 @Qualifier | 用 name 属性指定 |
| 使用频率 | 更常用 | 也常见（工作中两种都会遇到） |

```java
// 多个同类型 Bean 时，@Autowired 要配合 @Qualifier 指定名字
@Autowired
@Qualifier("userDaoImpl")
private UserDao userDao;

// @Resource 直接指定名字
@Resource(name = "userDaoImpl")
private UserDao userDao;
```

## 5. Bean 作用域：singleton / prototype（面试必背）

### 白话理解

作用域决定"这个 Bean 在容器里是**一个**还是**多个**"。

| 作用域 | 白话理解 | 特点 |
|--------|---------|------|
| `singleton`（默认） | 容器里只有**一个**实例，谁都拿到同一个 | 省内存，但**有线程安全问题**（有状态字段时） |
| `prototype` | 每次获取都**新建一个**实例 | 无共享问题，但开销大 |

```java
@Service
@Scope("prototype")   // 改成每次获取都是新对象
public class DemoService {
}

// singleton 时：
// ctx.getBean() 两次 → 同一个对象（== 比较为 true）
// prototype 时：
// ctx.getBean() 两次 → 两个不同对象
```

### 面试必背

> **singleton**：容器创建时只创建一个实例，每次 getBean 返回同一个。省资源，但 Bean 内有可变成员变量时线程不安全。
> **prototype**：每次 getBean 都创建新实例。无共享，但创建开销大。
> **默认是 singleton**；有状态的对象用 prototype，无状态的（Service、Dao）用 singleton 即可。

## 6. Bean 生命周期（了解流程即可）

### 白话理解

一个 Bean 从出生到销毁，Spring 会依次调用这些阶段：

```
① 实例化（new 出对象）
② 属性注入（注入依赖）
③ 初始化 init-method（可自定义）
④ 就绪，可以干活了
⑤ 容器关闭时销毁 destroy-method
```

```java
@Component
public class MyBean {

    @PostConstruct          // 初始化后执行（等价于 init-method）
    public void init() {
        System.out.println("Bean 初始化完成");
    }

    @PreDestroy             // 销毁前执行（等价于 destroy-method）
    public void destroy() {
        System.out.println("Bean 即将销毁");
    }
}
```

> 白话记忆：**出生（构造）→ 喂奶（注入）→ 上学（init）→ 工作 → 退休（destroy）**。

---

## 7. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ IOC = 对象不自己 new，交给 Spring 容器 | 控制权反转，解耦 |
| ✅ 四个注解：@Component/@Service/@Repository/@Controller | 标了就被容器管理，需配组件扫描 |
| ✅ 注入方式：字段 / Setter / 构造器 | 构造器注入官方推荐，字段注入最方便 |
| ✅ @Autowired 按类型，@Resource 按名称 | 同类型多个时要指定 |
| ✅ 默认 singleton，有状态用 prototype | 面试必背 |
| ✅ 生命周期：构造 → 注入 → init → 使用 → destroy | @PostConstruct / @PreDestroy |
