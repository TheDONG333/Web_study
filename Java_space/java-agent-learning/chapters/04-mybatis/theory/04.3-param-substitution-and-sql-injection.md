# 04.3 #{} 与 ${}：SQL 注入防护（面试高频）

> **学习目标**
> - 理解 #{} 和 ${} 的底层区别
> - 能解释 SQL 注入的原理
> - 知道什么时候必须用 ${}

---

## 1. 什么是 SQL 注入？

### 白话理解

假设登录 SQL 是这样拼出来的：

```java
String sql = "SELECT * FROM users WHERE username = '" + username + "' AND password = '" + password + "'";
```

如果用户在用户名框输入：`admin' -- `（admin 后面加引号加空格加注释符号），拼出来就是：

```sql
SELECT * FROM users WHERE username = 'admin' -- ' AND password = 'xxx'
```

`--` 在 SQL 里是**注释**，后面的密码判断被整段注释掉了。于是**不用密码就能以 admin 登录**——这就是 SQL 注入。

### 技术要点

SQL 注入的本质：**用户输入被当成 SQL 代码执行了**。解决办法：用户输入只当**数据**看，不当**代码**看。

---

## 2. #{}：预编译（安全）

### 白话理解

`#{}` 把参数交给数据库的**预编译机制**（PreparedStatement）处理：SQL 先编译好，参数之后通过占位符 `?` 单独传递。用户输入永远是"数据"，不可能变成 SQL 代码。

```xml
<select id="findByUsername" resultType="User">
    SELECT * FROM users WHERE username = #{username}
</select>
```

实际发给数据库的（参数单独传）：

```sql
SELECT * FROM users WHERE username = ?
```

即使传入 `admin' -- `，数据库也只当作普通字符串去匹配，**不会执行**。

### 技术要点

- 底层是 `PreparedStatement` + `setString()` 设置参数
- 天然防 SQL 注入
- **能用 #{} 的地方必须用 #{}**（日常 99% 的场景）

---

## 3. ${}：字符串拼接（危险）

### 白话理解

`${}` 直接把值**拼进 SQL 字符串**，相当于上面的手写拼接。传什么 SQL 就变成什么。

```xml
<select id="findByUsername2" resultType="User">
    SELECT * FROM users WHERE username = ${username}
</select>
```

如果 `username = admin' -- `，SQL 变成：

```sql
SELECT * FROM users WHERE username = admin' -- 
```

**注入成功，SQL 报错或绕过校验。**

---

## 4. 对比总结（面试必背）

| 对比 | #{} | ${} |
|------|-----|-----|
| 底层机制 | PreparedStatement 预编译 + `?` 占位 | 字符串直接拼接 |
| 安全性 | ✅ 防 SQL 注入 | ❌ 有注入风险 |
| 是否能处理引号 | ✅ 自动加引号转义 | ❌ 需自己加引号 |
| 适用场景 | 传值（条件、参数） | 表名、列名、排序字段等 SQL 片段 |

### 面试标准回答

> `#{}` 是预编译占位符，底层使用 PreparedStatement 的 `?`，参数作为数据传递，能防止 SQL 注入；`${}` 是字符串拼接，直接把值拼进 SQL，存在注入风险，**只允许用在不会变的值上**（如表名、排序字段），且这些值绝不能来自用户输入。

---

## 5. 什么时候必须用 ${}

场景：动态排序、动态表名。

```xml
<!-- 排序字段和排序方向没法用 #{}（因为它是 SQL 片段，不是值） -->
<select id="findOrdered" resultType="User">
    SELECT * FROM users
    ORDER BY ${column} ${direction}
</select>
```

```java
Map<String, Object> params = new HashMap<>();
params.put("column", "id");       // 代码里写死，不允许用户传
params.put("direction", "DESC");

List<User> list = session.selectList("userMapper.findOrdered", params);
```

### 使用 ${} 的安全底线

- 值必须在**代码里写死**（枚举、白名单校验）
- 绝不直接接收用户输入
- 需要用户选择排序字段时，先用代码校验：

```java
// 白名单校验：只允许这两个值
String column = "id".equals(input) ? "id" : "username";
```

---

## 6. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 默认用 #{} | 预编译，防注入，自动加引号 |
| ✅ ${} 只用于表名/列名/排序等 SQL 片段 | 且值必须代码写死 |
| ✅ SQL 注入 = 用户输入变成 SQL 代码 | 预编译让输入永远只是数据 |
| ✅ 面试答法：预编译占位 vs 字符串拼接 | 安全 vs 危险 |
