## 1. 「白话篇」Servlet 到底是什么？为什么需要它？

### 1.1 从餐厅服务员讲起

想象你去一家餐厅吃饭：

- 你（浏览器）点了菜，把订单交给了服务员（Servlet）
- 服务员跑到后厨告诉你厨师（Java 业务代码）要做什么菜
- 厨师做好后，服务员把菜端回给你

**Servlet 就是这个"服务员"**——它在浏览器和你的 Java 业务代码之间来回传递数据：

```
浏览器（客户端）──发送请求──▶ Servlet（服务员）──调用──▶ Java 业务代码（后厨）
                                                      │
浏览器（客户端）◀──返回响应──  Servlet（服务员）◀──返回结果──┘
```

> **一句话总结**：Servlet 是 Java Web 的"门面"，所有从浏览器发来的 HTTP 请求，都由 Servlet 接住、解析，再交给后面的 Java 代码处理，处理完再由 Servlet 把结果返回给浏览器。

### 1.2 没有框架时的原始形态

你平时用 Spring Boot 写 Controller 是这样的：

```java
@RestController
public class UserController {
    @GetMapping("/users")
    public List<User> getUsers() {
        return userService.findAll();
    }
}
```

只需加 `@GetMapping` 注解，框架就帮你把请求路由到这个方法。但 Spring MVC 底层，**每个请求到达时，真正干活的就是 Servlet**。

> Spring MVC 的 `DispatcherServlet` 就是一个 Servlet，它负责把所有请求分发给各个 Controller。

理解 Servlet，你就理解了 **Spring MVC 的底层根基**。

### 1.3 从代码层面看 Servlet 是什么

```java
// Servlet 本质上是一个接口，你的类实现这个接口就是"一个 Servlet"
public interface Servlet {
    void init(ServletConfig config);      // 初始化：Servlet 出生时调用一次
    void service(ServletRequest req, ServletResponse res); // 服务：每次请求来都调用
    void destroy();                        // 销毁：Servlet 被干掉时调用一次
}
```

实际开发中，你不需要直接实现 `Servlet` 接口，而是**继承 `HttpServlet` 类**，然后重写 `doGet()` 或 `doPost()` 方法：

```java
// 专门处理 HTTP 请求的便捷基类
public abstract class HttpServlet extends GenericServlet {
    // 根据请求方法（GET/POST/PUT/DELETE）自动分发给对应的方法
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) { ... }
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) { ... }
    protected void doPut(HttpServletRequest req, HttpServletResponse resp) { ... }
    protected void doDelete(HttpServletRequest req, HttpServletResponse resp) { ... }
}
```

> **白话**：你不用关心底层怎么解析 HTTP 报文，HttpServlet 已经帮你把请求头/请求体/请求参数都提取好了，你直接从 `req` 对象里取数据就行。

## 2. Servlet 生命周期：三个阶段的完整走向

### 2.1 生命周期全景

```
① init()        ──▶ ② service()    ──▶ ③ destroy()
  （出生，一次）        （干活，每次请求）        （销毁，一次）
```

| 阶段 | 方法 | 调用次数 | 做什么 | 白话理解 |
|------|------|---------|--------|---------|
| **初始化** | `init()` | 只调用 1 次 | 加载配置、建立数据库连接等 | "服务员上岗培训" |
| **服务** | `service()` → `doGet()`/`doPost()` | 每个请求调 1 次 | 处理请求、返回响应 | "服务员接单送菜" |
| **销毁** | `destroy()` | 只调用 1 次 | 释放资源、关闭连接 | "服务员下班收拾" |

### 2.2 详细生命周期流程（带代码）

```java
import javax.servlet.*;
import javax.servlet.http.*;
import javax.servlet.annotation.*;
import java.io.*;

// @WebServlet 注解：告诉 Tomcat 这个 Servlet 负责处理哪个 URL
@WebServlet("/lifecycle")
public class LifecycleDemoServlet extends HttpServlet {

    // ========== ① init()：Servlet 创建时调用一次 ==========
    @Override
    public void init() throws ServletException {
        System.out.println("===== Servlet 初始化：init() 被调用了 =====");
        System.out.println("这里适合做：加载配置文件、建立数据库连接池、预热缓存等");
        System.out.println("整个 Servlet 生命周期中只执行一次\n");
    }

    // ========== ② service() → doGet()/doPost()：每次请求都调用 ==========
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        System.out.println("===== 收到 GET 请求：第 N 次处理请求 =====");
        System.out.println("请求线程：" + Thread.currentThread().getName());
        System.out.println("请求 URL：" + req.getRequestURL());
        System.out.println("请求参数：" + req.getQueryString());
        System.out.println();

        resp.setContentType("text/html;charset=UTF-8");
        resp.getWriter().write("<h2>Servlet 生命周期演示</h2><p>请查看控制台输出</p>");
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        // POST 请求会自动路由到这里
        System.out.println("===== 收到 POST 请求 =====");
        doGet(req, resp);  // 简单起见，交给 doGet 处理
    }

    // ========== ③ destroy()：Servlet 销毁时调用一次 ==========
    @Override
    public void destroy() {
        System.out.println("===== Servlet 销毁：destroy() 被调用了 =====");
        System.out.println("这里适合做：关闭数据库连接、释放文件句柄、清理临时数据");
        System.out.println("整个 Servlet 生命周期中只执行一次");
    }
}
```

**运行后控制台输出（两次请求）：**

```
===== Servlet 初始化：init() 被调用了 =====          ← 只有第一次访问时输出
整个 Servlet 生命周期中只执行一次

===== 收到 GET 请求：第 1 次处理请求 =====            ← 每次访问都输出
请求线程：http-nio-8080-exec-1
请求 URL：http://localhost:8080/demo/lifecycle

===== 收到 GET 请求：第 2 次处理请求 =====            ← 第二次访问又输出
请求线程：http-nio-8080-exec-2

（关闭 Tomcat 时才会输出 destroy）
===== Servlet 销毁：destroy() 被调用了 =====
```

> 💡 **关键理解**：
> - `init()` 只在**第一次访问**时调用（如果 `loadOnStartup` 设置了正数则在 Tomcat 启动时就调）
> - 后续的请求不会再走 `init()`，直接走 `doGet()`/`doPost()`
> - **同一个 Servlet 实例**会被多个请求线程共享，这就是 Servlet 线程不安全的根源

### 2.3 Servlet 的线程模型（重要！）

```
Tomcat 线程池 ├─▶ 线程1 ──▶ 同一 Servlet 实例 ──▶ doGet()
              ├─▶ 线程2 ──▶ 同一 Servlet 实例 ──▶ doGet()
              ├─▶ 线程3 ──▶ 同一 Servlet 实例 ──▶ doGet()
              └─▶ ...
```

> ⚠️ **重大陷阱**：Tomcat 只创建一个 Servlet 实例，所有请求线程共享它。如果你在 Servlet 中定义了**成员变量**，多个线程会同时读写它，导致线程安全问题！

```java
// ❌ 错误写法：成员变量有线程安全问题
@WebServlet("/bad")
public class BadServlet extends HttpServlet {
    private int counter = 0;  // 所有请求线程共享！

    protected void doGet(HttpServletRequest req, HttpServletResponse resp) {
        counter++;  // 线程不安全！可能丢失计数
        resp.getWriter().write("第 " + counter + " 次访问");
    }
}

// ✅ 正确写法：局部变量不存在线程安全问题
@WebServlet("/good")
public class GoodServlet extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) {
        int counter = 0;  // 每个线程独立拥有
        counter++;
        resp.getWriter().write("第 " + counter + " 次访问");
    }
}
```

## 3. HttpServletRequest：从请求中拿数据

> **白话**：`req` 对象里装的是浏览器发过来的所有东西——URL 参数、表单数据、Cookie、请求头、客户端 IP……你要什么就从里面取。

### 3.1 获取请求行信息（URL / 方法 / 协议）

```java
protected void doGet(HttpServletRequest req, HttpServletResponse resp) {
    // ── 请求行信息 ──
    String method = req.getMethod();           // GET / POST / PUT / DELETE
    String requestURI = req.getRequestURI();   // /demo/user/info
    StringBuffer requestURL = req.getRequestURL(); // http://localhost:8080/demo/user/info
    String protocol = req.getProtocol();       // HTTP/1.1
    String queryString = req.getQueryString(); // name=张三&age=25（只有 GET 有）

    System.out.println("请求方法：" + method);
    System.out.println("请求URI：" + requestURI);
    System.out.println("完整URL：" + requestURL);
    System.out.println("查询字符串：" + queryString);
}
```

**访问 `http://localhost:8080/demo/user/info?name=张三&age=25` 时输出：**

```
请求方法：GET
请求URI：/demo/user/info
完整URL：http://localhost:8080/demo/user/info
查询字符串：name=张三&age=25
```

### 3.2 获取请求参数（GET 和 POST 通用）

这是**最常用**的操作，而且 `req.getParameter()` 对 GET（URL 参数）和 POST（表单 Body 参数）**通用**：

```java
protected void doPost(HttpServletRequest req, HttpServletResponse resp) {
    // ── ① 获取单个参数 ──
    String username = req.getParameter("username");  // 获取 username 参数

    // ── ② 获取多值参数（如 checkbox） ──
    String[] hobbies = req.getParameterValues("hobby"); // hobby=篮球&hobby=足球

    // ── ③ 获取所有参数名 ──
    Enumeration<String> paramNames = req.getParameterNames();
    while (paramNames.hasMoreElements()) {
        String name = paramNames.nextElement();
        String value = req.getParameter(name);
        System.out.println(name + " = " + value);
    }

    // ── ④ 获取所有参数的 Map（处理未知参数时常用）──
    Map<String, String[]> paramMap = req.getParameterMap();
    for (Map.Entry<String, String[]> entry : paramMap.entrySet()) {
        System.out.println(entry.getKey() + " → " + String.join(",", entry.getValue()));
    }
}
```

> **白话**：不管请求是 GET（参数在 URL 上）还是 POST（参数在 Body 里），`req.getParameter("key")` 都能拿到值。这是 Servlet 规范帮你做好的——不需要手动解析 URL 或 Body。

### 3.3 获取请求头信息

```java
protected void doGet(HttpServletRequest req, HttpServletResponse resp) {
    // ── 获取单个请求头 ──
    String userAgent = req.getHeader("User-Agent");
    String accept = req.getHeader("Accept");
    String referer = req.getHeader("Referer");

    // ── 遍历所有请求头 ──
    Enumeration<String> headerNames = req.getHeaderNames();
    while (headerNames.hasMoreElements()) {
        String name = headerNames.nextElement();
        String value = req.getHeader(name);
        System.out.println(name + " : " + value);
    }
}
```

### 3.4 获取客户端信息

```java
// 客户端 IP（注意：有代理时要处理 X-Forwarded-For）
String remoteAddr = req.getRemoteAddr();
// 客户端端口
int remotePort = req.getRemotePort();
// 服务器当前上下文路径

```

### 3.5 请求域对象（Request Attribute）：同一次请求内共享数据

> **白话**：转发时，前一个 Servlet 怎么把数据传给后一个 Servlet？靠的就是 `req.setAttribute("key", value)`——把数据存在 request 对象上，同一个请求内到处都能取。

```java
// ====== ServletA.java：处理请求，然后转发 ======
@WebServlet("/servletA")
public class ServletA extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {

        // 1. 处理业务，得到数据
        User user = new User("张三", 25);

        // 2. 把数据放进 request 域
        req.setAttribute("user", user);           // 可以放任意对象
        req.setAttribute("message", "操作成功");
        req.setAttribute("timestamp", System.currentTimeMillis());

        // 3. 转发给 ServletB（后续会详细讲）
        req.getRequestDispatcher("/servletB").forward(req, resp);
    }
}

// ====== ServletB.java：接收转发过来的请求 ======
@WebServlet("/servletB")
public class ServletB extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {

        // 4. 从 request 域中取出数据
        User user = (User) req.getAttribute("user");
        String message = (String) req.getAttribute("message");
        Long timestamp = (Long) req.getAttribute("timestamp");

        System.out.println("收到转发数据：" + user + ", " + message + ", " + timestamp);

        // 注意：取出来后数据还在，不会消失
    }
}
```

> ⚠️ **关键**：`req.setAttribute()` 存放的数据只能在**同一次请求**内访问。请求结束后（响应返回给浏览器）这些数据就没了。

### 3.6 表单数据获取（完整示例）

下面是一个完整的注册表单处理示例，对接 HTML 表单提交：

**HTML 前端：**
```html
<form action="/demo/register" method="post">
    用户名：<input type="text" name="username"><br>
    密码：  <input type="password" name="password"><br>
    性别：  <input type="radio" name="gender" value="male">男
           <input type="radio" name="gender" value="female">女<br>
    爱好：  <input type="checkbox" name="hobby" value="篮球">篮球
           <input type="checkbox" name="hobby" value="足球">足球
           <input type="checkbox" name="hobby" value="编程">编程<br>
    城市：  <select name="city">
               <option value="北京">北京</option>
               <option value="上海">上海</option>
           </select><br>
    <button type="submit">注册</button>
</form>
```

**Servlet 后端：**
```java
@WebServlet("/register")
public class RegisterServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {

        // 设置请求编码（只影响 POST Body，GET 的 URL 参数需单独处理）
        req.setCharacterEncoding("UTF-8");
        resp.setContentType("text/html;charset=UTF-8");
        PrintWriter out = resp.getWriter();

        // ── 获取单值参数 ──
        String username = req.getParameter("username");
        String password = req.getParameter("password");
        String gender = req.getParameter("gender");
        String city = req.getParameter("city");

        // ── 获取多值参数（checkbox）──
        String[] hobbies = req.getParameterValues("hobby");

        out.println("<h2>注册信息</h2>");
        out.println("<p>用户名：" + username + "</p>");
        out.println("<p>密码：" + password + "</p>");
        out.println("<p>性别：" + (gender != null ? gender : "未选择") + "</p>");
        out.println("<p>城市：" + city + "</p>");
        out.println("<p>爱好：");
        if (hobbies != null) {
            for (String h : hobbies) {
                out.print(h + " ");
            }
        }
        out.println("</p>");
    }
}
```

> 💡 **中文乱码处理**：
> - POST 请求：`req.setCharacterEncoding("UTF-8");` 必须在 `getParameter()` 之前调用
> - GET 请求：Tomcat 8+ 默认用 UTF-8 解码 URL 参数，一般不需要额外处理；Tomcat 7 及以下需改 server.xml

## 4. HttpServletResponse：向浏览器返回数据

> **白话**：`resp` 对象是你能控制"返回什么给浏览器"的全部手段——内容、状态码、响应头、重定向，都在这个对象上操作。

### 4.1 响应数据的三种输出方式

| 方式 | 获取方法 | 返回类型 | 适用场景 |
|------|---------|---------|---------|
| **字符流** | `resp.getWriter()` | `PrintWriter` | 返回文本（HTML、JSON、XML 等） |
| **字节流** | `resp.getOutputStream()` | `ServletOutputStream` | 返回二进制（图片、PDF、文件下载） |

> ⚠️ **这两种流不能同时使用**，一个响应只能用一种。

```java
// 方式一：字符流（最常用）
protected void doGet(HttpServletRequest req, HttpServletResponse resp)
        throws IOException {
    resp.setContentType("application/json;charset=UTF-8");
    PrintWriter out = resp.getWriter();
    out.println("{\"name\":\"张三\", \"age\":25, \"msg\":\"你好世界\"}");
    // out.flush(); ← 一般不手动 flush，容器会自动处理
}

// 方式二：字节流（文件下载）
protected void doGet(HttpServletRequest req, HttpServletResponse resp)
        throws IOException {
    resp.setContentType("application/octet-stream");
    resp.setHeader("Content-Disposition", "attachment;filename=avatar.png");

    // 读取图片文件写入响应
    FileInputStream fis = new FileInputStream("D:/images/avatar.png");
    ServletOutputStream out = resp.getOutputStream();

    byte[] buffer = new byte[1024];
    int len;
    while ((len = fis.read(buffer)) != -1) {
        out.write(buffer, 0, len);
    }
    fis.close();
}
```

### 4.2 设置响应状态码和响应头

```java
protected void doPost(HttpServletRequest req, HttpServletResponse resp)
        throws IOException {
    // ── 设置状态码 ──
    resp.setStatus(HttpServletResponse.SC_CREATED);           // 201
    resp.setStatus(HttpServletResponse.SC_INTERNAL_SERVER_ERROR); // 500

    // ── 设置响应头 ──
    resp.setContentType("text/html;charset=UTF-8");           // 内容类型
    resp.setHeader("Cache-Control", "no-cache");              // 缓存控制
    resp.setHeader("X-Custom-Header", "custom-value");        // 自定义响应头
    resp.addHeader("Set-Cookie", "sessionId=abc123");         // 添加 Cookie
    resp.setIntHeader("X-Rate-Limit", 100);                   // 整数头字段

    // ── 两个特殊的状态码设置方法 ──
    // 302 重定向（便捷方法）
    resp.sendRedirect("/demo/login.html");
    // 设置 500 并输出错误信息（便捷方法）
    resp.sendError(HttpServletResponse.SC_NOT_FOUND, "用户不存在");
}
```

### 4.3 乱码问题的正确设置

> 这是**初学者最容易踩的坑**——中文输出变问号。

需要同时设置**编码方式**（`.setCharacterEncoding()`）和**内容类型中的编码声明**（`Content-Type` 里的 `charset`）：

```java
// ========== 推荐写法（一步到位）==========
resp.setContentType("text/html;charset=UTF-8");
// 这行干了三件事：
// ① 告诉浏览器"这是 HTML"
// ② 告诉浏览器"编码是 UTF-8"
// ③ 告诉 Servlet 容器"写出去的字符也用 UTF-8 编码"

// ========== 写法对比 ==========
// ❌ 只设置了字符集，没告诉浏览器用什么解码
resp.setCharacterEncoding("UTF-8");

// ✅ 同时设置 Content-Type（推荐）
resp.setContentType("text/html;charset=UTF-8");

// ✅ 两行分开写等效于一行 setContentType
resp.setCharacterEncoding("UTF-8");
resp.setContentType("text/html");  // 但 Content-Type 中的 charset 不会自动设置
```

> **白话**：`setCharacterEncoding("UTF-8")` 是告诉 Servlet 容器"我输出中文时别乱码"；`setContentType("text/html;charset=UTF-8")` 在此基础上还同时告诉浏览器"你收到后也按 UTF-8 解码"。推荐只用 `setContentType("...;charset=UTF-8")` 一次搞定。

## 5. 转发（Forward）与重定向（Redirect）：核心区别

> 这是面试**必考题**，也是开发中最常用的两个请求跳转方式。

### 5.1 生活类比

| | 转发（Forward） | 重定向（Redirect） |
|------|---------|---------|
| **类比** | 你去 A 窗口办事，A 说"我帮你转给 B"，你在原地等，A 和 B 内部交接 | 你去 A 窗口，A 说"你去 B 窗口办"，你得自己走过去 |
| **浏览器地址栏** | 不变 | 变了（变成新地址） |
| **浏览器知道吗** | 不知道（一次请求，服务器内部转发） | 知道（两次请求） |

### 5.2 代码对比

```java
// ========== ① 转发（Forward）：服务器内部跳转 ==========
@WebServlet("/forward-demo")
public class ForwardServlet extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {

        // 设置数据（转发时可以携带数据）
        req.setAttribute("message", "从 ForwardServlet 传来的数据");

        // 转发到 /target（request 和 response 对象直接传递）
        req.getRequestDispatcher("/target").forward(req, resp);

        // ⚠️ 注意：forward 之后的代码也会执行，但输出到浏览器的内容会被忽略
        System.out.println("这行还是会打印，但 resp 的输出会被忽略");
    }
}

// ========== ② 重定向（Redirect）：浏览器重新发请求 ==========
@WebServlet("/redirect-demo")
public class RedirectServlet extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {

        // 方式1：直接发 302 + Location 头
        resp.setStatus(302);
        resp.setHeader("Location", "/demo/target");

        // 方式2：便捷方法（最常用）
        resp.sendRedirect("/demo/target");

        // ⚠️ 注意：重定向后，旧 request 对象中的数据全部丢失！
        // 因为浏览器会发起一个全新的 HTTP 请求
    }
}
```

### 5.3 核心区别表（面试必背）

| 对比维度 | 转发（Forward） | 重定向（Redirect） |
|---------|----------------|-------------------|
| **HTTP 请求数** | 1 次 | 2 次（浏览器收到 302 后重新发起 GET） |
| **地址栏 URL** | 不变 | 变成跳转后的 URL |
| **Request 域数据** | ✅ 可以携带（同一个 request） | ❌ 丢失（新 request） |
| **跨域跳转** | ❌ 不能（只能同项目内） | ✅ 可以（http → https、跨站点） |
| **发生位置** | 服务器内部 | 浏览器端 |
| **状态码** | 200（浏览器不知道发生了转发） | 302 / 301 |
| **执行速度** | 快（没有额外网络开销） | 慢（多一次 HTTP 往返） |
| **适用场景** | 页面间传数据（查询 → 结果页） | 登录后跳转、防止表单重复提交（PRG 模式） |

### 5.4 PRG 模式（Post-Redirect-Get）

> 这是一个重要的工程实践，防止表单重复提交。

```java
// ❌ 错误模式：POST 后直接转发
// 用户刷新页面 → 浏览器提示"是否重新提交表单" → 体验差 + 可能重复插入数据
@WebServlet("/post-bad")
public class PostBadServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) {
        // 保存数据到数据库
        userService.save(user);
        // 直接转发到成功页
        req.getRequestDispatcher("/success.jsp").forward(req, resp);
        // ⚠️ 用户刷新此页面会重复提交！
    }
}

// ✅ 正确模式：PRG（Post → Redirect → Get）
@WebServlet("/post-good")
public class PostGoodServlet extends HttpServlet {
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {
        // 1. 保存数据到数据库
        userService.save(user);

        // 2. 把一次性的提示信息存到 Session
        req.getSession().setAttribute("flash", "注册成功！");

        // 3. 重定向到 GET 接口（浏览器地址栏变了）
        resp.sendRedirect(req.getContextPath() + "/success");
        // ✅ 用户刷新 → 只会再次 GET /success，不会重复 POST
    }
}

// GET 处理：返回成功页面
@WebServlet("/success")
public class SuccessServlet extends HttpServlet {
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) {
        String msg = (String) req.getSession().getAttribute("flash");
        req.getSession().removeAttribute("flash");  // 用一次就删
        resp.getWriter().write("<h1>" + msg + "</h1>");
    }
}
```

## 6. 完整实战：一个同时处理 GET 和 POST 的用户查询接口

```java
package com.example.servlet;

import javax.servlet.*;
import javax.servlet.http.*;
import javax.servlet.annotation.*;
import java.io.*;
import java.util.*;

/**
 * 用户查询接口 —— 同时处理 GET（查询单个）和 POST（批量查询）
 *
 * GET  /user?action=query&id=1         → 返回单个用户的 JSON
 * POST /user?action=query              → Body 中传 id 列表，返回多个用户
 */
@WebServlet("/user")
public class UserServlet extends HttpServlet {

    // 模拟数据库
    private static final Map<String, String> USER_DB = new LinkedHashMap<>();
    static {
        USER_DB.put("1", "张三");
        USER_DB.put("2", "李四");
        USER_DB.put("3", "王五");
    }

    // ====== 统一的请求处理入口 ======
    @Override
    protected void service(HttpServletRequest req, HttpServletResponse resp)
            throws ServletException, IOException {
        // 1. 统一字符编码
        req.setCharacterEncoding("UTF-8");
        resp.setContentType("application/json;charset=UTF-8");

        // 2. 根据 action 参数分发（简单路由）
        String action = req.getParameter("action");
        if ("query".equals(action)) {
            super.service(req, resp);  // 交给 doGet/doPost
        } else {
            resp.setStatus(400);
            resp.getWriter().write("{\"error\":\"未知操作\"}");
        }
    }

    // ====== 处理 GET：查询单个用户 ======
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {
        String id = req.getParameter("id");

        if (id == null || id.isEmpty()) {
            resp.setStatus(400);
            resp.getWriter().write("{\"error\":\"请提供 id 参数\"}");
            return;
        }

        String name = USER_DB.get(id);
        PrintWriter out = resp.getWriter();

        if (name != null) {
            // 拼接 JSON（生产环境请用 Jackson/Gson）
            out.write("{\"code\":200, \"data\":{\"id\":\"" + id +
                      "\",\"name\":\"" + name + "\"}}");
        } else {
            resp.setStatus(404);
            out.write("{\"code\":404, \"error\":\"用户不存在\"}");
        }
    }

    // ====== 处理 POST：批量查询 ======
    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp)
            throws IOException {
        // 读取 JSON Body（这里简化为读取纯文本逗号分隔的 id）
        StringBuilder body = new StringBuilder();
        BufferedReader reader = req.getReader();
        String line;
        while ((line = reader.readLine()) != null) {
            body.append(line);
        }
        // 示例 Body: "1,2,3"
        String[] ids = body.toString().split(",");

        StringBuilder json = new StringBuilder("{\"code\":200, \"data\":[");
        boolean first = true;
        for (String id : ids) {
            String name = USER_DB.get(id.trim());
            if (name != null) {
                if (!first) json.append(",");
                json.append("{\"id\":").append(id).append(",\"name\":\"")
                    .append(name).append("\"}");
                first = false;
            }
        }
        json.append("]}");
        resp.getWriter().write(json.toString());
    }
}
```

> **从这个例子可以看出**：
> - `service()` 方法可以做统一的预处理（编码、简单路由）
> - GET 和 POST 可以写在同一个 Servlet 中，通过 doGet/doPost 分开处理
> - Servlet 直接用 `resp.getWriter()` 输出 JSON 是可以的（但生产环境建议用 Jackson）

## 7. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ Servlet 是 Java Web 的门面 | 所有 HTTP 请求都由 Servlet 接住，Spring MVC 底层就是 DispatcherServlet |
| ✅ 生命周期三阶段 | `init()`（一次）→ `service()`（每次请求）→ `destroy()`（一次） |
| ✅ **Servlet 不是线程安全的** | 一个实例被所有请求线程共享，成员变量有线程安全问题 |
| ✅ `req.getParameter()` 对 GET 和 POST 通用 | 不需要手动解析 URL 或 Body |
| ✅ `req.setAttribute()` 仅同一次请求有效 | 转发时可以携带，重定向会丢失 |
| ✅ 转发是服务器内部跳转（1 次请求） | 重定向是浏览器重新发请求（2 次请求） |
| ✅ 输出中文用 `setContentType("...;charset=UTF-8")` | 不需要单独调 setCharacterEncoding |
| ✅ POST 后必须重定向（PRG 模式） | 防止刷新时重复提交表单 |
