# 11.2 消息序列化：用 Jackson 替代默认 JDK 序列化

> **学习目标**
> - 理解为什么默认序列化会在管理后台看到"乱码"
> - 会用 Jackson2JsonMessageConverter 一行配置解决
> - 知道生产者和消费者的转换器必须一致
> - 避开类型头（__TypeId__）带来的常见坑

---

## 1. 白话理解：消息在 MQ 里长什么样？

你发的是 Java 对象，但 MQ 只能存**字节**。所以发送前要把对象"打包"成字节，接收后再"拆包"还原——这个动作叫**序列化 / 反序列化**。

问题在于：**用哪种打包方式？**

| 方式 | 打包结果 | 人能看懂吗 |
|------|---------|-----------|
| JDK 序列化（默认） | Java 私有二进制格式 | ❌ 管理后台里是一堆乱码/十六进制 |
| JSON 序列化（Jackson） | `{"orderId":"1001",...}` | ✅ 一眼看懂 |

> **默认的坑**：Spring AMQP 对非 String 对象默认走 JDK 序列化。你打开第 10 章的 Queues 页面点开消息，看到的是 `rO0ABXNy...` 这类乱码——**排查问题极其痛苦**，而且别的语言（Python/Go）根本读不了。

---

## 2. 解决：注册一个 Jackson 转换器

### 白话理解

告诉 Spring："以后所有消息，都用 JSON 打包。"只需要在配置类里加一个 Bean：

```java
@Configuration
public class RabbitConfig {

    @Bean
    public MessageConverter messageConverter() {
        return new Jackson2JsonMessageConverter();
    }
}
```

> **为什么一个 Bean 就够了？** Bootstrap 的自动配置检测到容器里有 `MessageConverter`，会自动把它装到 `RabbitTemplate`（发送）和监听容器工厂（接收）上——两边统一用 JSON。这就是 08.1 说的"自动配置 + 你配了它就用你的"。

### 效果对比

**配置前**（管理后台 Payload 里）：

```
rO0ABXNyABFqYXZhLnV0aWwuSGFzaE1hcAAAAAAAAAAB...
```

**配置后**：

```json
{"orderId":"1001","username":"tom"}
```

> 排查问题时能直接看到业务内容——**这一条配置值得养成习惯**。

---

## 3. 发送和接收必须用同一种转换器

### 白话理解

序列化和反序列化是**一对锁和钥匙**：发送方用 JSON 打包，接收方也必须用 JSON 拆包，否则拆不开。

| 发送方 | 接收方 | 结果 |
|--------|--------|------|
| JSON | JSON | ✅ 正常 |
| JDK | JDK | ✅ 正常（但乱码，不推荐） |
| JSON | JDK | ❌ 报转换异常 / 乱码 |
| JDK | JSON | ❌ 报转换异常 |

> 同一个项目里两边共用同一个 Bean，天然一致。**跨项目/跨语言时**，要约定好都用 JSON——这也是 JSON 成为 MQ 消息事实标准的原因。

---

## 4. 两个常见坑

### 坑一：类型头 `__TypeId__`

`Jackson2JsonMessageConverter` 发送时会悄悄加一个消息头 `__TypeId__`，记录**发送方类的全限定名**（如 `com.demo.dto.OrderMessage`）。接收方靠它把 JSON 还原成对象。

- 同项目收发：没问题
- **不同项目**：如果接收方没有同名同包的类，会报 `ClassNotFoundException` 或转换失败

**解决思路**（了解即可）：接收方用 `Map`/`String` 接收，或配置 `DefaultJackson2JavaTypeMapper` 做类名映射。当前阶段保持**收发在同一个项目**就不会遇到。

### 坑二：时间类型

`LocalDateTime` 等 Java 8 时间类型，Jackson 默认不认识，可能报错。**初学阶段最简单的做法**：DTO 里的时间字段先用 `String`，等后面需要再配 `JavaTimeModule`。

---

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 默认 JDK 序列化是二进制 | 后台看到乱码，跨语言不可读 |
| ✅ 一个 Bean 换 Jackson | `new Jackson2JsonMessageConverter()` |
| ✅ Boot 自动装配 | 配了 MessageConverter 就自动用到收发两端 |
| ✅ 收发转换器必须一致 | 不一致就拆包失败 |
| ✅ `__TypeId__` 头 | 同项目无感，跨项目要注意 |
| ✅ 时间字段先 String | 避免 LocalDateTime 转换报错 |
