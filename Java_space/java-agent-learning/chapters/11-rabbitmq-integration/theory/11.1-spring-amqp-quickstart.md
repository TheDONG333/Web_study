# 11.1 Spring AMQP 快速入门：代码收发消息

> **学习目标**
> - 会引入 spring-boot-starter-amqp 并完成 yml 连接配置
> - 会在 Spring 里声明交换机、队列、绑定（对比第 10 章的手动创建）
> - 会用 RabbitTemplate 发消息、用 @RabbitListener 收消息
> - 理解"自动装配"在这套流程里帮了什么忙

---

## 1. 白话理解：从"手点控制台"到"代码收发"

第 10 章你在管理后台里手动建交换机、建队列、发消息——那是**理解模型**。真实项目当然不可能靠人点，要让代码自动干：

- 发送方：程序里调用一个方法，消息就进 MQ → **RabbitTemplate**
- 接收方：消息一到，程序里某个方法自动被触发 → **@RabbitListener**

Spring 提供的这套封装叫 **Spring AMQP**，Boot 再包一层成 `spring-boot-starter-amqp`。它做的事和 08.1 一样：**把连接、通道、序列化这些样板代码自动配好**，你只管写业务。

> **一句话**：第 10 章学"MQ 有什么"，这一章学"Java 怎么用"。

---

## 2. 引入依赖 + 基础配置

### 2.1 加依赖

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-amqp</artifactId>
</dependency>
```

> 不需要写版本号——Spring Boot 的 parent 统一管理（回忆 08.2：starter 全家桶的意义）。

### 2.2 yml 配置：地址、端口、vhost、账号密码

```yaml
spring:
  rabbitmq:
    host: localhost          # MQ 所在机器
    port: 5672               # AMQP 协议端口（不是 15672！）
    virtual-host: /          # 虚拟主机，默认 /
    username: admin          # 第 10 章 docker run 时设的
    password: admin123
```

| 配置项 | 对应第 10 章的概念 | 常见错误 |
|--------|-------------------|---------|
| `host` | MQ 服务器地址 | 写了 `http://` 前缀（不要写协议） |
| `port` | **5672** | 写成 15672（那是管理后台网页端口） |
| `virtual-host` | vhost 隔离 | 多环境/多项目时容易忘 |
| `username/password` | 账号密码 | 还用 guest，或密码不是 run 时设的 |

> **最容易错的一条**：程序连的是 **5672**，浏览器看后台才用 **15672**。两个端口别混。

## 3. 声明交换机、队列、绑定（代码版"建基础设施"）

### 白话理解

第 10 章你在后台点鼠标建了交换机、队列、绑定。Spring 里改成**启动时自动声明**：写几个 `@Bean`，应用一启动就去 MQ 上创建（已存在则跳过）。

```java
@Configuration
public class RabbitConfig {

    // ① 交换机：直连型
    @Bean
    public DirectExchange orderExchange() {
        return new DirectExchange("ex.order");
    }

    // ② 队列：true = 持久化
    @Bean
    public Queue orderQueue() {
        return new Queue("q.order.notify", true);
    }

    // ③ 绑定：交换机 ──(order.create)──▶ 队列
    @Bean
    public Binding orderBinding() {
        return BindingBuilder.bind(orderQueue())
                .to(orderExchange())
                .with("order.create");
    }
}
```

> **好处**：新环境部署时不用再去后台手动点一遍——**基础设施即代码**。启动应用，MQ 上该有的东西自动出现。

## 4. RabbitTemplate：发送消息

### 白话理解

`RabbitTemplate` 就是 10.2 里的"**生产者**"在 Spring 里的化身。注入它，调 `convertAndSend`，消息就出发了。

```java
@Service
public class OrderService {

    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void createOrder(String orderId, String username) {
        // 参数：交换机名、路由键、消息内容
        rabbitTemplate.convertAndSend("ex.order", "order.create",
                Map.of("orderId", orderId, "username", username));

        System.out.println("订单已创建，通知消息已发出: " + orderId);
    }
}
```

`convertAndSend` 做两件事：

```
① convert：把你的对象转成消息体（怎么转由"消息转换器"决定 → 11.2 详讲）
② send：发给指定交换机 + 路由键（走第 10 章的模型）
```

> **对照记忆**：`convertAndSend(交换机, 路由键, 内容)` 三个参数，正是 10.2 邮局模型里的"分拣中心、地址、信"。

## 5. @RabbitListener：收到消息自动执行

### 白话理解

`@RabbitListener` 是"**消费者**"的懒人写法：你在方法上标一个队列名，Spring 就会派一个后台线程**一直盯着这个队列**，有消息就调用你的方法。

```java
@Component
public class OrderNotifyListener {

    @RabbitListener(queues = "q.order.notify")
    public void handleOrderCreated(Map<String, Object> message) {
        // 方法参数就是消息体（已自动转换好）
        System.out.println("【收到订单通知】" + message);

        // 真实业务：发短信、发邮件、加积分……
    }
}
```

几个要点：

| 要点 | 说明 |
|------|------|
| 不需要手动写循环 | Spring 在后台持续监听 |
| 方法参数即消息体 | 自动反序列化（11.2 配好 Jackson 才不乱码） |
| 方法不能是 private | Spring 要能代理调用 |
| 一个队列可以有多个消费者 | 消息会被分摊，不会重复消费 |
| 消费失败会怎样 | 默认会重新入队，反复失败要配重试/死信（后续再学） |

> **和 Controller 的区别**：Controller 是"用户请求来了才执行"，Listener 是"队列里有消息就执行"——一个由 HTTP 触发，一个由 MQ 触发。

## 6. 最小可运行链路

把上面拼起来，一条消息的代码旅程：

```
用户调接口 ──▶ OrderService.createOrder()
                    │ rabbitTemplate.convertAndSend("ex.order","order.create",msg)
                    ▼
             交换机 ex.order ──(绑定 order.create)──▶ 队列 q.order.notify
                                                          │
                                                          ▼ 自动触发
                                            OrderNotifyListener.handleOrderCreated()
                                                          │
                                                          ▼
                                                    发短信 / 发邮件
```

> 注意：**发送和消费是异步的**。接口返回"下单成功"时，短信可能还没发出去——这正是 10.1 讲的"异步"在代码里的样子。

## 7. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ starter-amqp | 一个依赖搞定连接、模板、监听容器 |
| ✅ yml 连 5672 | 15672 是网页后台，别混 |
| ✅ @Bean 声明基础设施 | 交换机/队列/绑定随应用启动自动创建 |
| ✅ RabbitTemplate | `convertAndSend(交换机, 路由键, 内容)` |
| ✅ @RabbitListener | 标在方法上，队列有消息自动执行 |
| ✅ 异步本质 | 发送方不等消费方，接口先返回 |
