# 10.2 RabbitMQ 核心模型：六个角色与一条消息的旅程

> **学习目标**
> - 记住 RabbitMQ 的六个核心角色：生产者、消费者、交换机、队列、路由键、绑定
> - 能说清一条消息从产生到被消费的完整路径
> - 理解最重要的一条规则：**生产者不直接发队列**
> - 看懂几个协作概念：Connection / Channel / vhost / ack

---

## 1. 白话理解：整个 RabbitMQ 就是一座邮局

| 邮局里的东西 | RabbitMQ 里的角色 | 白话 |
|-------------|------------------|------|
| 寄信人 | **生产者（Producer）** | 写好消息交给邮局 |
| 分拣中心 | **交换机（Exchange）** | 按规则决定信投到哪个邮箱 |
| 信封上的地址 | **路由键（Routing Key）** | 分拣依据 |
| 分拣规则 | **绑定（Binding）** | 交换机与邮箱之间的对应关系 |
| 邮箱 | **队列（Queue）** | 消息暂时存放的地方 |
| 收信人 | **消费者（Consumer）** | 从邮箱取信处理 |

```
生产者 ──消息(带路由键)──▶ 交换机 ──按绑定规则──▶ 队列 ──▶ 消费者
```

> 记住这张图，RabbitMQ 你就懂了一大半。

---

## 2. 六个核心角色逐个说清

### ① 生产者（Producer）

发消息的一方。它**只做一件事：把消息交给交换机**，不关心发给谁、谁在收。

### ② 消费者（Consumer）

收消息的一方。它**只做一件事：从队列里取消息处理**，不关心消息是谁发的。

### ③ 交换机（Exchange）

**分拣中心**。它收到消息后，根据**交换机类型 + 路由键 + 绑定关系**，决定把消息投递到哪些队列。

> ⚠️ 交换机**自己不存消息**！它只负责"转发"。没有队列接收的消息会**直接丢失**。

### ④ 队列（Queue）

**真正存消息的地方**。消息在队列里排队，等消费者来取。队列是 RabbitMQ 里唯一会持久保存消息的地方（配合持久化设置）。

### ⑤ 路由键（Routing Key）

生产者发消息时附带的一个字符串（如 `order.create`）。它相当于**信封上的地址**，交换机靠它决定投递方向。

### ⑥ 绑定（Binding）

**交换机与队列之间的连线**，连线上可以写规则（如"路由键等于 order.create 的消息才投给我"）。

```
交换机 ──[绑定: order.create]──▶ 队列A
       ──[绑定: order.pay]────▶ 队列B
```

---

## 3. 一条消息的完整旅程

```
① 生产者把消息发给交换机，消息带路由键 "order.create"
                    │
                    ▼
② 交换机查看自己的绑定关系
   ├─ 绑定1: 路由键 order.create → 队列 q.order.create  ✅ 匹配
   └─ 绑定2: 路由键 order.pay    → 队列 q.order.pay     ❌ 不匹配
                    │
                    ▼
③ 消息被投进 q.order.create 队列，排队等待
                    │
                    ▼
④ 消费者从队列取出消息，处理（扣库存、发通知…）
```

> **关键点**：消息可能被投递到**一个队列**（Direct 精准匹配），也可能被投递到**多个队列**（Fanout/Topic 匹配多条绑定）——这由交换机类型决定（10.3、10.4 详讲）。

---

## 4. 最重要的一条规则：生产者不直接发队列

初学者最常犯的错：以为"生产者 → 队列 → 消费者"。

**正确的是**：生产者**永远发给交换机**，交换机再决定进哪个队列。

```
❌ 生产者 ──▶ 队列 ──▶ 消费者
✅ 生产者 ──▶ 交换机 ──▶ 队列 ──▶ 消费者
```

**例外（了解即可）**：RabbitMQ 有一个**默认交换机**（名字是空字符串 `""`），它的规则是"路由键等于队列名"。所以有时看起来像直接发队列，其实还是走了默认交换机。

> 理解这一点，你就不会问出"为什么我建了队列却收不到消息"——因为消息发到了交换机，但**没有绑定到你的队列**。

## 5. 四个协作概念（看懂即可，不深挖）

| 概念 | 白话 | 为什么需要 |
|------|------|-----------|
| **Connection** | 客户端到 RabbitMQ 的一条 TCP 连接 | 建连接开销大，别频繁建 |
| **Channel** | 连接里的"虚拟通道"，一个连接可开多个 | 生产者/消费者实际都用 Channel 通信，复用连接 |
| **vhost** | 虚拟主机，逻辑隔离 | 不同项目/团队互不干扰（默认 vhost 是 `/`） |
| **ack** | 消费者处理完后告诉 MQ"这条我处理完了" | 消费者中途挂了，消息可以重新投递，不丢 |

> 这些概念在管理后台里都能直接看到（Connections / Channels / Admin 标签页），实操时会带你认一遍。

---

## 6. 四种交换机预览

| 交换机类型 | 匹配规则 | 使用频率 |
|-----------|---------|---------|
| **Direct** | 路由键**完全相等**才投递 | ⭐⭐⭐ 最基础 |
| **Fanout** | 忽略路由键，**广播给所有绑定队列** | ⭐⭐⭐ 发布订阅 |
| **Topic** | 路由键**通配符匹配** | ⭐⭐⭐ 最灵活、最常用 |
| Headers | 按消息头匹配（不常用） | ⭐ 了解即可 |

---

## 7. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 六角色 | 生产者、消费者、交换机、队列、路由键、绑定 |
| ✅ 交换机不存消息 | 只负责分拣转发，没队列接就丢 |
| ✅ 生产者不直接发队列 | 永远发交换机，由交换机决定去向 |
| ✅ 队列是唯一存消息的地方 | 消费者从队列取 |
| ✅ Connection vs Channel | 一条连接开多个通道复用 |
| ✅ 四种交换机 | Direct / Fanout / Topic 必会，Headers 了解 |
