# 10.3 Direct 与 Fanout 交换机：精准投递 vs 广播

> **学习目标**
> - 掌握 Direct 交换机：路由键完全匹配才投递
> - 掌握 Fanout 交换机：忽略路由键，广播给所有绑定队列
> - 能根据业务场景在两者之间做选择
> - 避开两个高频误区（路由键没匹配 / 绑定漏了）

---

## 1. Direct 交换机：地址写对才送到

### 白话理解

Direct 是最"讲规矩"的分拣员：**路由键必须和绑定规则一模一样**，才把消息投给那个队列。多一个字、少一个字都不行。

```
交换机 ex.order (direct)
├── 绑定: order.create ──▶ 队列 q.order.create
└── 绑定: order.pay    ──▶ 队列 q.order.pay

发消息 routingKey = "order.create"  →  只进 q.order.create
发消息 routingKey = "order.pay"     →  只进 q.order.pay
发消息 routingKey = "order.cancel"  →  ❌ 没有匹配，消息丢失
```

### 典型业务场景

| 场景 | 路由键设计 |
|------|-----------|
| 订单事件分流 | `order.create` → 创建队列；`order.pay` → 支付队列 |
| 短信按类型分流 | `sms.code` → 验证码队列；`sms.marketing` → 营销短信队列 |
| 日志分级 | `log.error` → 告警队列；`log.info` → 普通日志队列 |

### 两个必须知道的细节

**① 同一个路由键可以绑定多个队列**——消息会**复制一份发给每个匹配的队列**，不是"谁抢到算谁的"。

```
绑定: order.create ──▶ q.order.create
绑定: order.create ──▶ q.audit        ← 再绑一个审计队列

发 order.create → q.order.create 和 q.audit 都收到
```

**② 没有队列匹配时，消息直接丢弃**（除非开启 mandatory 等特殊配置）。这是"我发了消息但没人收到"最常见的原因——**先检查绑定，再检查路由键**。

---

## 2. Fanout 交换机：大喇叭广播

### 白话理解

Fanout 根本**不看路由键**（写了也没用），它把消息**复制给所有和它绑定的队列**。像一个广播电台：只要你的收音机调到了这个频道，就能收到，不管你"想听什么"。

```
交换机 ex.notify (fanout)
├── 绑定 ──▶ 队列 q.inventory
├── 绑定 ──▶ 队列 q.points
└── 绑定 ──▶ 队列 q.email

发任意消息（路由键随便写）→ 3 个队列全部收到
```

### 典型业务场景

| 场景 | 说明 |
|------|------|
| 发布订阅 | 一个事件，所有订阅方都要知道（如"系统公告"） |
| 订单支付成功通知 | 库存、积分、邮件、短信各自处理，互不影响 |
| 配置变更广播 | 所有节点收到通知后刷新本地缓存 |

> **Fanout 的价值**：新增一个下游（比如"加积分服务"），只需新建队列绑定到这个交换机，**生产者和现有消费者都不用改**——这正是 10.1 讲的"解耦"最纯粹的形态。

---

## 3. Direct vs Fanout：怎么选

| | Direct | Fanout |
|---|--------|--------|
| 匹配依据 | 路由键**完全相等** | 不匹配，**全发** |
| 路由键 | 必须写对 | 写了也忽略 |
| 消息去向 | 1 个或多个精确匹配的队列 | 所有绑定队列 |
| 适合 | **不同消息给不同处理方** | **同一个消息通知所有处理方** |
| 例子 | `order.create` 给订单队列，`order.pay` 给支付队列 | 支付成功 → 库存/积分/邮件都收到 |

> **选择口诀**：**"各干各的"用 Direct，"人人有份"用 Fanout。** 两者都不够用时（比如既要按前缀分流又要按模式匹配），上 Topic（下一节）。

---

## 4. 两个高频误区

### 误区一：消息发了，队列是空的

按顺序自查：

```
① 交换机名写对了吗？（同名交换机可能有多个类型）
② 路由键和绑定的路由键完全一致吗？（大小写、点号、空格都算）
③ 队列真的绑定到这个交换机了吗？（绑定是"连线"，建了队列≠绑定了）
④ 消息是不是发到了别的 vhost？（vhost 隔离，默认都是 /）
```

### 误区二：以为 Fanout 也需要正确的路由键

Fanout 忽略路由键，随便写都能广播。但**习惯上还是写一个有意义的值**（如 `order.paid`），方便日后排查和切换交换机类型。

---

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ Direct | 路由键完全相等才投递，适合按类型分流 |
| ✅ Fanout | 忽略路由键，广播给所有绑定队列 |
| ✅ 同键多队列 | Direct 匹配到几个队列就复制几份 |
| ✅ 无匹配即丢弃 | 收不到消息先查绑定和路由键 |
| ✅ 新增下游 | Fanout 加队列+绑定即可，上游不动 |
| ✅ 选择 | 各干各的用 Direct，人人有份用 Fanout |
