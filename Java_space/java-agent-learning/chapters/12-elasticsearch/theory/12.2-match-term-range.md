# 12.2 三种基础查询：match / term / range

> **学习目标**
> - 掌握 match：全文关键词搜索（会分词、算相关度）
> - 掌握 term：精确值匹配（不分词，必须配 keyword 字段）
> - 掌握 range：数值 / 日期范围查询
> - 能一眼判断某个字段该用哪种查询

---

## 1. match：全文关键词搜索

### 白话理解

`match` 是"**智能搜索**"：它会把你的关键词**先分词**，再和字段里的词比对，算相关度排序。

```json
GET /products/_search
{
  "query": {
    "match": { "title": "iPhone 15" }
  }
}
```

执行过程：

```
用户输入 "iPhone 15"
        │ 分词
        ▼
["iphone", "15"]
        │ 去倒排索引里找
        ▼
标题包含 iphone 或 15 的文档 → 按相关度打分排序
```

**关键点**：

| 要点 | 说明 |
|------|------|
| 会分词 | 关键词和字段内容都会被拆成词 |
| 默认 OR | 只要命中**部分词**就可能返回（可用 `"operator": "and"` 要求全部命中） |
| 算相关度 | `_score` 越高越靠前 |
| 用在 | **text 字段**（标题、内容） |

> **为什么搜"15 iPhone"也能搜到？** 因为分词后是两个词，顺序无关。这是 `LIKE '%15 iPhone%'` 永远做不到的。

### 中文分词的小提醒（了解）

ES 默认的 `standard` 分词器对中文是**按单字切**（"手机"→"手"+"机"），搜索效果一般。生产中文项目通常安装 **IK 分词器**。本阶段不展开——实操用英文型号词（iPhone / Pro）演示，效果最直观。

## 2. term：精确值匹配

### 白话理解

`term` 是"**死板匹配**"：**不分词**，拿你给的值和字段里存的**完整值**逐字比对，完全相等才算命中。

```json
GET /products/_search
{
  "query": {
    "term": { "category": "手机" }
  }
}
```

`category` 是 `keyword` 类型，存的就是完整的"手机"三个字，完全相等 → 命中。

### 最容易踩的坑：term 查 text 字段查不到

```
文档标题 "Apple iPhone 15 Pro 手机"
  │ 写入时 text 字段被分词
  ▼
["apple", "iphone", "15", "pro", "手", "机"]
```

此时执行 `{"term": {"title": "iPhone"}}`：

- term **不分词**，拿整个 `"iPhone"` 去比对
- 但索引里存的是小写 `"iphone"`（standard 分词器会转小写）
- 而且 term 不会把 `"iPhone"` 拆开或转小写
- → **查不到！**

> **结论**：`term` 只用于 `keyword` 字段（分类、品牌、状态码、标签），不要用来查 `text` 字段。查标题用 `match`。

### match vs term 对比（必记）

| | match | term |
|---|-------|------|
| 是否分词 | ✅ 会 | ❌ 不会 |
| 匹配方式 | 词级别匹配 | 完整值精确相等 |
| 算分 | ✅ 相关度 | ✅（但通常配 filter 不用分） |
| 适用字段 | text | keyword |
| 典型场景 | 搜标题/内容 | 分类、品牌、状态 |

---

## 3. range：范围查询

### 白话理解

数值、日期比大小——价格 5000~8000、上架时间最近 30 天，都用 range。

```json
GET /products/_search
{
  "query": {
    "range": {
      "price": { "gte": 5000, "lte": 8000 }
    }
  }
}
```

| 参数 | 含义 | 白话 |
|------|------|------|
| `gte` | ≥ | 大于等于 |
| `gt` | > | 大于 |
| `lte` | ≤ | 小于等于 |
| `lt` | < | 小于 |

**日期范围**也能用（了解）：

```json
{ "range": { "createdAt": { "gte": "now-30d", "lte": "now" } } }
```

> **记忆**：`e` = equal（等于），所以 `gte` 是"大于**或等于**"。这个命名规则记一次就够。

---

## 4. 三种查询怎么选（一张表）

| 你想做什么 | 用什么 | 例子 |
|-----------|--------|------|
| 按关键词搜标题/内容 | **match** | 搜"iPhone 15" |
| 按分类/品牌/状态精确过滤 | **term** | 分类 = 手机 |
| 按价格/日期筛范围 | **range** | 价格 5000~8000 |
| 几个条件组合 | **bool**（下一节） | 关键词 + 价格 + 排除品牌 |

> **选择口诀**：**关键词用 match，精确值用 term，比大小用 range。**

---

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ match 会分词 | 词级匹配 + 相关度排序，用于 text |
| ✅ term 不分词 | 完整值精确相等，用于 keyword |
| ✅ term 查 text 必失败 | 索引里存的是拆开的词，不是原句 |
| ✅ range 比大小 | gte/gt/lte/lt，数值和日期都行 |
| ✅ 中文分词 | 默认按单字切，生产用 IK（了解） |
