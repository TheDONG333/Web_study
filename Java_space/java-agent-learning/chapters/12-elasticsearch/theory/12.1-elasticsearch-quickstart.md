# 12.1 Elasticsearch 入门：全文搜索为什么不用 MySQL

> **学习目标**
> - 理解 ES 解决什么问题（MySQL `LIKE` 为什么不够用）
> - 记住三个核心概念：索引 index、文档 document、字段 field
> - 会在 ES 里建索引、写数据（实操的数据准备）
> - 知道 ES 用 REST 接口操作（不需要 Java 代码也能玩）

---

## 1. 白话理解：MySQL 的 LIKE 为什么搜不好

商品表有 100 万条数据，用户搜"iPhone 15"：

```sql
SELECT * FROM product WHERE title LIKE '%iPhone 15%';
```

两个致命问题：

**① 慢**：`%...%` 前后都有通配符，索引失效，只能**逐行扫描** 100 万条字符串。

**② 搜不准**：用户搜"15 iPhone"（词序反了）就搜不到；搜"苹果手机"也搜不到标题写"Apple iPhone"的商品——**它只会死板地匹配字符，不理解"词"**。

ES 的思路完全不同：它提前把标题**拆成一个个词**，建一张"词 → 文档"的目录表：

```
词 "iphone" → 文档 1、文档 2、文档 5
词 "15"     → 文档 1、文档 3
词 "手机"    → 文档 1、文档 2、文档 3、文档 4
```

搜"iPhone 15"时，直接查目录，**毫秒级**找到同时包含这些词的文档，还能按**相关度**排序。这张目录叫**倒排索引**——像书后面的"关键词索引页"，而不是一页页翻书。

> **一句话**：MySQL 适合"按条件查记录"，ES 适合"**按关键词找内容**"。两者是互补关系，不是替代关系。

## 2. 三个核心概念（对照 MySQL 记）

| ES 概念 | 对照 MySQL | 白话 |
|---------|-----------|------|
| **索引（index）** | 表（table） | 一类数据的集合，如 `products` |
| **文档（document）** | 行（row） | 一条 JSON 数据 |
| **字段（field）** | 列（column） | JSON 里的一个属性，如 `title`、`price` |

```
索引 products
├── 文档 1: {"title":"Apple iPhone 15 Pro 手机", "price":7999, "category":"手机"}
├── 文档 2: {"title":"Apple iPhone 14 手机", "price":4999, "category":"手机"}
└── 文档 3: {"title":"机械键盘 87键 青轴", "price":299, "category":"外设"}
```

> ⚠️ **术语坑**：ES 里的"索引"是**名词**（一类数据），不是数据库里"建索引"那个**动词**。别混。

## 3. ES 用 REST 接口操作：一条 URL + 一段 JSON

ES 自带 HTTP 服务，所有操作都是发请求：

```
GET  /products/_search        查询
POST /products/_doc/1         写入 id=1 的文档
PUT  /products                创建索引
DELETE /products              删除索引
```

**两种调试工具**（实操详细讲）：

| 工具 | 地址 | 优点 |
|------|------|------|
| **Kibana Dev Tools**（推荐） | `http://localhost:5601` → Dev Tools | 有补全、格式化、历史记录 |
| Postman / curl | `http://localhost:9200` | 不用多起一个容器 |

> 本阶段**不写 Java 代码**——先把查询语法练熟。后面做项目时再用 Java 客户端，语法是一样的。

## 4. 建索引：先定义字段类型

### 白话理解

建索引时可以顺便声明每个字段**是什么类型、怎么被搜索**。不声明也能写数据（ES 会自动猜），但**猜错很难改**，所以建议显式定义。

```json
PUT /products
{
  "mappings": {
    "properties": {
      "title":     { "type": "text" },
      "category":  { "type": "keyword" },
      "brand":     { "type": "keyword" },
      "price":     { "type": "double" },
      "stock":     { "type": "integer" },
      "createdAt": { "type": "date" }
    }
  }
}
```

**最重要的区分：`text` vs `keyword`**（下一节 `term` 查询全靠它）：

| 类型 | 是否分词 | 适合 | 例子 |
|------|---------|------|------|
| `text` | ✅ 会拆成词 | 全文搜索（match） | 商品标题、文章内容 |
| `keyword` | ❌ 整串保存 | 精确匹配、分类、标签 | 分类、品牌、状态 |

> `title` 用 `text`（要关键词搜索），`category` / `brand` 用 `keyword`（要精确过滤）——这个设计在实操里会用到。

## 5. 写数据：一条文档一段 JSON

```json
POST /products/_doc/1
{
  "title": "Apple iPhone 15 Pro 手机",
  "category": "手机",
  "brand": "Apple",
  "price": 7999,
  "stock": 100,
  "createdAt": "2026-09-01"
}
```

返回结果里重点看两个字段：

| 字段 | 值 | 含义 |
|------|-----|------|
| `result` | `created` | 新建成功（重复发同一 id 会变成 `updated`） |
| `_id` | `1` | 文档 id，你指定的 |

> **文档 id** 不指定也行，ES 会自动生成。指定 id 的好处是**重复写入会覆盖**（幂等），适合商品这种有唯一编号的数据。

## 6. 第一个搜索（先看一眼效果）

```json
GET /products/_search
{
  "query": {
    "match": { "title": "iPhone" }
  }
}
```

结果里的 `hits.hits` 就是命中的文档，每条带一个 `_score`（相关度分数，越高越相关）。

## 7. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ ES 解决"关键词搜索" | 倒排索引 + 相关度排序，不是替代 MySQL |
| ✅ 三概念 | index≈表、document≈行、field≈列 |
| ✅ REST 操作 | 一条 URL + 一段 JSON，Kibana/Postman 都能调 |
| ✅ text vs keyword | text 分词做全文搜，keyword 整串做精确匹配 |
| ✅ 显式 mapping | 字段类型一开始就定好，别靠 ES 猜 |
