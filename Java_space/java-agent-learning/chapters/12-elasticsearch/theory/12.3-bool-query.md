# 12.3 bool 组合查询：must / filter / must_not

> **学习目标**
> - 会用 bool 把多个条件组合成一个查询
> - 分清 must、filter、must_not 三者的区别
> - 理解 filter "不打分"为什么更快，知道什么时候该用它
> - 了解 should（可选加分项）

---

## 1. 白话理解：bool 就是"条件与或非"

真实搜索很少只有一个条件。用户搜索"Pro"，往往还要：

- 价格在 5000~8000 之间
- 排除苹果品牌
- 只搜手机分类

一个 `bool` 查询把这些条件**装在一起**，四个子句各司其职：

```
bool
├── must     必须匹配（算分）    相当于 AND
├── filter   必须匹配（不算分）  相当于 AND（更快的过滤）
├── must_not 必须不匹配          相当于 NOT
└── should   应该匹配（加分）    相当于 OR（了解）
```

> **一句话**：**must 管"搜得准"，filter 管"筛得快"，must_not 管"排除掉"。**

---

## 2. 三个必学子句

### must：必须匹配，参与打分

```json
{
  "query": {
    "bool": {
      "must": [
        { "match": { "title": "Pro" } }
      ]
    }
  }
}
```

- 条件必须满足（AND）
- **参与相关度计算**——所以放"关键词搜索"这类需要排序的条件

### filter：必须匹配，但不打分

```json
{
  "query": {
    "bool": {
      "filter": [
        { "range": { "price": { "gte": 5000, "lte": 8000 } } }
      ]
    }
  }
}
```

- 条件必须满足（AND）
- **不计算相关度分数**（`_score` 不受它影响）
- 结果可以被 ES **缓存**，重复查询更快
- 适合：价格区间、分类、库存、状态、时间范围等"**是/否**"型过滤

> **为什么 filter 更快？** 打分要做词频统计、向量计算等；filter 只判断"在不在范围内"，还能缓存结果。**不需要影响排序的条件，一律用 filter。**

### must_not：必须不匹配

```json
{
  "query": {
    "bool": {
      "must_not": [
        { "term": { "brand": "Apple" } }
      ]
    }
  }
}
```

- 条件必须不满足（NOT）
- 不参与打分
- 适合：排除下架商品、排除某品牌、排除自己

---

## 3. 完整组合：三个子句一起用

需求：搜索标题含 "Pro"、价格 5000~7000、排除 Apple 品牌的商品。

```json
GET /products/_search
{
  "query": {
    "bool": {
      "must": [
        { "match": { "title": "Pro" } }
      ],
      "filter": [
        { "range": { "price": { "gte": 5000, "lte": 7000 } } }
      ],
      "must_not": [
        { "term": { "brand": "Apple" } }
      ]
    }
  }
}
```

执行逻辑：

```
先用 filter 快速筛出价格区间内的文档（缓存友好）
        │
        ▼
再用 must 在这些文档里找标题含 Pro 的（算分排序）
        │
        ▼
最后 must_not 把 Apple 品牌的剔除
```

> **顺序不用你操心**，ES 会自动优化执行计划。你只要把条件放对子句。

---

## 4. should（了解即可）

`should` 表示"**满足了更好**"：不强制，但满足的文档分数更高。

```json
{
  "bool": {
    "must":   [ { "match": { "title": "手机" } } ],
    "should": [ { "term": { "brand": "华为" } } ]
  }
}
```

- 搜"手机"时，华为品牌的商品**排得更靠前**，但其他品牌也能出现
- 默认只要满足任意一个 should 就加分；可用 `minimum_should_match` 控制必须满足几个

> 本阶段知道"should 是加分项"即可，实际项目用到了再查。

---

## 5. 子句选择速查

| 条件性质 | 放哪个子句 | 例子 |
|---------|-----------|------|
| 关键词搜索，要影响排序 | **must** | 标题含 "Pro" |
| 范围/分类过滤，只关心是/否 | **filter** | 价格 5000~8000、分类=手机 |
| 排除某些结果 | **must_not** | 排除 Apple、排除下架 |
| 可选的偏好，影响排序 | should | 优先展示自营 |

> **性能习惯**：能放 filter 的别放 must——**filter 不打分、可缓存**，数据量大时差距明显。

---

## 6. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ must | 必须匹配 + 算分，用于关键词 |
| ✅ filter | 必须匹配 + 不算分 + 可缓存，用于范围/分类过滤 |
| ✅ must_not | 必须不匹配，用于排除 |
| ✅ should | 可选加分，了解即可 |
| ✅ 性能口诀 | 不影响排序的条件一律 filter |
