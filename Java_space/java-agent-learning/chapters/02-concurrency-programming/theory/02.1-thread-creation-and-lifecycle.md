# 02.1 线程的三种创建方式与生命周期

> **学习目标**
> 
> - 掌握 Java 中创建线程的三种方式及其适用场景
> - 理解线程的六大状态及状态流转机制
> - 能够分析多线程程序的执行路径

---

## 1. 概述

多线程是 Java 并发编程的基石。理解线程如何创建、运行、以及在不同状态间如何流转，是写出正确并发代码的第一步。本章从最基础的线程创建方式讲起，深入分析线程的生命周期模型。

---

## 2. 线程与进程的概念

| 概念     | 定义                   | 类比        |
| ------ | -------------------- | --------- |
| **进程** | 操作系统分配资源的最小单位        | 一家餐厅      |
| **线程** | CPU 调度的最小单位，进程内的执行路径 | 餐厅里的一个服务员 |

> 同一进程内的线程共享堆内存和方法区，但每个线程拥有独立的虚拟机栈和程序计数器。

## 3. 线程的三种创建方式

### 3.1 方式一：继承 Thread 类

```java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("线程执行中: " + Thread.currentThread().getName());
    }
}

// 使用
MyThread t = new MyThread();
t.start();  // 启动线程（注意：不是调用 run()）
```

**特点：**

- 直接继承 `Thread` 类，重写 `run()` 方法
- Java 是单继承，如果类已经继承了其他类就不能用此方式
- 调用 `start()` 启动线程，而不是直接调 `run()`（直接调 `run()` 只是普通方法调用）

### <mark>3.2 方式二：实现 Runnable 接口（优先使用）</mark>

```java
class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("线程执行中: " + Thread.currentThread().getName());
    }
}

// 使用
Thread t = new Thread(new MyTask());
t.start();

// Lambda 简化（推荐）
Thread t = new Thread(() -> System.out.println("线程执行中"));
t.start();
```

**特点：**

- 实现 `Runnable` 接口，不破坏类的继承体系
- 更适合多个线程共享同一任务的场景
- **推荐优先使用，比继承 Thread 更灵活**

### 3.3 方式三：实现 Callable 接口 + FutureTask

```java
class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        System.out.println("线程执行中: " + Thread.currentThread().getName());
        return 42;  // 有返回值
    }
}

// 使用
FutureTask<Integer> futureTask = new FutureTask<>(new MyCallable());
Thread t = new Thread(futureTask);
t.start();

// 获取返回值（会阻塞直到线程执行完毕）
Integer result = futureTask.get();
```

**特点：**

- 可以有**返回值**
- 可以**抛出异常**（Runnable 不行）
- 配合 `FutureTask` 获取异步执行结果
- 本质是 Runnable 的增强版（FutureTask 实现了 Runnable 接口）

### 3.4 三种方式的对比

| 对比维度  | Thread      | Runnable    | Callable    |
| ----- | ----------- | ----------- | ----------- |
| 继承/实现 | 继承 Thread   | 实现 Runnable | 实现 Callable |
| 返回值   | ❌ 无         | ❌ 无         | ✅ 有         |
| 抛异常   | ❌ 不可抛出受检异常  | ❌ 不可        | ✅ 可以        |
| 资源共享  | 不自然         | ✅ 自然        | ✅ 自然        |
| 推荐度   | ⭐ 不推荐（继承受限） | ⭐⭐⭐ 推荐      | ⭐⭐⭐ 有返回值时推荐 |

> 💡 **核心建议**：优先使用 Runnable/Callable，避免继承 Thread。Runnable 用 Lambda 更简洁，Callable 需要返回值时使用。

## 4. 线程生命周期（六大状态）

### 4.1 状态总览

Java 线程在任意时刻都处于以下六个状态之一（定义在 `Thread.State` 枚举中）：

```
                        ┌───────────────────────────┐
                        │         NEW               │
                        │  （新建，尚未 start()）      │
                        └───────────┬───────────────┘
                                    │ start()
                                    ▼
                        ┌───────────────────────────┐
                 ┌──────│      RUNNABLE              │──────┐
                 │      │  （就绪 + 运行中）           │       │
                 │      └───────────┬───────────────┘       │
                 │                  │                        │
      获取锁失败  ▼                  ▼ 等待条件          等待/超时
                 │                                        │
     ┌────────────────────┐  ┌──────────────────┐  ┌──────────────┐
     │      BLOCKED       │  │     WAITING      │  │ TIMED_WAITING │
     │ （阻塞，等待锁）      │  │（无限等待被唤醒）    │  │（超时等待）    │
     └────────────────────┘  └──────────────────┘  └──────────────┘
                 │                  │                       │
                 └──────获取到锁────┴──────被唤醒/超时──────┘
                                    │
                                    │ run() 执行完毕 / 异常
                                    ▼
                        ┌───────────────────────────┐
                        │       TERMINATED           │
                        │  （已终止）                  │
                        └───────────────────────────┘
```

### 4.2 状态详解

| 状态       | 枚举值             | 说明                       | 进入条件                                                     | 离开条件                                       |
| -------- | --------------- | ------------------------ | -------------------------------------------------------- | ------------------------------------------ |
| **新建**   | `NEW`           | 线程对象已创建，但尚未调用 `start()`  | `new Thread()`                                           | 调用 `start()`                               |
| **可运行**  | `RUNNABLE`      | 正在 JVM 中执行，或等待操作系统调度（就绪） | `start()` 后 / 从其他状态回来                                    | CPU 时间片用完 / 进入其他状态                         |
| **阻塞**   | `BLOCKED`       | 等待获取监视器锁（synchronized 块） | 试图进入 synchronized 块但锁被其他线程持有                             | 获取到锁                                       |
| **无限等待** | `WAITING`       | 等待另一个线程显式唤醒              | `Object.wait()` / `Thread.join()` / `LockSupport.park()` | 被 `notify()`/`notifyAll()` 唤醒 / `unpark()` |
| **超时等待** | `TIMED_WAITING` | 在指定时间后自动返回               | `Thread.sleep(ms)` / `wait(timeout)` / `join(timeout)`   | 超时 / 被唤醒                                   |
| **终止**   | `TERMINATED`    | 线程已执行完毕                  | `run()` 方法正常结束或抛出未捕获异常                                   | —                                          |

### 4.3 状态流转的代码演示

```java
public class ThreadLifecycleDemo {
    public static void main(String[] args) throws Exception {
        Thread t = new Thread(() -> {
            try {
                // RUNNABLE 状态
                System.out.println("状态2: " + Thread.currentThread().getState());

                // 进入 TIMED_WAITING
                Thread.sleep(100);

                // 模拟获取锁（演示 BLOCKED 需要配合另一个线程）
                synchronized (ThreadLifecycleDemo.class) {
                    Thread.sleep(50);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        // NEW 状态
        System.out.println("状态1 (NEW): " + t.getState());

        t.start();
        Thread.sleep(10);
        // RUNNABLE 状态
        System.out.println("状态3 (RUNNABLE): " + t.getState());

        t.join();
        // TERMINATED 状态
        System.out.println("状态4 (TERMINATED): " + t.getState());
    }
}
```

### 4.4 几个关键方法的作用

| 方法            | 作用                   | 释放锁？        | 所属类         |
| ------------- | -------------------- | ----------- | ----------- |
| `sleep(ms)`   | 线程休眠指定毫秒             | ❌ 不释放       | Thread 静态方法 |
| `yield()`     | 提示调度器让出 CPU（仍可能继续运行） | ❌ 不释放       | Thread 静态方法 |
| `join()`      | 等待调用 join 的线程结束      | —           | Thread 实例方法 |
| `wait()`      | 线程进入等待，释放锁           | ✅ 释放        | Object 方法   |
| `notify()`    | 唤醒一个等待该锁的线程          | ✅ 在同步块结束后释放 | Object 方法   |
| `interrupt()` | 设置中断标志，通知线程停止        | ❌           | Thread 实例方法 |

## 5. 关键要点总结

| 要点                                                                 | 说明                            |
| ------------------------------------------------------------------ | ----------------------------- |
| ✅ 创建线程优先用 Runnable/Callable                                        | **避免单继承限制**，Callable 支持返回值和异常 |
| ✅ start() 启动线程，run() 只是普通方法调用                                      | 误调 run() 不会创建新线程              |
| ✅ 六大状态：NEW → RUNNABLE → BLOCKED/WAITING/TIMED_WAITING → TERMINATED | 理解了状态机就理解了线程的行为               |
| ✅ sleep() 不释放锁，wait() 释放锁                                          | 面试高频易错点                       |
| ✅ interrupt() 是"通知协作"而非"强制终止"                                      | 线程需要自行检查中断状态                  |

### 三、详解 sleep () 不释放锁

#### 执行流程

1. 线程 A 拿到 `synchronized` 的锁，进入同步块；
2. 执行 `Thread.sleep(3000)`，线程进入 `TIMED_WAITING` 超时等待状态；
3. **锁依旧被线程 A 持有，不会交出去**；
4. 其他线程想进入同一个`synchronized`代码块，全部卡在 `BLOCKED` 阻塞排队；
5. 3 秒休眠结束，A 回到 RUNNABLE，继续持有锁执行剩余代码，执行完出同步块才释放锁。

#### 生活类比

卫生间（锁）被你占用，你在里面躺 3 分钟睡觉（sleep），门全程反锁，别人只能在门外干等，你睡醒开门别人才能进。

### 四、详解 wait () 释放锁

#### 执行流程

1. 线程 A 拿到锁，进入`synchronized`代码块；
2. 调用 `lock.wait()`，立刻做两件事：
   ① **主动释放当前持有的监视器锁**；
   ② 线程进入 WAITING 无限等待队列，原地等待唤醒；
3. 其他排队的线程可以抢到锁，执行同步代码；
4. 其他线程执行 `lock.notify()` / `notifyAll()` 唤醒 A；
5. A 被唤醒后**不能立刻执行**，需要重新竞争锁，抢到锁后才能继续往下跑。

#### 生活类比

你占用卫生间，临时有事要等朋友（wait），主动开门出来（释放锁），别人可以先进去；朋友来喊你（notify），你再重新排队抢卫生间。

#### 为什么 wait 必须在 synchronized 里？

wait 要释放锁，没有获取锁的前提下，根本不存在锁可以释放，JVM 直接抛`IllegalMonitorStateException`。sleep 无锁操作，随便写。
