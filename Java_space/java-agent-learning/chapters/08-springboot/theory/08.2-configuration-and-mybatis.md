> **学习目标**
> - 会读会写 yml（对比 application.properties 和 SSM 的 xml 配置）
> - 掌握常用配置项：端口、上下文路径、数据源、日志

> - 知道分层和事务在 Boot 里和 SSM 完全一样

## 1. application.yml：Boot 唯一要记的配置文件

### 白话理解

SSM 章配置散在三份 xml 里，Boot 把"配置"这件事收敛到一个文件：`resources/application.yml`。

yml 全称 YAML，可以理解为"**按层级缩进的 properties**"——用缩进表达归属关系，比 properties 的一长串点号好读：

```properties
# application.properties（SSM/Boot 也能用，等价的旧写法）
server.port=8080
spring.datasource.username=root
```

```yaml
# application.yml（推荐写法）
server:
  port: 8080            # 冒号后必须有一个空格
spring:
  datasource:           # 缩进=层级，两层空格
    username: root
```

**yml 语法只需要记 4 条**：

| 语法 | 规则 | 例子 |
|------|------|------|
| 键值 | `键: 值`，**冒号后必须有空格** | `port: 8080` |
| 层级 | 用缩进表达，同一层缩进对齐 | `spring:` 下面缩进两格写子项 |
| 注释 | `#` 开头 | `# 数据库配置` |
| 数组 | `- ` 开头 | 较少用，见 Thymeleaf 章即可 |

> **记不住就报错**：yml 写错（最常见：冒号后没空格、缩进不对齐）启动会直接报解析错误，报错里会给出**行号**，照着改就行。

### 常用配置（背下来这组就够了）

```yaml
server:
  port: 8080                # 端口（被占用就改，如 8081）
  servlet:
    context-path: /demo     # 访问前缀（可选，加了要访问 localhost:8080/demo/...）

spring:
  datasource:               # 数据源（SSM 的 DriverManagerDataSource 在这里）
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/agent_learn?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8
    username: root
    password: 123456

mybatis:
  mapper-locations: classpath:mapper/*.xml   # mapper.xml 放哪
  configuration:
    map-underscore-to-camel-case: true       # 下划线列名 → 驼峰属性

logging:
  level:
    com.demo.mapper: debug   # 打印 Mapper 的 SQL（排查问题神器）
```

### 在代码里读配置

```java
@RestController
public class HelloController {

    @Value("${server.port}")          // 从 yml 取值
    private Integer port;

    @GetMapping("/port")
    public String showPort() {
        return "当前端口: " + port;
    }
}
```

## 2. 整合 MyBatis：对照 SSM 看，每个配置都去哪了

### 白话理解

第五章你在 spring-context.xml 里手动配了四样东西：数据源、SqlSessionFactoryBean、MapperScannerConfigurer、事务管理器。第七章又配了一遍。Boot 里这四样**一个 starter + 几行 yml** 全部搞定：

| SSM 手写的配置（xml） | SpringBoot 对应 |
|----------------------|----------------|
| `DriverManagerDataSource` bean | yml 的 `spring.datasource.*` |
| `SqlSessionFactoryBean` bean | mybatis starter 自动配置 |
| `MapperScannerConfigurer` 扫描包 | 接口加 `@Mapper` 注解，或启动类加 `@MapperScan` |
| `DataSourceTransactionManager` bean | starter 自动配置，@Transactional 直接用 |

### Step 1：加依赖（Initializr 勾选 MyBatis + MySQL，或手动加）

```xml
<dependency>
    <groupId>org.mybatis.spring.boot</groupId>
    <artifactId>mybatis-spring-boot-starter</artifactId>
    <version>3.0.4</version>
</dependency>
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>8.4.0</version>
    <scope>runtime</scope>
</dependency>
```

> 注意：MyBatis 的 starter 不在 Boot 官方全家桶里（IDEA 勾选面板里有），所以要自己写版本号；mysql 驱动运行时才需要。

### Step 2：Mapper 接口——不需要 MapperScannerConfigurer 了

```java
package com.demo.mapper;

import com.demo.entity.User;
import java.util.List;

@Mapper                       // ① 告诉 Boot：这个接口要生成代理对象
public interface UserMapper {

    User findById(int id);

    List<User> findAll();
}
```

> 接口多了也可以换一种写法：启动类上加 `@MapperScan("com.demo.mapper")` 一次扫整个包，接口上就不用一个个写 @Mapper 了。二选一即可。

### Step 3：mapper.xml——和第四章写法一模一样

mapper.xml 放在 `resources/mapper/` 下（yml 的 `mapper-locations` 指向这里），namespace 写接口全类名，SQL 语法没有任何变化：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
    "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.demo.mapper.UserMapper">

    <select id="findAll" resultType="com.demo.entity.User">
        SELECT * FROM users
    </select>

</mapper>
```

> **记忆**：Boot 整合 MyBatis = 依赖 + yml 数据源 + @Mapper + xml，就这四步，比 SSM 少了三份配置文件。

## 3. 分层和事务：和 SSM 一模一样

### 白话理解

Boot 没有发明新分层，第七章的铁律原封不动：

```
com.demo
├── DemoApplication.java      ← 启动类
├── controller/               ← web 层：收参数、返回 Result
├── service/                  ← 业务层：业务逻辑 + @Transactional
├── mapper/                   ← 数据层：Mapper 接口
└── entity/                   ← 实体类
```

事务也一样：SSM 里你手动配了 `DataSourceTransactionManager` + `<tx:annotation-driven>`；Boot 的自动配置检测到数据源后**自动帮你配好**，所以你只需要像 Spring 章那样写：

```java
@Service
public class UserServiceImpl implements UserService {

    @Autowired
    private UserMapper userMapper;

    @Override
    @Transactional(rollbackFor = Exception.class)   // 用法和第五章完全一致
    public void register(User user) {
        userMapper.insert(user);
        // 中途抛异常 → 自动回滚
    }
}
```

> **理解锚点**：@Transactional 的传播、隔离级别、失效场景（05.3 学的）在 Boot 里 100% 适用。Boot 只是把"事务管理器从哪来"这件事自动化了。

## 4. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ yml 四语法 | 冒号后有空格、缩进表层级、# 注释、- 列表 |
| ✅ 数据源配置 | 全在 `spring.datasource.*`，报错就查这里 |
| ✅ 整合 MyBatis | 依赖 + yml + @Mapper + xml 四步，无 xml 配置 |
| ✅ mapper.xml 无变化 | namespace=接口全类名，SQL 语法同第四章 |
| ✅ 分层铁律不变 | Controller → Service → Mapper，和 SSM 完全一样 |
| ✅ 事务照旧 | @Transactional 直接用，自动配置已备好事务管理器 |
