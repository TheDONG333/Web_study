## 1. @ConfigurationProperties：整组配置"打包绑到对象"

### 白话理解

08.2 学了用 `@Value` 一条条取值：

```java
// ❌ 配置有 5 项就要写 5 个 @Value，字段一变改一堆
@Value("${file.upload-path}")   private String uploadPath;
@Value("${file.max-size}")      private Long maxSize;
```

@ConfigurationProperties 是**批量签约**：yml 里的一组配置（同一个 prefix 下）一次性绑到一个类的所有字段——像搬家时"整屋签约"而不是一间间单独谈。

```yaml
# application.yml 里自定义一组配置（前缀起名：项目名.用途）
file:
  upload-path: D:/uploads
  max-size: 10485760
```

```java
package com.demo.config;

import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.stereotype.Component;

@Component                                  // ① 交给 Spring 管理
@ConfigurationProperties(prefix = "file")   // ② 绑定 yml 里 file 开头的配置
public class FileProperties {
    private String uploadPath;   // 字段名和 yml 的 key 一一对应（驼峰对应连字符）
    private Long maxSize;
    // 必须要有 getter / setter（Boot 靠 setter 填值）
    public String getUploadPath() { return uploadPath; }
    public void setUploadPath(String uploadPath) { this.uploadPath = uploadPath; }
    public Long getMaxSize() { return maxSize; }
    public void setMaxSize(Long maxSize) { this.maxSize = maxSize; }
}
```

用的时候直接注入这个配置类：

```java
@RestController
public class FileController {
    @Autowired
    private FileProperties fileProperties;

    @GetMapping("/file/config")
    public String show() {
        return fileProperties.getUploadPath();   // 不再散落一堆 @Value
    }
}
```

> **小结**：配置少用 @Value；配置多了（自定义功能模块的参数）就用 @ConfigurationProperties 整理成一个类——这也是以后写"自定义 starter"时给用户暴露配置的标准姿势。

## 2. profile 多环境：同一套代码，换环境只换配置

### 白话理解

一个项目要跑在三个环境：本地开发（dev）、测试服务器（test）、生产（prod）。三个环境的差异几乎全在**配置**上：数据库地址、日志级别、端口。总不能每换一次环境改一次 application.yml 再改回来吧？

profile 就是"**多套配置 + 一个开关**"：

```
resources/
├── application.yml          ← 公共配置 + 环境开关
├── application-dev.yml      ← 开发环境：本地数据库
├── application-prod.yml     ← 生产环境：线上数据库（真实项目密码走密钥管理，不写明文）
```

```yaml
# application.yml（公共部分 + 激活哪个环境）
server:
  port: 8080
spring:
  profiles:
    active: dev        # ⚠️ 开关：dev / prod，改这里就能换环境
```

```yaml
# application-dev.yml（只写和 dev 相关的差异项）
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/agent_learn
    username: root
    password: 123456
logging:
  level:
    com.demo.mapper: debug      # 开发时打印 SQL
```

```yaml
# application-prod.yml（prod 的差异项；公共配置自动合并）
spring:
  datasource:
    url: jdbc:mysql://192.168.1.10:3306/agent_learn
    username: prod_user
    password: Prod@2026
logging:
  level:
    com.demo.mapper: warn
```

**启动时也可以不写死**（打包部署时用，优先级最高）：

```
java -jar demo.jar --spring.profiles.active=prod
```

> **记忆**：profile = 一份公共配置 + 每环境一份差异配置 + active 开关。同一份代码永不改动，只动开关和差异文件。

## 3. 自定义 starter 原理：把 08.1 的自动配置反过来用

### 白话理解（了解，不用手写）

08.1 说过：Boot 启动时去每个 jar 的 `AutoConfiguration.imports` 文件里翻"候选配置员"名册。

**自定义 starter 就是你自己造一个这样的 jar**：把你团队常用的功能（比如统一鉴权、统一日志）写成自动配置类，登记到你自己 jar 的 imports 文件里。别人引入你的 starter 依赖 → Boot 启动时自动翻到你的名册 → 条件通过 → 功能自动生效。

```
别人用你的 starter：
  加一行依赖 your-common-spring-boot-starter
  → Boot 自动配置 3 条件检查
  → 生效，无需任何配置
```

生产上公司内部经常这么干：把"公司统一框架"打成 starter，新项目一行依赖就继承全部规范。**本质还是 08.1 那一套**：自动配置类 + imports 登记 + 条件注解。

## 4. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 配置多了用 @ConfigurationProperties | prefix 绑定一组配置到对象，必须有 setter |
| ✅ profile = 环境开关 | application-{环境}.yml + `spring.profiles.active` |
| ✅ 公共配置自动合并 | 环境文件只写差异项 |
| ✅ 自定义 starter 原理 | 自动配置类 + imports 名册登记，本质是 08.1 的机制 |
