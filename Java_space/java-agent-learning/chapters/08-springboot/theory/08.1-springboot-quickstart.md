# 08.1 SpringBoot 快速入门：Boot 帮你写好了 SSM 的配置

> **学习目标**
> - 理解 SpringBoot 和 SSM 的关系（Boot = 自动化了的 SSM）
> - 会用 IDEA 的 Spring Initializr 创建项目，认识 starter
> - 看懂 @SpringBootApplication 和自动配置的大致原理（不深挖源码）
> - 会写第一个 REST 接口并直接运行

---

## 1. Boot 到底是什么？—— 先想清楚"它解决了什么"

### 白话理解

第七章你亲手搭过一个 SSM 项目：要写 web.xml、spring-context.xml、spring-mvc.xml、一堆依赖版本对齐、外置 Tomcat 部署……**这些重复劳动没有任何技术含量，却最容易出错**（版本不匹配、配置漏一项、报错看不懂）。

SpringBoot 就是把这堆事**自动化**了。用一句话记住它的本质：

> **Boot = 帮你在启动时自动写好 SSM 那三份 xml 的框架**

| SSM 里你手写的 | SpringBoot 里变成了 |
|----------------|--------------------|
| web.xml + 外置 Tomcat | 内嵌 Tomcat，一个 main 方法直接跑 |
| DispatcherServlet 配置 | 自动配置类帮你注册 |
| spring-mvc.xml（扫描、JSON、拦截器） | 引一个 starter 依赖就生效 |
| spring-context.xml（数据源、MyBatis、事务） | application.yml 几行配置 |
| 手写一堆依赖并对齐版本 | starter 一个依赖打包解决 |
| 打 war 包部署到 Tomcat | 直接运行，或打 jar 包 `java -jar` 运行 |

> 学到这里你应该有种"原来如此"的感觉：**Boot 没有发明新东西**，Controller/Service/Mapper 分层、@Transactional、拦截器……全是前面学的。Boot 只是帮你把"配置的活"干了。

## 2. 创建项目：Spring Initializr

### 白话理解

"Initializr" = 初始化器。就像装修公司给的**标准毛坯房**：户型（项目结构）帮你定好、水电管线（依赖）按你勾的选型预埋，你拎包进场直接做自己那部分（业务代码）。

**创建步骤（IDEA）**：

```
File → New → Project → Spring Initializr
  ├── 语言: Java | 构建: Maven
  ├── JDK: 选 26（你的版本）
  ├── Spring Boot: 3.5.x
  └── 依赖(可多选): Spring Web / MySQL Driver / MyBatis Framework / Validation
```

生成出来的关键文件：

```
demo/
├── pom.xml                    ← 依赖和版本都帮你配好
└── src/main/
    ├── java/com/demo/
    │   └── DemoApplication.java   ← 启动类（唯一入口）
    └── resources/
        └── application.properties ← 配置文件（常改成 yml）
```

### 认识 starter：一个依赖 = 一组功能

SSM 章为了一个 web 功能你要手动加 spring-webmvc、jackson、servlet-api 等五六个依赖还要对齐版本。Boot 里：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

这一个 `starter-web` 内部打包了：SpringMVC + 内嵌 Tomcat + Jackson（JSON）+ 默认日志等，**版本也由 Boot 统一管理，你不用写 version**。

> **白话记忆**：starter = "全家桶套餐"。"我要做 web 后端" → 点 starter-web；"我要连 MySQL 写 SQL" → 点 starter（MyBatis 的）；"我要校验参数" → 点 starter-validation。各取所需。

## 3. 第一个接口：不用 web.xml、不用 springmvc.xml

启动类直接右键 **Run**，控制台出现 `Tomcat started on port 8080` 就成功了——内嵌 Tomcat 跟着你的 main 一起启动。

```java
package com.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication                      // 启动类核心注解
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
```

再写一个接口（SpringMVC 的知识原封不动搬来用）：

```java
package com.demo.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello(String name) {
        return "你好, " + name;
    }
}
```

浏览器访问 `http://localhost:8080/hello?name=张三` → 返回 `你好, 张三`。

> 对比第七章：没有 web.xml、没有 spring-mvc.xml、没有外置 Tomcat、没有打 war 部署——**这就是 Boot 的核心体验**。

## 4. @SpringBootApplication：三个注解合体

### 白话理解

启动类上的这个注解拆开看是三个注解（IDEA 里按住 Ctrl 点进去就能看到）：

| 组成部分 | 作用 | 对应 SSM 的什么 |
|---------|------|----------------|
| `@SpringBootConfiguration` | 标记这是配置类（含 @Configuration） | spring-context.xml |
| `@EnableAutoConfiguration` | 开启自动配置开关 | （下面细讲） |
| `@ComponentScan` | 扫描**本类所在包及所有子包** | component-scan 标签 |

**⚠️ 最容易踩的坑**：@ComponentScan 只扫启动类所在包及子包。所以：

```
❌ com.demo.DemoApplication（启动类）
   com.other.controller.HelloController   ← 扫不到，404！
✅ com.demo.DemoApplication
   com.demo.controller.HelloController    ← 放启动类的子包里
```

> **规则一句话**：Controller / Service / Mapper 的包，必须放在启动类所在包的**里面**。

## 5. 自动配置原理：看懂就行，不用深挖源码

### 白话理解（重点！面试也常问"自动配置原理"）

想象 Boot 启动时，有个"总包工头"（@EnableAutoConfiguration）干了三件事：

**① 翻名册**：它去所有依赖 jar 里找一份登记文件
`META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`，
里面登记着几百个"候选配置员"（自动配置类，如 DataSource 自动配置、SpringMVC 自动配置）。

**② 挨个面试候选配置员**：每个配置员上岗前都要回答"条件问题"（条件注解 @ConditionalXxx）：
- `@ConditionalOnClass`：**你引了相关依赖吗？** —— 没引 springmvc 的 jar，就跳过 MVC 配置员
- `@ConditionalOnMissingBean`：**你自己写过了吗？** —— 你自己 @Bean 了一个数据源，就跳过我的默认数据源
- （有时）`@ConditionalOnProperty`：配置文件里有关键项吗？

**③ 通过面试的才上岗**：帮你 new 好对象放进容器，你直接 @Autowired 就能用。

### 这解释了三个你以后天天见的现象

| 现象 | 原因 |
|------|------|
| 我没配数据源，为什么启动报 `Failed to configure a DataSource`？ | 自动配置发现你有 mysql 驱动却**没写 url**，条件不满足就放弃，容器里没有数据源 → 报错提醒你 |
| 我自己 @Bean 的东西为什么生效？ | `@ConditionalOnMissingBean` 检测到你配了，自动配置自动退让——**自己的配置永远优先** |
| 引了某个 starter 功能就出现？ | 对应自动配置员的条件①②③全通过，自动上岗 |

> **记忆锚点**：自动配置 = "名册登记 + 条件上岗，你动手的地方它不抢"。遇到"为什么自动生效/为什么不生效"的怪问题，往这三个条件上想，十有八九能定位。

## 6. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ Boot = 自动化的 SSM | 分层、事务、注解全是前面学的，Boot 只自动化了配置 |
| ✅ starter = 全家桶依赖 | 一个依赖打包一组功能，版本不用自己管 |
| ✅ 内嵌 Tomcat | main 方法直接跑，不用外置容器和 war 部署 |
| ✅ @SpringBootApplication | 配置类 + 自动配置开关 + 包扫描，三者合体 |
| ✅ 分层包放启动类子包里 | 扫不到就 404/报 bean 找不到 |
| ✅ 自动配置三条件 | 有依赖 + 你没自己配 + 配置没冲突 → 才自动上岗 |
