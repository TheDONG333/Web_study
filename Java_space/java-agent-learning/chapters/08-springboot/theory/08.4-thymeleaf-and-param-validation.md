## 1. Thymeleaf：服务端渲染的"新时代 JSP"（了解）

### 白话理解

回忆第三章：JSP 就是在 HTML 里嵌 Java 代码，服务器渲染完再发给浏览器。**Thymeleaf 干的是一模一样的事**——服务端渲染，只是换了个更优雅的写法：

| 对比 | JSP | Thymeleaf |
|------|-----|-----------|
| 页面本质 | 会被 Tomcat 编译成 Servlet | 纯 HTML 模板（普通浏览器直接打开也不报错） |
| Boot 支持 | 默认不支持（配置麻烦） | **Boot 官方默认模板引擎** |
| 语法 | `<%= %>` / `<c:forEach>` | `th:text` / `th:each` |
| 现状 | 老项目还在用 | 前端框架流行前的主流；**现在前后端分离，接口只返回 JSON，用得少了** |

> 结论：作为后端你只需要知道 Thymeleaf 长什么样，遇到老项目/需要 SEO 的场景能改页面即可。**你的实战项目是前后端分离风格（只写接口），这节只要看懂**。

### 怎么用（三步）

**① 加依赖**：`spring-boot-starter-thymeleaf`

**② Controller 返回"视图名 + 数据"**（返回的字符串不再拼 JSON 前缀，而是 templates 下的文件名）：

```java
@Controller                         // 注意：要渲染页面用 @Controller，不是 @RestController
public class PageController {

    @GetMapping("/user/page")
    public String userPage(Model model) {
        List<User> list = userService.findAll();
        model.addAttribute("userList", list);   // 数据放 Model，页面里取
        return "userList";                      // 对应 templates/userList.html
    }
}
```

**③ templates/userList.html 里用 th: 语法取数据**：

```html
<!-- 页面放 src/main/resources/templates/ 下，文件名和 return 的字符串一致 -->
<!DOCTYPE html>
<html lang="zh-CN" xmlns:th="http://www.thymeleaf.org">
<body>
    <!-- th:each：循环（类似 for） -->
    <p th:each="u : ${userList}">
        <!-- th:text：把内容填进标签 -->
        用户名：<span th:text="${u.username}"></span>
        <!-- th:if：条件判断 -->
        <span th:if="${u.email != null}" th:text="${u.email}"></span>
    </p>
</body>
</html>
```

> 与第六章 InternalResourceViewResolver 对比：那里配"前缀 /WEB-INF/jsp/ + 后缀 .jsp"，Boot 里**约定 templates/ 目录 + 不写后缀**，不用配任何东西。

## 2. @Valid 参数校验：把 if 校验换成"声明式体检"

### 白话理解

以前校验参数是在 Controller/Service 里手写 if：

```java
// ❌ 手写校验：每加一个字段就加一段 if，代码又臭又长，还容易漏
if (user.getUsername() == null || user.getUsername().isEmpty()) return "用户名不能为空";
if (user.getEmail() != null && !user.getEmail().matches("^\\w+@\\w+\\.\\w+$")) return "邮箱格式不对";
```

@Valid 的思路是**声明式**：像**入学体检表**一样，在实体类每个字段上直接标注"体检标准"，请求进 Controller 前框架自动体检，不合格直接打回，你一个 if 都不用写。

```java
package com.demo.entity;

import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

public class User {
    private Integer id;

    @NotBlank(message = "用户名不能为空")            // 非空白
    @Size(min = 3, max = 20, message = "用户名长度 3-20")
    private String username;

    @NotBlank(message = "密码不能为空")
    @Size(min = 6, message = "密码至少 6 位")
    private String password;

    @Email(message = "邮箱格式不对")                  // 为 null 时不校验，可空字段就这么写
    private String email;

    @Pattern(regexp = "^1\\d{10}$", message = "手机号格式不对")
    private String phone;
    // 其余 getter/setter ...
}
```

**常用校验注解表**：

| 注解 | 作用 | 加在哪 |
|------|------|--------|
| @NotBlank | 字符串不能是 null 且不能全空格 | String 字段 |
| @NotNull | 不能为 null | 任意 |
| @Size(min,max) | 长度范围 | String/集合 |
| @Email | 邮箱格式 | String（可空字段留空也通过） |
| @Pattern(regexp) | 正则校验 | String |
| @Min / @Max | 数值范围 | 数字 |

### 在 Controller 触发校验

```java
@PostMapping("/user")               // 接收 JSON，校验注解才会查这个对象
public Result addUser(@Valid @RequestBody User user) {   // ⚠️ @Valid 必须加，否则不生效
    return Result.ok(userService.add(user));
}
```

校验不通过时框架抛 `MethodArgumentNotValidException`——**正好交给 08.3 的全局异常处理器统一接住**：

```java
@ExceptionHandler(MethodArgumentNotValidException.class)
public Result handleValid(MethodArgumentNotValidException e) {
    // 取出第一条错误消息返回给前端（message 字段里写的就是它）
    String msg = e.getBindingResult().getFieldErrors().stream()
                  .findFirst().map(FieldError::getDefaultMessage)
                  .orElse("参数错误");
    return Result.fail(400, msg);
}
```

> **体验一下效果**：不传 username 直接 POST → 前端收到 `{"code":400,"message":"用户名不能为空"}`，后端一行 if 都没写。这就是声明式校验的意义。

## 3. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ Thymeleaf = 服务端渲染 | JSP 的现代替代，Boot 默认模板；前后端分离时代了解即可 |
| ✅ 渲染页面用 @Controller | 返回 templates 下文件名；只写接口用 @RestController |
| ✅ @Valid = 声明式校验 | 注解贴字段 = 体检表，进 Controller 前自动查 |
| ✅ 必须加 @Valid | 只有方法参数上写 @Valid 才触发校验 |
| ✅ 校验失败 = 一个异常 | MethodArgumentNotValidException → 全局异常统一转 JSON |
| ✅ 可空字段不加必填注解 | @Email 等对 null 直接放行 |
