# 08.3 前后端分离四件套：统一返回 / 全局异常 / 拦截器 / CORS

> **学习目标**
> - 会用统一 Result 封装所有接口返回
> - 会用全局异常处理器兜住所有异常
> - 会注册拦截器（对比 SSM 章：xml 注册变成了配置类）
> - 理解 CORS 跨域是什么、为什么前后端分离必配

---

## 1. 统一返回 Result：让前端只认识一种格式

### 白话理解

后端接口五花八门：有的返回字符串、有的返回对象、报错时有的返回 null、有的直接抛 500 页面……前端调用方就惨了——每个接口都要单独判断返回类型。

**统一返回** = 所有接口都套同一个壳：

```json
{"code": 200, "message": "操作成功", "data": {...}}
```

前端只看三样东西：**code**（成没成功）、**message**（提示语）、**data**（数据）。判断逻辑写一次，全站通用。

```java
package com.demo.common;

public class Result {
    private int code;        // 200 成功 | 401 未登录 | 400 参数错 | 500 服务器异常
    private String message;
    private Object data;

    public static Result ok()                    { return ok(null); }
    public static Result ok(Object data)         { return new Result(200, "操作成功", data); }
    public static Result fail(int code, String msg) { return new Result(code, msg, null); }

    public Result() {}
    public Result(int code, String message, Object data) {
        this.code = code; this.message = message; this.data = data;
    }
    // getter / setter ...
}
```

Controller 里用起来：

```java
@GetMapping("/user/{id}")
public Result getUser(@PathVariable Integer id) {
    if (id == null || id < 0) {
        return Result.fail(400, "id 不合法");     // 业务预期内的错误 → 手动返回
    }
    return Result.ok(userService.findById(id));   // 成功 → 包一层
}
```

> **边界划分**（面试也爱问）：**能预料的错误**（参数不对、用户不存在）在方法里手动 `Result.fail`；**预料不到的错误**（空指针、数据库挂了）交给下面的全局异常兜底。

## 2. 全局异常处理：和 SpringMVC 章一样，但要记住一件事

### 白话理解

Controller 里不写 try-catch 了，万一炸了谁来接？答案是"总收银台"——所有异常自动滚到 @RestControllerAdvice：

```java
package com.demo.exception;

import com.demo.common.Result;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice                       // 全局异常处理器（注意是 Rest 版）
public class GlobalExceptionHandler {

    @ExceptionHandler(RuntimeException.class)
    public Result handleRuntime(RuntimeException e) {
        return Result.fail(500, e.getMessage());
    }

    @ExceptionHandler(Exception.class)
    public Result handleOther(Exception e) {
        return Result.fail(500, "服务器开小差了，请稍后再试");
    }
}
```

> 对比第六章的区别就一处：SpringMVC 里要在 springmvc.xml 配置组件扫描，Boot 里放在启动类子包下**自动被扫到**，什么都不用配。8.4 节还会给它加一个"接住 @Valid 校验失败"的方法。

## 3. 拦截器：代码没变，注册方式变了

### 白话理解

拦截器本身（HandlerInterceptor 的 preHandle 等方法）和第六章一模一样。**变的只是注册方式**：SSM 写在 springmvc.xml 的 `<mvc:interceptors>` 标签里，Boot 没有 xml，改成——写一个配置类实现 WebMvcConfigurer，在代码里注册。

```java
package com.demo.interceptor;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.stereotype.Component;
import org.springframework.web.servlet.HandlerInterceptor;

@Component                                  // ① 让 Spring 管理它
public class LoginInterceptor implements HandlerInterceptor {

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) throws Exception {
        String token = request.getHeader("token");      // 前后端分离版：登录态放请求头
        if (token != null && !token.isEmpty()) {
            return true;                                // 放行
        }
        response.setStatus(401);
        response.setContentType("application/json;charset=UTF-8");
        response.getWriter().write("{\"code\":401,\"message\":\"请先登录\"}");
        return false;                                   // 拦截
    }
}
```

```java
package com.demo.config;

import com.demo.interceptor.LoginInterceptor;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration                                  // ② 配置类
public class WebConfig implements WebMvcConfigurer {

    @Autowired
    private LoginInterceptor loginInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginInterceptor)      // ③ 注册
                .addPathPatterns("/api/**")            //   拦哪些：/api/ 下所有
                .excludePathPatterns("/api/user/login"); // 放行哪些：登录接口
    }
}
```

> **翻译记忆**：SSM 的 `<mvc:interceptors><mvc:interceptor><mvc:mapping path>` 三行标签 = Boot 的 addInterceptors + addPathPatterns + excludePathPatterns。语义一一对应。

## 4. CORS 跨域：前后端分离开发必踩的坑

### 白话理解

**同源** = 协议 + 域名 + 端口三者完全一致（如 `http://localhost:8080` 的两个页面是同源的）。

前后端分离开发时：前端跑在 `http://localhost:5173`（Vue 等），后端跑在 `http://localhost:8080`——**端口不同 = 跨域**。浏览器出于安全策略，默认拦截"网页里的 JS 去请求别的源"（这就是同源策略，防止恶意网站偷你 Cookie 去调别的网站接口）。

**解决方向不是关掉浏览器安全，而是后端声明"我允许你访问"**：

```java
// 方式一：单接口放行（注解）
@CrossOrigin                          // 允许所有来源访问这个接口
@GetMapping("/hello")
public String hello() { return "ok"; }
```

```java
// 方式二：全局放行（推荐，一个项目配一次）——就在上面那个 WebConfig 里加一个方法
@Override
public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/**")                    // 所有接口
            .allowedOriginPatterns("*")           // 允许所有来源（开发期）
            .allowedMethods("GET", "POST", "PUT", "DELETE")
            .allowedHeaders("*");
}
```

> **面试一句话**：CORS 是**服务器**通过响应头（Access-Control-Allow-Origin 等）告诉浏览器"这个来源我允许"的机制；浏览器先拦截，服务器允许后放行。前后端分离项目必配，否则前端永远报跨域错。

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 统一返回 | 所有接口返回 {code, message, data}，前端判断逻辑只写一次 |
| ✅ 错误分两类 | 预料到的手动 fail；预料不到的全局异常兜底 |
| ✅ 全局异常 | @RestControllerAdvice + @ExceptionHandler，扫到即生效 |
| ✅ 拦截器注册 | xml → WebMvcConfigurer 配置类，语义一一对应 |
| ✅ CORS | 跨域被拦找后端配置，addCorsMappings 一次配完 |
