# 06.4 全局异常处理与拦截器（Interceptor）

> **学习目标**
> - 掌握 @ControllerAdvice + @ExceptionHandler 全局异常处理
> - 掌握拦截器的三个方法与注册方式
> - 能说清拦截器（Interceptor）和过滤器（Filter）的区别（面试高频）

---

## 1. 全局异常处理器

### 白话理解

没有异常处理时，Controller 里每个方法都要 try-catch，重复且容易漏。**全局异常处理器** = 一个专门接异常的地方：任何 Controller 方法抛异常，都自动跑到这里处理。

```java
@ControllerAdvice                     // 标注：全局异常处理类
public class GlobalExceptionHandler {

    // 处理业务异常（自己抛的 RuntimeException）
    @ExceptionHandler(RuntimeException.class)
    public Result handleRuntime(RuntimeException e) {
        return Result.fail(e.getMessage());   // 前端拿到友好提示
    }

    // 处理参数校验异常
    @ExceptionHandler(Exception.class)        // 兜底：其他所有异常
    public Result handleOther(Exception e) {
        e.printStackTrace();                  // 打印日志方便排查
        return Result.fail("服务器开小差了，请稍后再试");
    }
}
```

### 白话理解流程

```
Controller 方法抛异常
        │
        ▼
SpringMVC 自动找 @ControllerAdvice 里匹配的 @ExceptionHandler
        │
        ▼
调用对应处理方法 → 返回 Result JSON（或跳转错误页面）
```

### 技术要点

- `@ControllerAdvice` = 全局增强（对所有 Controller 生效）
- `@ExceptionHandler(异常类型.class)` = 处理哪种异常
- 按异常类型**从小到大**匹配：先匹配精确的，最后用 `Exception.class` 兜底
- 效果：前端永远拿到规范的 JSON，而不是一堆英文报错堆栈

## 2. 拦截器 Interceptor

### 白话理解

拦截器是"Controller 方法执行前/后"的关卡——登录校验、权限校验、日志记录都在这里做。

```
请求 → [拦截器 preHandle] → [Controller 方法] → [拦截器 postHandle] → [视图渲染后 afterCompletion]
```

### 三个方法

```java
public class LoginInterceptor implements HandlerInterceptor {

    // ① 方法执行前调用（返回 false 就拦截，不再执行）
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) throws Exception {
        System.out.println("拦截器：方法执行前");

        // 登录校验示例：Session 里没有用户就拦截
        if (request.getSession().getAttribute("user") == null) {
            response.sendRedirect("/demo/login.html");
            return false;              // 拦截！不执行 Controller
        }
        return true;                   // 放行
    }

    // ② 方法执行后、视图渲染前调用
    @Override
    public void postHandle(HttpServletRequest request, HttpServletResponse response,
                           Object handler, ModelAndView modelAndView) throws Exception {
        System.out.println("拦截器：方法执行后");
    }

    // ③ 请求完全结束（渲染完）后调用，常用于释放资源
    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) throws Exception {
        System.out.println("拦截器：请求结束");
    }
}
```

### 注册拦截器（springmvc.xml）

```xml
<mvc:interceptors>
    <!-- 拦截所有请求 -->
    <mvc:interceptor>
        <!-- 拦截哪些路径 -->
        <mvc:mapping path="/**"/>
        <!-- 不拦截哪些路径（放行登录页等） -->
        <mvc:exclude-mapping path="/login"/>
        <mvc:exclude-mapping path="/css/**"/>
        <bean class="com.demo.interceptor.LoginInterceptor"/>
    </mvc:interceptor>
</mvc:interceptors>
```

> 白话理解：`mapping` 说要拦截谁，`exclude-mapping` 说谁放行。登录页和静态资源不拦截，其余先过登录检查。

## 3. 拦截器 vs 过滤器（面试必背对比）

| 对比维度 | 过滤器 Filter | 拦截器 Interceptor |
|---------|-------------|-------------------|
| **所属框架** | Servlet 规范（Java 自带） | SpringMVC 框架 |
| **能操作什么** | 请求、响应（Request/Response 都能改） | 方法调用前后（拿不到请求体） |
| **能拿 Controller 对象吗** | ❌ 不能 | ✅ 能（handler 参数） |
| **执行时机** | Servlet 之前（**最早**） | Controller 之前（**Filter 之后**） |
| **能使用 Spring 的 Bean 吗** | ❌ 不方便（Spring 管不到） | ✅ 可以（@Autowired 注入 Service） |
| **适合做什么** | 编码、跨域、请求日志 | 登录校验、权限校验 |

### 执行顺序（重要）

```
浏览器 → [Filter 过滤器] → [DispatcherServlet] → [Interceptor 拦截器] → [Controller]
```

> **白话**：Filter 在门口（请求刚进 Tomcat 就拦截），Interceptor 在会议室门口（进到 SpringMVC 了再拦）。

### 记忆

> **Filter 管"请求本身"**（编码、CORS、日志——与业务无关）
> **Interceptor 管"业务访问"**（登录、权限——需要判断是谁在访问）

---

## 4. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ @ControllerAdvice + @ExceptionHandler = 全局异常 | 方法里不用再 try-catch |
| ✅ 拦截器三方法：preHandle / postHandle / afterCompletion | preHandle 返回 false 即拦截 |
| ✅ 拦截器注册：mvc:interceptors + mapping/exclude-mapping | 声明拦截谁、放行谁 |
| ✅ Filter 早于 Interceptor | Filter 管请求，Interceptor 管业务访问 |
| ✅ Interceptor 能用 Spring Bean，Filter 不行 | 所以登录校验用 Interceptor |
