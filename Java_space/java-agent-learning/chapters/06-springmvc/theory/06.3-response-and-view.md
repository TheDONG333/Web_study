# 06.3 数据返回：视图跳转与 JSON

> **学习目标**
> - 掌握返回页面的三种方式（字符串/ModelAndView/转发重定向）
> - 理解转发和重定向在 SpringMVC 里的写法
> - 掌握返回 JSON 的标准姿势

---

## 1. 返回页面：ModelAndView 与 Model

### 白话理解

传统开发要返回 JSP 页面。SpringMVC 里"返回页面 + 带数据"有两种方式：

**方式一：返回字符串视图名 + Model 带数据（最常用）**

```java
@Controller
public class PageController {

    @GetMapping("/user/detail")
    public String detail(Model model) {
        // 往 Model 里放数据（页面里用 ${user} 取）
        model.addAttribute("user", new User(1, "张三"));
        return "user/detail";   // 返回视图名 → 找 /WEB-INF/jsp/user/detail.jsp
    }
}
```

**方式二：ModelAndView（数据和视图一起返回）**

```java
@Controller
public class PageController {

    @GetMapping("/user/detail2")
    public ModelAndView detail2() {
        ModelAndView mv = new ModelAndView();
        mv.addObject("user", new User(1, "张三"));  // 数据
        mv.setViewName("user/detail");              // 视图名
        return mv;
    }
}
```

> 两种方式效果一样。方式一更简洁，工作中更常见。

## 2. 转发与重定向

### 白话理解

回忆 03.1：转发 1 次请求、地址栏不变、能带数据；重定向 2 次请求、地址栏变、数据丢失。SpringMVC 里用字符串前缀控制。

```java
@Controller
public class PageController {

    // 转发（默认）：返回字符串就是转发
    @GetMapping("/a")
    public String a() {
        return "user/list";             // 转发到视图 user/list
    }

    // 显式转发：forward: 前缀
    @GetMapping("/b")
    public String b() {
        return "forward:/user/list";    // 转发到 /user/list 这个请求
    }

    // 重定向：redirect: 前缀（地址栏会变！）
    @GetMapping("/c")
    public String c() {
        return "redirect:/user/list";   // 浏览器重新请求 /user/list
    }
}
```

### 对比表（面试高频）

| 对比 | 转发（forward） | 重定向（redirect） |
|------|---------------|------------------|
| 写法 | 默认 或 `forward:` 前缀 | `redirect:` 前缀 |
| 请求次数 | 1 次 | 2 次 |
| 地址栏 | 不变 | 会变 |
| 能否带数据 | Model 可以 | 不行（要用 Session 或 URL 参数） |
| 场景 | 页面间传数据 | 登录后跳转（PRG 防重复提交） |

```java
// 重定向带参数：拼在 URL 上
@GetMapping("/login")
public String login() {
    return "redirect:/index?msg=login_success";
}
```

## 3. 返回 JSON

### 白话理解

前后端分离项目只返回数据，不返回页面。**@RestController 下返回什么对象，就自动转成 JSON**。

```java
@RestController
public class UserController {

    // 返回对象 → JSON
    @GetMapping("/user/info")
    public User info() {
        return new User(1, "张三");      // → {"id":1,"name":"张三"}
    }

    // 返回 List → JSON 数组
    @GetMapping("/user/list")
    public List<User> list() {
        return List.of(new User(1, "张三"), new User(2, "李四"));
        // → [{"id":1,...},{"id":2,...}]
    }

    // 返回 Map → 自定义 JSON 结构
    @GetMapping("/user/result")
    public Map<String, Object> result() {
        Map<String, Object> map = new HashMap<>();
        map.put("code", 200);
        map.put("message", "操作成功");
        map.put("data", new User(1, "张三"));
        return map;   // → {"code":200,"message":"操作成功","data":{...}}
    }
}
```

### 标准返回结构（实际开发约定）

实际项目通常统一返回结构，方便前端统一处理：

```java
public class Result {
    private int code;      // 200 成功，500 失败
    private String message;
    private Object data;

    public static Result ok(Object data) {
        return new Result(200, "成功", data);
    }
    public static Result fail(String message) {
        return new Result(500, message, null);
    }
    // getter/setter 省略
}

// 使用
@RestController
public class UserController {
    @GetMapping("/user/info")
    public Result info() {
        return Result.ok(new User(1, "张三"));
        // → {"code":200,"message":"成功","data":{"id":1,"name":"张三"}}
    }
}
```

> 前端拿到 JSON 后，统一先看 `code`，再取 `data`——这就是你们以后前后端联调的标准协议。

## 4. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ 返回页面：字符串视图名 + Model 带数据 | 或 ModelAndView |
| ✅ 转发默认，重定向用 `redirect:` | 地址栏变化是判断标志 |
| ✅ @RestController 返回对象自动转 JSON | Jackson 自动完成 |
| ✅ 统一返回 Result 结构 | code + message + data |
