# 06.1 SpringMVC 执行流程：DispatcherServlet（面试手写）

> **学习目标**
> - 理解 SpringMVC 在 SSM 中的位置（web 层）
> - 掌握 DispatcherServlet 完整执行流程（面试手写流程）
> - 认识三大核心组件：HandlerMapping / HandlerAdapter / ViewResolver

---

## 1. SpringMVC 是什么？

### 白话理解

回忆第三章：你用 Servlet 接请求、自己判断 URL、自己调 Service、自己拼 HTML。每个功能都要写一堆重复代码。

**SpringMVC 就是把这套"接收请求 → 解析参数 → 调业务 → 返回结果"的流程全部封装好的 web 层框架**：

| 对比 | 第三章手写 Servlet | SpringMVC |
|------|-------------------|-----------|
| 接收请求 | 每个 Servlet 写一遍 | 一个 DispatcherServlet 统一接 |
| 路由分发 | 手动 if/else 判断 URL | 写一个注解就自动路由 |
| 取参数 | req.getParameter() 手动取 | 方法参数自动注入 |
| 返回结果 | 手动拼 HTML/JSON | 返回对象自动转 JSON |

> **一句话**：SpringMVC 是"Servlet 的自动化升级版"——你只需要写 Controller 方法和注解，剩下的请求处理全流程它包了。

### 三层中的位置

```
浏览器 → [SpringMVC（web层：接请求、回响应）] → [Service（业务层）] → [Dao（数据层）]
```

---

## 2. DispatcherServlet：前端控制器

### 白话理解

DispatcherServlet 是 SpringMVC 的**总指挥**——所有请求先到它手里，它再分派给对应的 Controller 方法。

```
所有请求 ──▶ DispatcherServlet（总指挥）
                  │ 分发
                  ▼
             对应的 Controller 方法
```

> 它本质上**就是一个 Servlet**（回忆 03.1：Spring MVC 底层就是 Servlet）。整个框架就是围绕它搭起来的。

## 3. 完整执行流程（面试必背，要能手写）

### 九步流程图

```
① 浏览器发送请求（/user/list）
        │
        ▼
② DispatcherServlet 接收请求
        │
        ▼
③ HandlerMapping（处理器映射器）：找哪个 Controller 方法能处理
   /user/list → UserController.list()
        │
        ▼
④ HandlerAdapter（处理器适配器）：调用这个方法
        │
        ▼
⑤ Controller 方法执行（调 Service → 返回结果）
        │
        ▼
⑥ 返回 ModelAndView（数据 + 视图名）
        │
        ▼
⑦ ViewResolver（视图解析器）：把视图名解析成真正的页面
   "list" → /WEB-INF/jsp/list.jsp
        │
        ▼
⑧ 视图渲染：把 Model 数据填进页面
        │
        ▼
⑨ 响应返回浏览器
```

### 文字版（面试手写用）

> **DispatcherServlet 执行流程：**
> ① 客户端发送请求到 DispatcherServlet；
> ② DispatcherServlet 调用 HandlerMapping，根据 URL 找到对应的 Controller 方法（Handler）；
> ③ 通过 HandlerAdapter 调用 Controller 中的方法（执行前经过拦截器 preHandle）；
> ④ Controller 执行业务逻辑，返回 ModelAndView；
> ⑤ DispatcherServlet 把 ModelAndView 交给 ViewResolver 解析成真正的视图；
> ⑥ 视图渲染（把 Model 数据填充进页面），返回给客户端。

### 关键点

| 步骤 | 组件 | 白话 |
|------|------|------|
| ③ | HandlerMapping | "这个 URL 找谁处理？" |
| ④ | HandlerAdapter | "怎么调用这个方法？（参数怎么传）" |
| ⑦ | ViewResolver | "视图名 'list' 对应哪个页面文件？" |

> 面试常问"为什么要有 HandlerAdapter"：因为 Handler 的类型可以是 Controller、HttpRequestHandler、Servlet 等，Adapter 统一了调用方式。

## 4. 返回 JSON 时的流程简化

> 现代项目（前后端分离）几乎只返回 JSON，不返回 JSP 页面。流程第 ⑥⑦⑧ 步被替换：

```
Controller 方法标 @ResponseBody（或类上 @RestController）
        │
        ▼
返回的对象不是 ModelAndView，而是数据对象
        │
        ▼
HandlerAdapter 用 Jackson 把对象转成 JSON 字符串
        │
        ▼
直接写入响应体返回给浏览器
```

> **白话**：返回 JSON 时不需要视图解析器了，对象自动转 JSON 返回。所以现在面试说流程时，最后可以说"若返回 JSON，则跳过视图解析，直接由 Jackson 转 JSON 返回"——显得你懂现代实践。

---

## 5. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ DispatcherServlet 是总指挥 | 所有请求先到它这，它再分发 |
| ✅ 三大组件：HandlerMapping / HandlerAdapter / ViewResolver | 找方法 / 调方法 / 解析视图 |
| ✅ 面试流程能默写九步 | 重点是 ③④⑦ 三步各干什么 |
| ✅ 前后端分离时代 | 返回 JSON 直接跳过视图解析 |
