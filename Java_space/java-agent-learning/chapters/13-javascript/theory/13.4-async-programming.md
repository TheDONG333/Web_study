# 13.4 异步编程：回调、Promise、async/await（重点）

> **学习目标**
> - 理解 JS 为什么需要异步（单线程 + 事件循环）
> - 知道回调函数是什么、回调地狱怎么来的
> - 掌握 Promise 的三种状态和 then/catch
> - 熟练使用 async/await 处理成功和失败（本章核心）
> - 能和 Java 的 CompletableFuture 对照理解

---

## 1. 白话理解：JS 是"单线程服务员"

JS 主线程**一次只能做一件事**。如果发一个网络请求要等 2 秒，同步写法会让整个页面卡死 2 秒——用户点什么都点不动。

所以 JS 的做法是：**请求交给浏览器在后台办，主线程继续干别的；等结果回来了再通知你**。这就是异步。

```
点外卖：
同步 = 站在店门口等 30 分钟，什么都干不了
异步 = 下单后回家干别的，外卖到了打电话叫你
```

> **和 Java 的差异**：Java 是多线程的，可以开新线程去等；JS 主线程只有一个，靠**事件循环 + 回调**实现"不阻塞"。这也是为什么后端联调时，前端代码里到处是异步。

---

## 2. 回调函数：把"到了叫我"写成函数

### 白话理解

回调 = **你先把"结果回来后要做什么"交给别人，别人做完再调用它**。

```javascript
console.log("1. 下单");

setTimeout(() => {
  console.log("3. 外卖到了");
}, 1000);              // 1 秒后执行这个函数

console.log("2. 继续干别的");

// 输出顺序：1 → 2 → 3
```

`setTimeout` 的第二个参数是毫秒数，第一个参数就是**回调函数**——时间到了浏览器来调用它。

> **关键现象**：代码是"1、2、3"的顺序写的，输出却是"1、2、3"——第 3 行没有阻塞，**主线程把定时器交给浏览器后就继续往下走了**。

---

## 3. 回调地狱：为什么需要 Promise

如果一个请求依赖上一个请求的结果，用回调写会一层套一层：

```javascript
getUser(userId, (user) => {
  getOrders(user.id, (orders) => {
    getOrderDetail(orders[0].id, (detail) => {
      console.log(detail);        // 再往下还要嵌套……
    });
  });
});
```

这就是"**回调地狱**"：缩进越来越深、错误处理分散、代码难以阅读。Promise 就是为了解决它。

---

## 4. Promise：一个"承诺"

### 白话理解

Promise 像一个**取餐凭证**：你现在拿不到餐，但凭证承诺"将来要么给你餐（成功），要么告诉你卖完了（失败）"。你可以先拿着凭证去干别的，到点了再来兑。

```javascript
const promise = new Promise((resolve, reject) => {
  // 这里写异步操作
  const success = true;

  if (success) {
    resolve("成功的数据");     // 兑现承诺 → fulfilled
  } else {
    reject("失败的原因");      // 拒绝承诺 → rejected
  }
});
```

### 三种状态（必记）

| 状态 | 含义 | 触发 |
|------|------|------|
| `pending` | 等待中 | 刚创建，还没结果 |
| `fulfilled` | 已成功 | 调用了 `resolve` |
| `rejected` | 已失败 | 调用了 `reject` |

> **状态不可逆**：从 pending 变成 fulfilled 或 rejected 后，再调 resolve/reject 都不会改变结果。

### 用 then / catch 取结果

```javascript
promise
  .then(data => {
    console.log("成功:", data);     // fulfilled 时执行
  })
  .catch(error => {
    console.log("失败:", error);    // rejected 时执行
  })
  .finally(() => {
    console.log("不管成败都执行");   // 收尾，可选
  });
```

### 把回调改成 Promise 后

```javascript
getUser(userId)
  .then(user => getOrders(user.id))
  .then(orders => getOrderDetail(orders[0].id))
  .then(detail => console.log(detail))
  .catch(err => console.log("出错了:", err));
```

嵌套变成了**链式调用**，错误只需要一个 `catch` 统一处理——这就是 Promise 的价值。

## 5. async / await：把异步写成同步的样子（核心）

### 白话理解

`async/await` 是 Promise 的**语法糖**：让你用写同步代码的方式写异步代码，不用再 `.then` 套来套去。

```javascript
async function loadUser() {
  try {
    const user = await getUser(1);        // 等结果回来，再往下走
    console.log("用户:", user);
  } catch (error) {
    console.log("请求失败:", error);       // 统一处理失败
  }
}

loadUser();
```

### 两条规则（必记）

| 关键字 | 规则 |
|--------|------|
| `async` | 加在函数前面，函数**一定返回 Promise** |
| `await` | 只能写在 async 函数里（或模块顶层），**等 Promise 出结果** |

```javascript
async function f() {
  return 1;              // 等价于 return Promise.resolve(1)
}

f().then(v => console.log(v));   // 1
```

### await 到底"等"什么

```javascript
async function test() {
  console.log("A");

  const data = await mockRequest();   // 暂停当前函数，等结果
  console.log("C", data);

  return data;
}

console.log("开始");
test();
console.log("B");

// 输出：开始 → A → B → C 数据
// 原因：await 暂停的是 test 函数，主线程没被阻塞，先打印 B
```

> **重要理解**：`await` 不是"阻塞整个程序"，它只暂停**当前 async 函数**。这正是 JS 单线程还能处理并发的秘密。

### 成功和失败都怎么处理

```javascript
async function main() {
  try {
    const data = await requestSuccess();   // 成功
    console.log("拿到数据:", data);
  } catch (err) {
    console.log("捕获失败:", err);          // 失败走这里
  } finally {
    console.log("请求结束");
  }
}
```

> **规范**：用 async/await 时，**一定要配 try/catch**，否则失败会变成"未处理的 Promise 拒绝"，控制台报红。

## 6. 和 Java CompletableFuture 对照

| JS | Java CompletableFuture | 说明 |
|----|------------------------|------|
| `new Promise((resolve, reject) => ...)` | `CompletableFuture.supplyAsync(...)` | 创建异步任务 |
| `.then(data => ...)` | `.thenApply(data -> ...)` | 成功后继续处理 |
| `.catch(err => ...)` | `.exceptionally(err -> ...)` | 失败处理 |
| `await promise` | `.join()` / `.get()` | 等结果 |
| `async function` | 返回 `CompletableFuture<T>` 的方法 | 声明异步 |
| `try { await } catch` | `try { join() } catch` | 同步式错误处理 |

> **核心差异**：Java 的 CompletableFuture 默认跑在**线程池**里，是真并行；JS 的 Promise 回调跑在**同一个主线程的事件循环**里，靠"不阻塞"实现并发。逻辑相似，底层机制不同。

---

## 7. 三个最常见的坑

| 坑 | 错误写法 | 正确写法 |
|----|---------|---------|
| 忘了 `await` | `const data = getUser();` → 拿到的是 Promise | `const data = await getUser();` |
| 忘了 `async` | 普通函数里写 `await` → 语法报错 | 函数前加 `async` |
| 不处理失败 | 只有 `await` 没有 try/catch | 用 `try/catch` 包住 |

```javascript
// ❌ 拿到的是 Promise 对象，不是数据
const data = getUser(1);
console.log(data);          // Promise { <pending> }

// ✅
const data2 = await getUser(1);
console.log(data2);         // { id: 1, name: "tom" }
```

## 8. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ JS 单线程 | 异步靠事件循环，不阻塞主线程 |
| ✅ 回调 | 把"结果回来后做什么"提前传进去 |
| ✅ Promise 三状态 | pending / fulfilled / rejected，状态不可逆 |
| ✅ then/catch/finally | 成功 / 失败 / 收尾 |
| ✅ async | 函数返回 Promise |
| ✅ await | 暂停当前 async 函数等结果，不阻塞全局 |
| ✅ try/catch | async/await 的错误处理方式 |
| ✅ Java 对照 | 与 CompletableFuture 的 thenApply/exceptionally 思路一致 |
