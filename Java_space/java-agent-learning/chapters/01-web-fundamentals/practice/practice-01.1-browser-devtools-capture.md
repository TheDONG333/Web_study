## 步骤

### Step 1：打开开发者工具并观察 Network 面板

**操作说明：**

1. 打开 Chrome/Edge 浏览器，按 **F12** 或 `Ctrl + Shift + I` 打开开发者工具
2. 切换到 **Network（网络）** 面板
3. 如果页面已经有请求记录，点击左上角的 🚫 清除按钮（Clear）清空
4. 勾选 **Preserve log**（保留日志）— 这样页面跳转时记录不会丢失
5. 确保 **Disable cache** ⚠️ **没有被勾选**（我们要观察真实的缓存行为）

**界面认识：**

```
┌─────────────────────────────────────────────────────────┐
│ Network 面板                                             │
├─────────────────────────────────────────────────────────┤
│ 🚫 Clear  ☑ Preserve log  ☐ Disable cache              │
├─────────────────────────────────────────────────────────┤
│ Name          Status    Type        Size       Time      │
│ ─────────────────────────────────────────────────────── │
│ index.html     200      document   4.2 KB     120 ms   │
│ style.css      200      stylesheet  12 KB      85 ms    │
│ app.js         200      script      45 KB      200 ms   │
│ logo.png       200      png         8.5 KB     34 ms    │
│ api/data       200      fetch       256 B      450 ms   │
└─────────────────────────────────────────────────────────┘
```

### Step 2：访问一个网页并捕获请求

**操作说明**：

1. 在浏览器地址栏输入一个常用网站（如 `https://www.baidu.com` 或 `https://github.com`）
2. 观察 Network 面板中出现的所有请求
3. 注意观察请求的**瀑布流**（Waterfall），看看哪些资源是并行加载的，哪些是串行的
- **并行加载**：多条资源请求同一时间段同时发出，浏览器利用多个 TCP 连接同时下载图片、css、字体；图里大量 png、css、woff 字体就是并行请求；
- **串行加载**：必须等上一个请求拿到响应、解析完毕，才会发起后续请求，典型就是 HTML 主文档→内嵌 JS；HTML 没下载解析完，浏览器找不到内部引用的 js/css，就没法发起这些资源请求。

**思考问题：**

- 第一个请求是什么？为什么？
- 哪些请求是并行发出的？哪些必须等待前面的完成？
- 总共发了多少个请求？总传输大小是多少？

### Step 3：分析一个完整的 HTTP 请求-响应

**操作说明：**

1. 点击任意一个请求（建议选一个 JS 或 CSS 文件，结构清晰）
2. 在弹出的详情面板中查看 **Headers** 子面板
3. 分别找到以下内容并填写到下面的表格中：

**请求部分（Request）：**

| 字段             | 你的观察到值 | 说明                   |
| -------------- | ------ | -------------------- |
| Request URL    | 填写     | 完整的请求地址              |
| Request Method | 填写     | GET / POST 等         |
| Status Code    | 填写     | 200 / 304 等          |
| Remote Address | 填写     | 服务器的 IP 和端口          |
| `Accept`       | 填写     | 客户端期望的响应格式           |
| `User-Agent`   | 填写     | 你的浏览器和操作系统信息         |
| `Cookie`       | 填写     | 携带的 Cookie（注意保护敏感信息） |

**响应部分（Response）：**

| 字段                       | 你的观察到值 | 说明            |
| ------------------------ | ------ | ------------- |
| `Content-Type`           | 填写     | 返回内容的格式       |
| `Content-Length`         | 填写     | 响应体大小         |
| `Cache-Control`          | 填写     | 缓存策略          |
| `ETag` / `Last-Modified` | 填写     | 缓存验证标识        |
| `Set-Cookie`             | 填写     | 服务器设置的 Cookie |

> 💡 **AI 辅助用法**：将你观察到的这些头字段复制给 AI，让 AI 解释每个字段的作用和为什么服务器返回了这个值。

### Step 4：分析缓存行为

**操作说明：**

1. 刷新页面（F5），观察哪些请求的 Status 变为 `200 (disk cache)`、`200 (memory cache)` 或 `304`
2. 对比第一次加载和第二次加载的差异：

| 指标       | 第一次加载 | 第二次加载 |
| -------- | ----- | ----- |
| 总请求数     |       |       |
| 总传输大小    |       |       |
| 加载完成时间   |       |       |
| 缓存命中的资源数 |       |       |

3. 点击一个 `304` 的请求，查看 Request Headers 中是否携带了：
   - `If-Modified-Since`
   - `If-None-Match`

> 💡 **AI 辅助用法**：将两次加载的截图或数据发给 AI，让 AI 分析哪些资源可以进一步优化缓存策略。

### Step 5：分析一个 POST 请求

**操作说明：**

1. 找一个有表单提交或登录功能的网站
2. 打开 DevTools → Network，确保 Preserve log 已勾选
3. 提交表单或登录
4. 在 Network 中找到对应的 POST 请求
5. 查看其 **Payload** 子面板（Chrome）或 **Params** → **Body**，观察请求体内容
6. 对比 GET 请求的 Parameters（在 URL 上）和 POST 请求的 Payload（在 Body 中）

**填写对比表：**

| 对比维度   | GET 请求（如获取数据） | POST 请求（如提交表单） |
| ------ | ------------- | -------------- |
| 请求 URL |               |                |
| 参数位置   |               |                |
| 状态码    |               |                |
| 请求体类型  | 无             |                |

## 常见问题

**Q：为什么我看到的请求比教程中多很多？**
A：现代网页会加载大量资源（图片、字体、埋点脚本、广告等），这是正常的。可以按 Type 列排序来分类查看。

**Q：Disable cache 勾选和不勾选有什么区别？**
A：勾选后，浏览器每次请求都不会使用缓存，强制从服务器获取最新资源（所有请求返回 200）。适合开发调试。

**Q：有些 Cookie 值很长，需要担心安全吗？**
A：实操中注意不要将登录态 Cookie 或 API Key 等信息截图分享出去。可以在观察后清除浏览数据。
