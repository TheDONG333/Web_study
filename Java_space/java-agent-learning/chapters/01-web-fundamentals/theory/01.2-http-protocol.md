# 01.2 HTTP 协议：请求方法、状态码与核心头字段

> **学习目标**
> - 理解 HTTP 协议的基本模型与报文结构
> - 掌握核心请求方法及其语义
> - 熟悉常见 HTTP 状态码及其含义
> - 理解关键请求/响应头字段的作用
> - 深入理解 GET 与 POST 的本质区别

---

## 1. 概述

**HTTP**（HyperText Transfer Protocol，超文本传输协议）是 Web 的基石。浏览器与服务器之间的一切通信都基于 HTTP 协议。理解 HTTP，就等于理解了 Web 的"语言"。

---

## 2. HTTP 协议基础

### 2.1 什么是 HTTP？

> HTTP 是一种**无状态**的**应用层**协议，采用**请求-响应模型**，基于 **TCP 连接**（或加密的 TLS 连接）进行通信。

**核心特征：**

| 特征 | 说明 |
|------|------|
| **无状态** | 服务器默认不记忆之前的请求（Cookie/Session 是额外机制） |
| **明文** | HTTP 报文以文本形式传输（HTTPS 加密后则不可读） |
| **灵活** | 可传输文本、图片、视频、JSON 等多种数据格式 |
| **简单** | 报文格式简单，人类可读 |

### 2.2 HTTP 报文结构

**请求报文：**
```http
POST /api/users HTTP/1.1                     ← 请求行（方法 + 路径 + 版本）
Host: api.example.com:8080                    ↓
Content-Type: application/json                请求头（Headers）
Authorization: Bearer xxxxxx                  ↓
                                              ← 空行（分隔头部与正文）
{                                             ← 请求体（Body）
    "name": "Alice",
    "age": 25
}
```

**响应报文：**
```http
HTTP/1.1 201 Created                          ← 状态行（版本 + 状态码 + 原因短语）
Content-Type: application/json                ↓
Cache-Control: max-age=3600                   响应头（Headers）
Set-Cookie: sessionId=abc123                  ↓
                                              ← 空行
{                                             ← 响应体（Body）
    "id": 42,
    "name": "Alice"
}
```

## 3. HTTP 请求方法

### 3.1 核心方法

| 方法 | 语义 | 幂等？ | 请求体？ | 响应体？ | 使用场景 |
|------|------|--------|---------|---------|---------|
| **GET** | 获取资源 | ✅ 是 | ❌ 无 | ✅ 有 | 查询数据、浏览页面 |
| **POST** | 提交/创建资源 | ❌ 否 | ✅ 有 | ✅ 有 | 创建订单、提交表单 |
| **PUT** | 完整替换资源 | ✅ 是 | ✅ 有 | ✅ 有 | 更新完整数据 |
| **PATCH** | 部分修改资源 | ❌ 否 | ✅ 有 | ✅ 有 | 更新部分字段 |
| **DELETE** | 删除资源 | ✅ 是 | ❌ 无 | 通常无 | 删除数据 |
| **HEAD** | 获取响应头（无响应体） | ✅ 是 | ❌ 无 | ❌ 无 | 检查资源是否存在 |
| **OPTIONS** | 查询支持的请求方法 | ✅ 是 | ❌ 无 | ✅ 有 | CORS 预检请求 |

### 3.2 GET 与 POST 的本质区别

> 这是面试高频题，但很多人只停留在"GET 参数在 URL 上，POST 参数在 Body 里"的表面理解。

| 维度 | GET | POST |
|------|-----|------|
| **语义** | 获取资源（幂等、安全） | 创建/处理资源（非幂等） |
| **参数位置** | URL 的查询字符串（?key=value） | 请求体（Body） |
| **长度限制** | 浏览器/服务器对 URL 长度有限制（通常 2KB-8KB） | 理论上无限制 |
| **缓存** | ✅ 可被浏览器缓存、加入书签 | ❌ 不可缓存 |
| **历史记录** | 参数会保留在浏览器历史中 | 参数不会保留 |
| **后退/刷新** | 安全（幂等，不会产生副作用） | 浏览器会提示"重新提交表单" |
| **数据类型** | 仅支持 ASCII 字符 | 支持任意数据类型（文件上传等） |

**核心要点：**

> GET 和 POST 在传输层都是 TCP 连接，没有本质的"包体结构差异"。它们的真正区别在于**语义**：
> - GET 意味着**读取**，不应该产生副作用
> - POST 意味着**提交**，可能改变服务器状态

## 4. HTTP 状态码

### 4.1 分类

| 分类 | 范围 | 含义 | 示例 |
|------|------|------|------|
| 🟢 1xx | 100-199 | 信息性响应 | 101 Switching Protocols |
| 🟢 2xx | 200-299 | 成功 | 200 OK, 201 Created |
| 🟡 3xx | 300-399 | 重定向 | 301 Moved Permanently, 304 Not Modified |
| 🟠 4xx | 400-499 | 客户端错误 | 404 Not Found, 403 Forbidden |
| 🔴 5xx | 500-599 | 服务器错误 | 500 Internal Server Error, 502 Bad Gateway |

### 4.2 高频状态码详解

| 状态码 | 原因短语 | 含义 | 场景 |
|--------|---------|------|------|
| **200** | OK | 请求成功 | 常规页面/数据返回 |
| **201** | Created | 资源创建成功 | POST 创建用户成功后 |
| **204** | No Content | 成功但无响应体 | DELETE 成功后 |
| **301** | Moved Permanently | 永久重定向 | 域名迁移（http→https） |
| **302** | Found | 临时重定向 | 登录后跳转 |
| **304** | Not Modified | 缓存未过期 | 浏览器缓存验证 |
| **400** | Bad Request | 请求格式错误 | 参数校验不通过 |
| **401** | Unauthorized | 未认证（需登录） | 未携带 Token |
| **403** | Forbidden | 无权限（已认证但被禁止） | 角色权限不足 |
| **404** | Not Found | 资源不存在 | URL 路径错误 |
| **405** | Method Not Allowed | 请求方法不被允许 | 对 GET 接口发 POST |
| **429** | Too Many Requests | 请求频率超限 | 接口限流 |
| **500** | Internal Server Error | 服务器内部错误 | 后端代码异常 |
| **502** | Bad Gateway | 网关/代理收到无效响应 | Nginx 代理的后端挂了 |
| **503** | Service Unavailable | 服务暂时不可用 | 服务器过载/维护 |
| **504** | Gateway Timeout | 网关超时 | 后端响应超时 |

## 5. 核心 HTTP 头字段

### 5.1 通用头（General Headers）

适用于请求和响应的头字段：

| 头字段 | 示例 | 说明 |
|--------|------|------|
| `Date` | `Date: Tue, 21 Jul 2026 08:00:00 GMT` | 报文发送时间 |
| `Cache-Control` | `Cache-Control: no-cache` | 缓存指令 |
| `Connection` | `Connection: keep-alive` | 连接管理 |

### 5.2 请求头（Request Headers）

| 头字段 | 示例 | 说明 |
|--------|------|------|
| `Host` | `Host: www.example.com` | **必需**，目标服务器域名 |
| `User-Agent` | `User-Agent: Mozilla/5.0 ...` | 客户端信息（浏览器/操作系统） |
| `Accept` | `Accept: application/json` | 客户端可接受的响应格式 |
| `Accept-Encoding` | `Accept-Encoding: gzip, deflate` | 支持的压缩算法 |
| `Accept-Language` | `Accept-Language: zh-CN,zh;q=0.9` | 偏好的语言 |
| `Authorization` | `Authorization: Bearer xxxxx` | 认证凭证 |
| `Cookie` | `Cookie: sessionId=abc123` | 携带的 Cookie |
| `Content-Type` | `Content-Type: application/json` | 请求体的 MIME 类型（POST/PUT 时使用） |
| `Content-Length` | `Content-Length: 42` | 请求体字节数 |
| `Referer` | `Referer: https://google.com` | 请求来源页面 URL |
| `Origin` | `Origin: https://example.com` | 请求来源（CORS 相关） |

### 5.3 响应头（Response Headers）

| 头字段 | 示例 | 说明 |
|--------|------|------|
| `Content-Type` | `Content-Type: text/html; charset=utf-8` | 响应体格式 |
| `Content-Length` | `Content-Length: 1024` | 响应体字节数 |
| `Content-Encoding` | `Content-Encoding: gzip` | 响应体压缩方式 |
| `Set-Cookie` | `Set-Cookie: sessionId=abc123; Path=/` | 设置 Cookie |
| `Location` | `Location: /new-page.html` | 重定向 URL（配合 3xx 状态码） |
| `Cache-Control` | `Cache-Control: max-age=3600` | 缓存策略 |
| `ETag` | `ETag: "33a64df5"` | 资源版本标识，用于缓存验证 |
| `Last-Modified` | `Last-Modified: Mon, 20 Jul 2026 12:00:00 GMT` | 资源最后修改时间 |
| `Access-Control-Allow-Origin` | `Access-Control-Allow-Origin: *` | CORS 跨域控制 |

### 5.4 Content-Type 常见 MIME 类型

| MIME 类型 | 说明 |
|-----------|------|
| `text/html` | HTML 文档 |
| `text/plain` | 纯文本 |
| `application/json` | JSON 数据 |
| `application/xml` | XML 数据 |
| `application/x-www-form-urlencoded` | 表单提交（默认） |
| `multipart/form-data` | 文件上传 |
| `image/png` / `image/jpeg` | 图片 |
| `application/octet-stream` | 二进制文件下载 |

## 6. 代码示例：用 Java 发送 HTTP 请求

```java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class HttpExample {
    public static void main(String[] args) throws Exception {
        // 创建 HttpClient（JDK 11+ 原生支持）
        HttpClient client = HttpClient.newBuilder()
                .followRedirects(HttpClient.Redirect.NORMAL)
                .build();

        // GET 请求
        HttpRequest getRequest = HttpRequest.newBuilder()
                .uri(URI.create("https://api.github.com/users/octocat"))
                .header("Accept", "application/json")
                .GET()
                .build();

        HttpResponse<String> response = client.send(getRequest,
                HttpResponse.BodyHandlers.ofString());

        System.out.println("状态码: " + response.statusCode());
        System.out.println("响应头: " + response.headers());
        System.out.println("响应体: " + response.body());
    }
}
```

## 7. 关键要点总结

| 要点 | 说明 |
|------|------|
| ✅ HTTP 报文 = 起始行 + 头部 + 空行 + 正文 | 结构和格式要熟记 |
| ✅ GET 是读取，POST 是提交 | 语义区别才是本质，参数位置只是表象 |
| ✅ 状态码 2xx 成功 / 3xx 重定向 / 4xx 客户端错 / 5xx 服务端错 | 看到状态码就能快速定位问题范围 |
| ✅ 请求头告诉服务器"我是谁、我要什么" | 响应头告诉客户端"返回了什么、怎么用" |
